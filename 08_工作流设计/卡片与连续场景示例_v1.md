# 卡片与连续场景示例 v1

日期：2026-11-03。配套《小说工作流设计_v1.md》。

**所有卡片均为设计示例，不是已写入v0的数据，也没有把候选内容接受为正式小说事实。** 使用《潮痕入骨》的仓库草案展示关联方式；新增剧情、台词、道具和场景安排均是本次原创提案。即使示例写“种子设定”，也只表示演示分支采用它，不能推断作者已批准正式作品。

## 1. 空白卡的共同部分

可由系统根据材料填写，作者只检查重要决定，不必逐格录入。

```yaml
id: 稳定且唯一的ID
kind: character / scene / plot / rule / world / state_change
version: 1
project: 作品ID
branch: 候选分支ID
authority: proposal / confirmed_setting / accepted_prose_fact
source:
  origin: 作者原话 / 仓库原文 / 正文提取 / 模型原创提案
  locator: 文件与条目或草稿与段落
  source_version: 提交ID或文件哈希
supersedes: null
dependencies: []
unknowns: []
```

卡片版本不可覆盖；状态变更另留历史。示例中“未知”是有效信息；不会为了格式好看补齐事实。

| 字段 | 示例 |

| 创作目标 | 写一条由可见异常推进到人物选择与代价的制度悬疑玄幻场景链 |
| 视角 | 沈砚，受限第三人称 |
| 人物关系目标 | 沈砚想查证，陆昭需要晋升与妹妹药额；互相帮助但利益不完全一致 |
| 读者承诺 | 异常有可追查的痕迹；追查会改变人物处境 |

真实使用时，若作者不指定题材，系统先给不同方案及取舍；不因仓库已有玄幻示例就替作者确定题材。

## 3. 人物卡 CHAR-SY：沈砚

### 稳定设定视图

来源：`fixtures/chaohen_minimal.json`中的人物草案。

| 字段 | 内容 |
|---|---|
| 身份 | 外门弟子，主要视角人物 |
| 想要 | 取得内门晋升资格，换回母亲遗物 |
| 更深的成长方向 | 本次转译提案：学会让他人知情并参与选择，而非独自查证后让同伴承担后果；源草案强调真相不能只靠独自查证 |
| 核心矛盾 | 需要制度提供机会，却发现制度记录可能有问题 |
| 行为倾向 | 追问可核对的细节；发现规则说谎时先取证，容易把盟友拖入被动 |
| 能力与代价 | 辨认被压低的灵息回声；追听会损失与至亲有关的清晰记忆 |
| 声音 | 少下结论，多用问题和细节逼人表态 |
| 不应冻结的内容 | 对制度和他人的信任、冒险意愿、求助方式都可以随事件改变 |
| 待明确 | 普通观察与主动追听的边界；具体失忆内容与触发场景 |

**一致性问题要问得具体：** 他这次冒险是为了证据、遗物还是保护他人？他知道风险吗？是否让同伴拥有选择？“做了与上章不同的事”本身不是错误。

### 剧情状态视图（候选演示分支）

| 时点 | 位置与所知 | 目标／关系 | 权威依据 |
|---|---|---|---|
| S01之前 | 检测场；未得知异常原因 | 晋升动机仍在 | 演示种子，待作者确认 |
| S01之后的计划 | 观察到第七息回亮；只形成“需要核对”的怀疑 | 陆昭遮挡过视线，但表达不愿涉险 | 只是场景计划；正文未接受前不提交 |
| S02之后的候选结果 | 有一份页号及缺页位置的记录；不知道缺页内容 | 选择先保护陆昭姓名，查证与晋升更难两全 | 对应下方本轮示范正文，仍是候选 |

### 当前场景视图

写S02时只取必要字段：想查证、提问式声音、不能提前知道缺页内容、陆昭并非无条件盟友。暂不调用能力来解决档案问题，避免在尚未明确的能力边界上创造事实；若改用能力，先在场景设计中写清触发和代价。

## 4. 人物卡 CHAR-LZ：陆昭

来源同上；人物自身目标须保留，不能只作为主角工具。

| 字段 | 内容 |
|---|---|
| 身份与目标 | 沈砚的室友和竞争者；进入内门以换取妹妹药额 |
| 与沈砚的分歧 | 认为现存规则至少能救眼前的人，不愿拿晋升赌未证实的真相 |
| 允许的复杂行为 | 可以替沈砚遮挡，却拒绝进一步参与调查 |
| 不能从一次行为推出 | 永久忠诚、已知内幕、同意主角替他承担决定 |
| 下一次变化需要的依据 | 新证据、亲身损失、沈砚尊重他的选择，或其他具体事件 |

关系按双方分别记：沈砚可能觉得“他会帮我”，陆昭却觉得“我已经帮过一次，再往前会害妹妹”。这两个认知可以同时成立。

## 5. 剧情卡 PLOT-01：异常、证据与代价

| 字段 | 内容 |
|---|---|
| 状态 | 候选人物弧和章节链 |
| 核心问题 | 当证据会让同伴失去机会时，沈砚愿意让谁承担代价？ |
| 外部链 | 检测异常 → 查档得到有限痕迹 → 保留证据导致晋升风险 |
| 内部链 | 默认独自解决 → 发现自己的证据会牵连陆昭 → 在后续决定中让陆昭知情 |
| 对抗力量 | 负责记录和晋升的制度执行者；其动机与真因暂不确定 |
| 可变部分 | 证据形式、查档方式、风险如何落地、陆昭是否参加下一步 |
| 固定约束 | 不用全知旁白提前解释幕后；不靠无代价神通跳过查证 |
| 首章结束承诺 | 读者知道选择已产生后果，仍不知道完整真相 |

候选机制比较：

| 方案 | 好处 | 代价与条件 |
|---|---|---|
| A. 交换信息 | 可以展示许照微的独立目标与信息差 | 需要明确她为何愿交换、交换什么，否则像送线索 |
| B. 为可核对记录署名 | 把证据与个人风险绑在一起，符合制度悬疑 | 必须先把署名用途与风险写清，不能随便盖章就算高压 |
| C. 潜入盗取原件 | 外部行动更强 | 需要布置防守、能力与追责，当前准备不足 |

本例采用B的局部形式：沈砚在自己提供的观察记录上署名，许照微要求他在补齐证人名字与仅保留缺页位置记录之间选择。它是本次原创提案；不宣称来自类型连接的已验证机制。

## 6. 连续场景卡

| 卡号 | S01 检测场 | S02 档案廊 | S03 退路变窄 |
|---|---|---|---|
| 来源 | 既有首章简报 | 既有功能＋本次局部设计 | 既有功能，具体实现待设计 |
| 功能 | 让异常与人物分歧可见 | 取得有限证据并作选择 | 让保留证据产生现实后果 |
| 进入条件 | 检测正在进行 | 已有可复述异常观察，能进入档案廊 | 已有实际取得、可追溯的证据 |
| 冲突 | 继续追问还是保住评级 | 补上证人名字，还是保留较弱的记录 | 交回证据还是承担晋升风险 |
| 计划结果 | 异常可核对，陆昭提出边界 | 取得页号与缺页位置记录，未揭真相 | 决定保留证据，代价落地 |
| 尚缺条件 | 异常感知与能力代价边界 | 进入权限、记录性质和许照微动机 | 谁发现证据、凭什么影响晋升、如何让陆昭承担风险 |
| 不得偷渡为事实 | 执事必是反派 | 缺页必由宗门高层删去 | 晋升资格已取消、陆昭已同意 |

上述缺口说明：系统必须继续设计前置因果，不能看到三张卡就宣布三场已经可运行。完整试写时，应先落实必要设定；若只试写S02局部，则采用明确列出的演示前提。

### S02详细卡 SCENE-02

- POV：沈砚；空间：档案廊；时序：检测之后，具体时距未定。
- 目标：取得能回读的档案痕迹，不是当场查清真相。
- 演示前提：沈砚已合法进入档案廊；手中有自己写的异常观察纸；许照微允许查看指定旧册；该册页码跳号且有撕痕。全部为本次候选补充，正式写作前须纳入设计确认。
- 对方目标：许照微愿指出缺页位置，但不愿替一份匿名证言背书；这是局部人物提案，不是她的完整正式人物卡。
- 冲突：若要她继续为观察记录背书，她要求证人身份；沈砚不愿擅自写入陆昭姓名。
- 选择：先署自己的名，拒绝替别人署名；取走一份仅记页号和缺页位置的纸。
- 计划变化：取得可回读的物件；调查能力受限；保护同伴意愿初次落实为行动。
- 可揭示：册中少了几页、许照微提出了条件、沈砚作出选择。
- 不可揭示：缺页内容、删页者、许照微是否掌握真相。
- 篇幅：本示例只展示局部对手戏；完整场景需补进入和离开后的衔接。

## 7. 方法卡：从原文到可用动作

### RULE-POWER-01：把权力差写成可见的选择限制

来源：资料库5.6，第11091–11102行。原文讲决定权、资源、话语权和信息权，要求权力转移有可见时刻。

| 字段 | 内容 |
|---|---|
| 状态 | 候选，未验证文学增益 |
| 适用条件 | 双方对资源、信息或决定权的掌控影响当前选择 |
| 本次转译 | 让谁能查看、持有、交出材料体现力量关系；不强迫每场出现彻底反转 |
| S02用法 | 许照微控制旧册和背书，沈砚控制是否提供陆昭姓名 |
| 可见表现 | 她按住册页；他只写自己的名字；她给出的记录明确有限 |
| 检验 | 读者能否理解双方各控制什么，以及这怎样改变选择 |
| 反例 | 只写“她掌握权力”，人物选择不受任何影响 |
| 不适用 | 本场没有相关权力变化，却为满足规则强造反转 |

“不强迫反转”和本场的物件安排是本次改写，不是原文逐字要求。

### RULE-STYLE-01：比较叙述方式

来源：资料库106.1，第100815–100827行。采用叙述句式、用词、距离的一致性定义；将“通过身体信号呈现全篇语言风格统一”的机器指令标为错误转译候选。

- 适用：正文完成后与作者认可样段比较。
- 操作：标出突变的叙述距离、突兀的词汇和解释性旁白，再判断是否有叙事原因。
- 不做：把角色对白强制统一；禁止所有有意风格变化；用“手指发抖”替代文风审查。
- 当前限制：10月29日作者偏好某次版本，可作为临时参照，不等于作者已批准整个长期文风规范。

### RULE-BODY-01：身体限制影响行动

来源：资料库8.1，第20229–20240行。

- 适用：伤势、疲劳或其他身体状态确实影响当前行动或判断。
- 转译：描写它造成的动作差异、选择成本与后续后果；不强制每场增加疼痛和呼吸描写。
- S02决定：不用。当前没有已确认的身体障碍需要表现，不为了调用这张卡给人物制造伤势。

## 8. 本轮原创局部正文示范

用途：展示卡片怎样转成对手戏。它由本次对话创作，未通过v0调用或作者验收，不是正式章节，也不是历史盲测的新结果。

〔P1〕许照微翻到第四十七页，把册子转了过来。下一页是五十二。沈砚伸手去拨中间那道窄缝，她的指腹先按住了纸边。

〔P2〕“看页码。”她说。

〔P3〕断口藏在装订线里，留下半截墨迹。沈砚凑近了些，仍辨不出是什么字。他把自己的纸放在册旁，纸上写着检测时数过的息数，最下方空着两行。

〔P4〕“缺的是哪一天？”

〔P5〕许照微没答，笔尖落在他的空行上。“谁和你一起看见的？”

〔P6〕“我。”

〔P7〕“你刚才说，旁边还有一个人。”

〔P8〕沈砚接过笔，写下自己的名字。写到最后一画时，墨在纸上洇出一个小点。第二行还空着。检测场外，陆昭说过的那句话又挤了进来：别把我写进去。

〔P9〕“他没让我写。”沈砚把笔放回去，“这一张，我自己认。”

〔P10〕许照微把旧册收到手边。她另取一张纸，写下册名、两侧页码，在中间留了一段空白。

〔P11〕“这张只能记下你今天看到了哪里。”她把新纸推给他，又点了点那份观察记录，“它证不了你这张。”

〔P12〕沈砚将两张纸分开折好。先前他以为，找到缺页，检测时看见的东西便有了着落。如今两张纸都在他手里，中间却仍空着。

段号只用于示例证据定位；正式导出正文不保留这些内部标记。

## 9. 从正文提取变化：不能照抄场景计划

假设把以上文本登记为候选草稿 `DRAFT-DEMO-02-v1`，可以提取下表。当前并没有真的登记或接受。

| 候选变化 | 证据 | 可以得出的内容 | 不能得出的内容 |
|---|---|---|---|
| 沈砚看到页码47之后是52，装订处有断口 | P1、P3 | 一个可见缺页迹象 | 缺页者是谁、缺页内容是什么 |
| 沈砚在自己的观察纸上署名 | P8、P9 | 他留下了自己的署名 | 宗门已正式立案、晋升资格已取消 |
| 他没有写陆昭姓名 | P8、P9 | 此次选择尊重了陆昭的边界 | 陆昭信任已经提高；陆昭目前不知道这次选择 |
| 他取得一份册名和页码记录 | P10–P12 | 物品持有变化，记录内容有限 | 已拿到原缺页、获得官方证明或揭开真相 |
| 许照微说记录不能证明观察 | P11 | 她说了这句话，表达了立场 | 她一定无辜／一定撒谎／知道内幕 |

读者知道沈砚作过保护陆昭的选择；陆昭尚不知情。世界事实、人物认知与读者信息应分别存储。

## 10. 伏笔与读者承诺卡 PROMISE-01

| 字段 | 内容 |
|---|---|
| 承诺 | 第七息回亮与缺页之间是否有关联？ |
| 状态 | 候选分支中已提出问题，尚未证明有关联 |
| 提出位置 | S01异常；S02有限档案痕迹 |
| 已付给读者的信息 | 异常可以复述；档案确有可见缺口；人物愿为查证承担部分责任 |
| 未兑现 | 两者因果联系、异常机制、谁造成缺页 |
| 拟兑现窗口 | 当前卷内至少给一次可验证进展，具体章号待卷纲决定 |
| 误用警报 | 不得重复“似乎有更大阴谋”充当连续推进 |
| 可选处理 | 补证据、证明暂时无关、调整窗口、明确取消此线；均保留理由 |

S03承接时必须先回答：谁接触到了证据，为什么会发现，怎样依已有规则影响晋升。缺这些因果时，系统回到场景设计，而不是直接写“第二天他被取消了资格”。

## 11. 一次审稿应怎样说

有效意见示例：

- **证据含义**：P11限制了纸条作用，因此后文不可把它写成官方证明；若需要官方效力，要新增其权限与程序依据。
- **人物变化**：P9支持沈砚此次尊重同伴边界，不足以宣布成长弧已经完成；后续还需在更高压力下检验。
- **前后衔接**：P8引用陆昭原话。完整S01若最终没有这句话，S02必须调整，不能只凭卡片认定说过。
- **待作者判断**：P12直接解释两份证据之间的空缺，清楚但略显点题；可与更克制的动作收尾比较，不把某种风格判为客观错误。

无效意见：“权力规则已消费，人物一致性100分，全部通过。”它没有说明证据，也没有解决尚缺的前置设定。

## 12. 日常使用时作者看到什么

开始新故事：系统呈现2–3个故事提案和取舍，作者选择方向。之后系统填充必要卡片，列出少量重要未知。

继续写作：系统展示本次要推进的内容、预算和核心变化，自动选配、起草与审改。作者主要阅读正文，并查看简短的变化摘要。

接受一章：展示“采用哪些场景版本；人物和物件发生了什么变化；哪些承诺已推进；仍有哪些问题”。作者可一次接受整章，也可只接受前两场。

要求修改：例如“陆昭更有自己的考虑”。系统先定位相关场景和人物动机，给出修改影响；保持明确的既有约束，生成新版本，不覆盖旧稿。

暂停再继续：先恢复已确认的需求、接受版本、相关事实和未兑承诺，再展示下一步。不能以“聊天里记得”代替读取记录。

这些交互是拟实现行为。本次卡片示例用于确认结构与创作方法，尚不能证明自动运行质量。
