# 小说部分实际搭建 Implementation Plan v1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 作者于 2026-11-03 授权按此方案开始施工；里程碑完成后更新本计划及根目录资料说明。

**Goal:** 在现有v0上完成资料选配、故事设计、写审改、带证据的状态提交和跨章接续。

**Architecture:** Python命令行与SQLite继续承担本地执行。复用现有模型适配、不可变草稿与导出，在独立扩展表中记录规划任务、卡片、状态和新流程。旧ACCOS的版本检查、输入清单、人物确认与一致性合同通过适配复用。

**Tech Stack:** Python >=3.11、标准库、SQLite、pytest >=8,<10，Windows PowerShell。

**Spec:** 同目录《03_小说部分架构与复用设计_v1.md》《小说工作流设计_v1.md》《卡片与连续场景示例_v1.md》。以03的接口合同实施，遇冲突先修正文档并记录决定。

## 3. 拟实现后的使用示例

下列为新CLI规格，当前版本尚不提供这些命令。ID来自前一步JSON输出，`PATH`文件均为UTF-8。

```powershell
.\.venv\Scripts\python.exe -m nw --project demo init --name '小说试验'
.\.venv\Scripts\python.exe -m nw --project demo brief --text '作者的目标' --constraints '视角及限制'
.\.venv\Scripts\python.exe -m nw --project demo cards import --file .\fixtures\story_seed\rules.json
.\.venv\Scripts\python.exe -m nw --project demo plan propose --scope book --brief-version 1 --budget .\budget.json
.\.venv\Scripts\python.exe -m nw --project demo plan show --id PLAN_ID
.\.venv\Scripts\python.exe -m nw --project demo cards decide --id PLAN_CARD_ID --version 1 --decision approved --reason '选择该方向'
.\.venv\Scripts\python.exe -m nw --project demo plan apply --id PLAN_ID --decision DECISION_ID
.\.venv\Scripts\python.exe -m nw --project demo story adopt --baseline .\baseline.json
.\.venv\Scripts\python.exe -m nw --project demo novel start --request .\job.json
.\.venv\Scripts\python.exe -m nw --project demo novel resume --job JOB_ID
```

方向确认后如需细化章/场，再执行对应scope的plan propose/apply。novel resume读取持久任务并显示待作者决定项，不要求每次重填notes。

`PLAN_CARD_ID`为plan show返回的候选方案根卡之一。cards decide批准该根卡，plan apply据此只应用对应方案及其子卡。

下面是试用预算的示意内容。字符上限用于本地装包，提供器仍须检查模型实际上下文限制；它不是token计数保证。output_limit映射到提供器支持的输出token参数。

```json
{
  "max_calls": 12,
  "max_revisions": 2,
  "context_char_limit": 24000,
  "output_limit": 3000,
  "price_snapshot": null,
  "max_cost": null
}
```

job.json使用相同budget对象，字段为mode、branch_id、scene_ids、brief_ref、budget。首次写作mode填write，scene_ids取已应用计划生成的真实ID；续写填continue，局部重写填revise并通过场景卡指定修改要求。baseline.json包含已确认的setting_card_refs、initial_facts、expected_accepted映射、as_of_story_order、disclosure_order和coverage，新书初始facts和accepted可为空；旧项目必须列出真实已接受版本并审阅当前状态的时间锚点及历史覆盖范围。JSON里的ID均须由前一步生成，示意名称不能进入正式引用。
