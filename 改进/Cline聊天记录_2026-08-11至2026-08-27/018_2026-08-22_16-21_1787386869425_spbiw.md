## 一、任务目标

对全部原始角色及配角资料进行创作可用性审查，重点确认“孤光”是否具备成为主角的可执行、可持续塑造素材。

本审查只回答一个问题：

> 原始资料是否足以让创作者在具体场景中稳定写出角色的选择、行动、语言、反应、关系变化和长期弧光？

不评估项目配置是否正确，不评估正文写得好不好，也不根据执行产物反推人物设定。

## 三、审查原则

### 3.1 证据优先级

按以下顺序判断：

1. 原始资料中明确写出的具体人物事实；
2. 原始资料中的人物关系、身份、行动和信息边界；
3. 原始资料中能够稳定推导出行为的规则；
4. 角色分类规则；
5. 动态网络或静态网络中对角色功能的约束；
6. 不得使用项目配置或执行产物补足缺失事实。

### 3.2 不允许的推断

以下情况不得当作事实：

- 只因为出现“主角”标签，就认定某个具体人物是主角；
- 只因为出现“重要配角”，就认定存在具体重要配角；
- 只因为“孤光”没有被某一次检索命中，就断言孤光不存在；
- 只因为人物与某个剧情节点相连，就推断人物拥有某种动机；
- 只根据类型规则推断人物性格；
- 只根据网络节点推断人物姓名；
- 只根据项目产物中的人物字段反推原始资料；
- 只根据名称判断两个名字是同一人物。

### 3.3 结论状态

每项审查结果必须归入以下状态之一：

| 状态 | 定义 |
|---|---|
| 已证实 | 原始资料存在直接、可定位的证据 |
| 部分证实 | 有相关事实，但不足以支撑完整创作行为 |
| 资料存在但难以转写 | 有抽象设定，但不能转化为稳定的动作、语言或选择 |
| 资料冲突 | 不同原始资料对同一人物事实给出不一致信息 |
| 未发现 | 在成功完成的目标范围内没有命中 |
| 未确认 | 因路径、编码、命令中断或文件读取失败，不能判断是否存在 |
| 不适用 | 该维度不属于该角色类型，或没有适用场景 |

“未发现”和“未确认”必须严格区分。

## 四、第一阶段：确认实际资料范围

### 4.1 文件存在性检查

对所有候选文件逐个输出：

- 绝对路径；
- 是否存在；
- 文件大小；
- 修改时间；
- 扩展名；
- 是否为目标资料；
- 是否允许纳入审查。

建议命令：

```powershell
$paths = @(
  'D:\小说\原始资料\动态网络.txt',
  'D:\小说\原始资料\类型系统.txt',
  'D:\小说\原始资料\类型连接.txt',
  'D:\小说\原始资料\融合清单.json',
  'D:\小说\原始资料\资料库.txt',
  'D:\小说\原始资料\锚点网络.txt',
  'D:\小说\原始资料\静态网络.txt',
  'D:\小说\资料库索引.jsonl',
  'D:\小说\文档\资料库索引.jsonl'
)

foreach ($p in $paths) {
  if (Test-Path -LiteralPath $p) {
    $f = Get-Item -LiteralPath $p
    [pscustomobject]@{
      Path = $f.FullName
      Exists = $true
      Length = $f.Length
      LastWriteTime = $f.LastWriteTime
      Extension = $f.Extension
    }
  } else {
    [pscustomobject]@{
      Path = $p
      Exists = $false
      Length = $null
      LastWriteTime = $null
      Extension = [IO.Path]::GetExtension($p)
    }
  }
}
```

### 4.2 文件读取验证

每个文件独立读取，不把失败混入无命中结果。

需要记录：

```text

编码：
总行数：
首行摘要：
```

文本文件优先使用 UTF-8；如果出现乱码，再分别尝试：

- UTF-8；
- UTF-8 with BOM；
- GB18030；
- Unicode/UTF-16。

不能因为默认编码读取为空或乱码，就判定文件没有人物资料。

## 六、第三阶段：按角色类型建立审查对象

每个已确认的真实人物先判断角色类型。

### 6.1 主角

必须检查：

- 核心视角；
- 核心欲望；
- 核心执念；
- 长线驱动力；
- 不可替代性；
- 核心悬念绑定；
- 至少三个不可逆转折点；
- 能力与代价；
- 终局前的变化空间。

### 6.2 重要配角

必须检查：

- 与主角的具体关系；
- 独立欲望；
- 独立冲突；
- 独立弧光；
- 关系演变；
- 对主角的影响；
- 对主线的影响；
- 被移除后的剧情损失。

### 6.3 次要配角

必须检查：

- 每次出场目的；
- 传递的信息；
- 制造的冲突；
- 提供的资源；
- 展示的世界信息；
- 单场景内是否完成角色功能；
- 是否存在不必要的独立背景负担。

### 6.4 背景角色

必须检查：

- 是否有明确的氛围或生活功能；
- 是否能体现世界运转；
- 是否被错误要求承担主线人物功能；
- 是否应该降级为无名背景行动者。

### 6.5 缺席者

必须检查：

- 是否明确已故或离场；
- 对当前剧情的持续影响；
- 信件、遗物、回忆或他人叙述；
- 是否触发主角重大决策；
- 每次信息释放是否不同；
- 历史与伏笔是否有回收路径。

### 6.6 反派或对立角色

必须检查：

- 与主角核心目标的具体对立；
- 反派自己的目标；
- 选择动机；
- 价值逻辑；
- 资源与能力；
- 对主角造成的可持续压力；
- 是否存在可理解其选择的证据；
- 是否通过行动体现，而非只有“反派”标签。

## 七、第四阶段：十一维创作可用性审查

对每个真实人物，逐维填写证据。

### 7.1 情绪

检查：

- 基础情绪；
- 复合情绪；
- 情绪触发条件；
- 情绪强度；
- 情绪抑制方式；
- 情绪释放方式；
- 情绪余波；
- 情绪变化是否能改变后续行动。

最低可写标准：

```text
触发条件 + 内部反应 + 外部表现 + 后续影响
```

只有“冷静”“敏感”“压抑”等形容词，不足以判定为可写。

### 7.2 心理

检查：

- 核心恐惧；
- 核心欲望；
- 羞耻、愧疚、执念或创伤；
- 自我认知；
- 自我欺骗；
- 心理防御；
- 压力下的心理变化；
- 心理状态是否会产生选择。

### 7.3 认知

检查：

- 已知信息；
- 未知信息；
- 错误认知；
- 认知盲区；
- 判断方式；
- 观察重点；
- 证据标准；
- 认知升级节点；
- 认知变化是否改变立场。

### 7.4 语言

检查：

- 句式倾向；
- 说话速度；
- 信息透露策略；
- 回避方式；
- 质问、试探、安抚或威胁方式；
- 对不同关系对象是否使用不同语言；
- 语言是否能暴露或掩饰情绪；
- 是否有可识别但不僵化的表达特征。

只有“话少”“毒舌”“温柔”等标签，不足以生成稳定对白。

### 7.5 动作

检查：

- 常态动作；
- 压力动作；
- 犹豫动作；
- 决断动作；
- 回避动作；
- 与能力相符的行动方式；
- 行动成本；
- 行动结果；
- 是否有重复出现的行为标识。

### 7.6 身份

检查：

- 社会身份；
- 组织身份；
- 家庭身份；
- 公开身份；
- 隐藏身份；
- 身份资源；
- 身份限制；
- 身份冲突；
- 身份变化的触发条件。

### 7.7 关系

检查：

- 关系对象；
- 关系起点；
- 权力差；
- 信息差；
- 信任程度；
- 情感债务；
- 依赖与排斥；
- 关系变化触发条件；
- 关系变化后的行为结果。

只有“朋友”“敌人”“亲人”等静态称谓，不足以证明关系可持续发展。

### 7.8 身体状态

检查：

- 固定身体特征；
- 伤病或能力限制；
- 疲劳、疼痛、饥饿、失眠等状态；
- 情绪对应的身体反应；
- 身体状态对行动的限制；
- 身体状态是否有变化和代价。

### 7.9 信息边界

检查：

- 角色知道什么；
- 角色不知道什么；
- 角色误解什么；
- 角色隐瞒什么；
- 谁知道角色的秘密；
- 角色如何获得新信息；
- 信息是否有获取成本；
- 信息变化是否推动关系或剧情。

这是判断角色是否能持续制造悬念和冲突的核心维度。

### 7.10 剧情功能

检查：

- 主线驱动；
- 冲突制造；
- 信息承载；
- 资源提供；
- 价值对照；
- 关系推进；
- 世界展示；
- 主题承载；
- 伏笔或回收功能；
- 角色选择是否改变剧情状态。

### 7.11 角色弧光

检查：

- 初始状态；
- 初始信念；
- 主要压力；
- 关键选择；
- 不可逆后果；
- 中段认知或关系变化；
- 终局前状态；
- 终局选择；
- 变化代价；
- 是否保留连续性。

主角至少需要能够明确列出：

```text
起点状态
转折点一
转折点二
转折点三
终局前状态
变化代价
```

如果只能写“成长”“觉醒”“改变”，则标记为“资料存在但难以转写”。

## 八、第五阶段：问题分类和影响等级

### 8.1 资料缺失

适用情况：

- 原始资料没有该字段；
- 只有角色标签，没有具体事实；
- 有姓名，但没有足以行动的设定；
- 有关系名称，但没有关系状态；
- 有弧光标签，但没有阶段和转折。

### 8.2 资料存在但难以转化

适用情况：

- 只有抽象形容词；
- 只有概念，没有触发条件；
- 只有情绪名称，没有行为表现；
- 只有能力，没有限制和代价；
- 只有身份，没有资源和约束；
- 只有关系称谓，没有变化机制；
- 只有弧光结论，没有过程。

### 8.3 资料冲突

适用情况：

- 同一人物出现互斥身份；
- 同一关系在不同文件中方向相反；
- 时间、年龄、经历或生死状态不一致；
- 同一别名指向多个无法区分的人物；
- 能力限制前后不一致；
- 人物目标与明确行为规则互相矛盾。

### 8.4 检索或路径失败

适用情况：

- 文件不存在但路径未确认；
- 命令被中断；
- 输出被截断；
- 编码读取失败；
- 只扫描了部分文件；
- 某个文件读取成功，但其他文件没有完成扫描。

该类问题不能改写为“资料缺失”。

### 8.5 影响等级

| 等级 | 含义 |
|---|---|
| 致命 | 无法确认角色实体、主角身份、核心驱动力或基本行动逻辑 |
| 高 | 无法稳定推动多场景或多章节行为 |
| 中 | 可以写局部场景，但容易出现重复、失真或关系断裂 |
| 低 | 不影响当前出场，但限制细节丰富度或长期一致性 |

## 九、第六阶段：孤光主角专项判定

“孤光”必须单独完成以下检查。

### 9.1 实体确认

必须回答：

```text
是否在原始资料中出现？
出现在哪个文件？
是否有行号？
是姓名、别名、代号、称谓还是概念？
是否与另一个人物建立身份绑定？
```

### 9.2 主角最低素材

至少需要确认：

- 明确欲望；
- 明确执念；
- 核心恐惧或代价；
- 主动选择机制；
- 压力反应；
- 独特语言策略；
- 独特行为标识；
- 信息边界；
- 核心对立；
- 至少三个可展开的转折点；
- 初始状态和目标状态；
- 能力边界；
- 选择后的持续代价。

### 9.3 可持续性判定

将孤光分为以下等级：

| 等级 | 判定 |
|---|---|
| A | 资料足以支持多场景、多阶段和完整弧光 |
| B | 有核心驱动力，但缺少部分行为、关系或弧光细节 |
| C | 有人物概念，但无法稳定转写为行动 |
| D | 只有名称、身份或类别标签 |
| U | 因检索或路径问题尚未确认 |

在没有完整原始资料扫描前，不能把孤光判为“没有人物”，只能使用“U：未确认”。

## 十、第七阶段：报告格式

最终报告按以下顺序输出。

### 10.1 执行摘要

包含：

```powershell
    $f = Get-Item -LiteralPath $p
    [pscustomobject]@{
      Path = $f.FullName
      Exists = $true
      Length = $f.Length
      LastWriteTime = $f.LastWriteTime
      Extension = $f.Extension
    }
  } else {
    [pscustomobject]@{
      Path = $p
      Exists = $false
      Length = $null
      LastWriteTime = $null
      Extension = [IO.Path]::GetExtension($p)
    }
  }
}
```

### 4.2 文件读取验证

每个文件独立读取，不把失败混入无命中结果。

需要记录：

```text
文件：
读取方式：
读取是否成功：
编码：
总行数：
首行摘要：
末行摘要：
失败原因：
```

文本文件优先使用 UTF-8；如果出现乱码，再分别尝试：

- UTF-8；
- UTF-8 with BOM；
- GB18030；
- Unicode/UTF-16。

不能因为默认编码读取为空或乱码，就判定文件没有人物资料。

## 六、第三阶段：按角色类型建立审查对象

每个已确认的真实人物先判断角色类型。

### 6.1 主角

必须检查：

- 核心视角；
- 核心欲望；
- 核心执念；
- 长线驱动力；
- 不可替代性；
- 核心悬念绑定；
- 至少三个不可逆转折点；
- 能力与代价；
- 终局前的变化空间。

### 6.2 重要配角

必须检查：

- 与主角的具体关系；
- 独立欲望；
- 独立冲突；
- 独立弧光；
- 关系演变；
- 对主角的影响；
- 对主线的影响；
- 被移除后的剧情损失。

### 6.3 次要配角

必须检查：

- 每次出场目的；
- 传递的信息；
- 制造的冲突；
- 提供的资源；
- 展示的世界信息；
- 单场景内是否完成角色功能；
- 是否存在不必要的独立背景负担。

### 6.4 背景角色

必须检查：

- 是否有明确的氛围或生活功能；
- 是否能体现世界运转；
- 是否被错误要求承担主线人物功能；
- 是否应该降级为无名背景行动者。

### 6.5 缺席者

必须检查：

- 是否明确已故或离场；
- 对当前剧情的持续影响；
- 信件、遗物、回忆或他人叙述；
- 是否触发主角重大决策；
- 每次信息释放是否不同；
- 历史与伏笔是否有回收路径。

### 6.6 反派或对立角色

必须检查：

- 与主角核心目标的具体对立；
- 反派自己的目标；
- 选择动机；
- 价值逻辑；
- 资源与能力；
- 对主角造成的可持续压力；
- 是否存在可理解其选择的证据；
- 是否通过行动体现，而非只有“反派”标签。

## 七、第四阶段：十一维创作可用性审查

对每个真实人物，逐维填写证据。

### 7.1 情绪

检查：

- 基础情绪；
- 复合情绪；
- 情绪触发条件；
- 情绪强度；
- 情绪抑制方式；
- 情绪释放方式；
- 情绪余波；
- 情绪变化是否能改变后续行动。

最低可写标准：

```text
触发条件 + 内部反应 + 外部表现 + 后续影响
```

只有“冷静”“敏感”“压抑”等形容词，不足以判定为可写。

### 7.2 心理

检查：

- 核心恐惧；
- 核心欲望；
- 羞耻、愧疚、执念或创伤；
- 自我认知；
- 自我欺骗；
- 心理防御；
- 压力下的心理变化；
- 心理状态是否会产生选择。

### 7.3 认知

检查：

- 已知信息；
- 未知信息；
- 错误认知；
- 认知盲区；
- 判断方式；
- 观察重点；
- 证据标准；
- 认知升级节点；
- 认知变化是否改变立场。

### 7.4 语言

检查：

- 句式倾向；
- 说话速度；
- 信息透露策略；
- 回避方式；
- 质问、试探、安抚或威胁方式；
- 对不同关系对象是否使用不同语言；
- 语言是否能暴露或掩饰情绪；
- 是否有可识别但不僵化的表达特征。

只有“话少”“毒舌”“温柔”等标签，不足以生成稳定对白。

### 7.5 动作

检查：

- 常态动作；
- 压力动作；
- 犹豫动作；
- 决断动作；
- 回避动作；
- 与能力相符的行动方式；
- 行动成本；
- 行动结果；
- 是否有重复出现的行为标识。

### 7.6 身份

检查：

- 社会身份；
- 组织身份；
- 家庭身份；
- 公开身份；
- 隐藏身份；
- 身份资源；
- 身份限制；
- 身份冲突；
- 身份变化的触发条件。

### 7.7 关系

检查：

- 关系对象；
- 关系起点；
- 权力差；
- 信息差；
- 信任程度；
- 情感债务；
- 依赖与排斥；
- 关系变化触发条件；
- 关系变化后的行为结果。

只有“朋友”“敌人”“亲人”等静态称谓，不足以证明关系可持续发展。

### 7.8 身体状态

检查：

- 固定身体特征；
- 伤病或能力限制；
- 疲劳、疼痛、饥饿、失眠等状态；
- 情绪对应的身体反应；
- 身体状态对行动的限制；
- 身体状态是否有变化和代价。

### 7.9 信息边界

检查：

- 角色知道什么；
- 角色不知道什么；
- 角色误解什么；
- 角色隐瞒什么；
- 谁知道角色的秘密；
- 角色如何获得新信息；
- 信息是否有获取成本；
- 信息变化是否推动关系或剧情。

这是判断角色是否能持续制造悬念和冲突的核心维度。

### 7.10 剧情功能

检查：

- 主线驱动；
- 冲突制造；
- 信息承载；
- 资源提供；
- 价值对照；
- 关系推进；
- 世界展示；
- 主题承载；
- 伏笔或回收功能；
- 角色选择是否改变剧情状态。

### 7.11 角色弧光

检查：

- 初始状态；
- 初始信念；
- 主要压力；
- 关键选择；
- 不可逆后果；
- 中段认知或关系变化；
- 终局前状态；
- 终局选择；
- 变化代价；
- 是否保留连续性。

主角至少需要能够明确列出：

```text
起点状态
转折点一
转折点二
转折点三
终局前状态
变化代价
```

如果只能写“成长”“觉醒”“改变”，则标记为“资料存在但难以转写”。

## 八、第五阶段：问题分类和影响等级

### 8.1 资料缺失

适用情况：

- 原始资料没有该字段；
- 只有角色标签，没有具体事实；
- 有姓名，但没有足以行动的设定；
- 有关系名称，但没有关系状态；
- 有弧光标签，但没有阶段和转折。

### 8.2 资料存在但难以转化

适用情况：

- 只有抽象形容词；
- 只有概念，没有触发条件；
- 只有情绪名称，没有行为表现；
- 只有能力，没有限制和代价；
- 只有身份，没有资源和约束；
- 只有关系称谓，没有变化机制；
- 只有弧光结论，没有过程。

### 8.3 资料冲突

适用情况：

- 同一人物出现互斥身份；
- 同一关系在不同文件中方向相反；
- 时间、年龄、经历或生死状态不一致；
- 同一别名指向多个无法区分的人物；
- 能力限制前后不一致；
- 人物目标与明确行为规则互相矛盾。

### 8.4 检索或路径失败

适用情况：

- 文件不存在但路径未确认；
- 命令被中断；
- 输出被截断；
- 编码读取失败；
- 只扫描了部分文件；
- 某个文件读取成功，但其他文件没有完成扫描。

该类问题不能改写为“资料缺失”。

### 8.5 影响等级

| 等级 | 含义 |
|---|---|
| 致命 | 无法确认角色实体、主角身份、核心驱动力或基本行动逻辑 |
| 高 | 无法稳定推动多场景或多章节行为 |
| 中 | 可以写局部场景，但容易出现重复、失真或关系断裂 |
| 低 | 不影响当前出场，但限制细节丰富度或长期一致性 |

## 十一、最终判定规则

### 11.1 可以判定“具备主角素材”

必须同时满足：

- 人物实体已确认；
- 有明确欲望或持续目标；
- 有能够推动行动的执念或核心问题；
- 有主动选择机制；
- 有压力反应；
- 有可观察的语言或动作特征；
- 有信息边界；
- 有核心冲突；
- 有至少三个可展开的状态变化或转折；
- 选择会产生持续代价；
- 不依赖项目配置或正文补全。

### 11.2 只能判定“部分具备”

适用于：

- 有姓名和核心概念；
- 有欲望或身份；
- 但缺少行为规则、信息边界、关系变化或弧光节点。

### 11.3 必须判定“资料不足”

适用于：

- 只有角色类别；
- 只有名字，没有行动依据；
- 只有性格形容词；
- 只有剧情功能；
- 只有网络节点，没有人物事实。

### 11.4 必须判定“未确认”

适用于：

- 文件没有全部扫描完成；
- 索引路径尚未核实；
- 命令中断；
- 编码不确定；
- 结果被截断；
- 只能证明某个文件无命中，不能证明全部原始资料无命中。

## 十二、执行完成标准

本次审查只有在以下条件全部满足后，才能标记为完成：

- 所有原始资料文件均完成存在性检查；
- 所有存在的目标文件均完成读取；
- 编码和读取失败均有记录；
- 人物名称、别名和代号完成索引；
- 模板对象与真实人物完成分离；
- 孤光完成独立检索和上下文核查；
- 每名真实人物完成十一维审查；
- 资料缺失、难转写、冲突和未确认状态完成区分；
- 所有结论都有文件和行号证据；
- 没有引用项目配置、章节正文或执行产物；
- 最终报告明确列出剩余未验证项；
- 在证据不足时使用“未确认”而不是“人物不存在”。

本方案的核心结论标准是：

- 语言与关系变化的关系

## 十二、选择与行动机制

这是把角色资料转化为剧情的关键层。

每次重要行动都应能回答：

- 触发事件是什么
- 角色当时的目标是什么
- 角色当时知道什么
- 角色当时不知道什么
- 角色当时误解什么
- 角色有哪些可选行动
- 哪个选项最符合角色的默认倾向
- 角色为什么不选择其他选项
- 角色受到什么压力
- 角色内部如何反应
- 角色外部做了什么
- 行动改变了什么
- 行动造成了什么可观察结果
- 行动消耗了什么资源
- 行动造成了什么关系变化
- 行动暴露了什么信息
- 行动留下了什么持续代价
- 行动是否改变了角色的信念
- 行动是否改变了角色的目标
- 行动是否推进或破坏主线
- 行动是否使下一场景产生新的限制

也就是说，单纯的：

```text
角色：谨慎
事件：遇到危险
行动：角色做出选择
```

是不合格的。

至少需要形成：

```text
触发条件
-> 当时目标
-> 已知/未知/误解
-> 可选行动
-> 默认选择倾向
-> 具体行动
-> 可观察结果
-> 资源/关系/信息变化
-> 持续代价
-> 下一次选择受到的限制
```

## 十三、剧情功能与不可替代性

角色资料还必须说明角色为什么存在于故事里。

- 角色承担的剧情功能
- 主线功能
- 支线功能
- 悬念功能
- 信息功能
- 冲突功能
- 资源功能
- 情绪功能
- 主题功能
- 价值对照功能
- 关系推动功能
- 事件触发功能
- 反转功能
- 伏笔功能
- 爽点或压抑释放功能
- 角色是否能独立行动
- 角色是否有自己的目标线
- 角色是否有自己的弧光
- 角色被删除后故事损失什么
- 角色是否只是传递信息
- 角色是否只是推动主角
- 角色是否拥有主角之外的生存逻辑

重要配角尤其需要：

- 独立于主角的欲望
- 独立于主角的选择
- 独立于主角的冲突
- 独立于主角的弧光
- 角色被移除后的剧情损失

## 十四、成长弧与变化资料

弧光不只是“从弱变强”，而是人物的信念、选择、关系、能力和代价共同变化。

- 初始状态
- 初始信念
- 初始错误信念
- 初始目标
- 初始关系状态
- 初始能力状态
- 初始信息状态
- 弧光触发事件
- 弧光起点
- 至少三个不可逆转折
- 每个转折前的信念
- 每个转折时面对的选择
- 每个转折的具体行动
- 每个转折的不可逆后果
- 每个转折带来的关系变化
- 每个转折带来的信息变化
- 每个转折带来的能力变化
- 每个转折带来的代价
- 弧光中段状态
- 弧光顶点
- 终局前状态
- 终局前仍未解决的问题
- 最终选择
- 最终选择的代价
- 角色最终改变了什么
- 角色最终没有改变什么
- 角色是否保留矛盾
- 角色弧光对主线结局的影响

## 十五、场景创作转换资料

这部分不是角色设定，而是完整角色资料如何转成具体场景。

每个场景至少需要：

- 场景中的角色实体
- 角色当前目标
- 角色当前状态
- 角色当前关系状态
- 角色当前知道的信息
- 角色当前不知道的信息
- 角色当前误解
- 角色当前可用资源
- 角色当前受限资源
- 触发事件
- 外部压力
- 内部压力
- 可选行动
- 角色默认倾向
- 角色具体选择
- 可观察动作
- 可观察语言
- 可观察身体反应
- 可观察情绪
- 对手或关系对象的反应
- 场景结果
- 信息变化
- 状态变化
- 关系变化
- 资源变化
- 代价
- 弧光状态变化
- 对下一场景的限制

## 十六、完整资料与评估结果必须分开

后续独立验证中需要严格区分两类内容。

### 输入资料

输入资料是角色本身拥有的全部创作内容，包括：

- 人物实体
- 身份
- 外显表现
- 性格
- 心理
- 欲望
- 目标
- 恐惧
- 弱点
- 秘密
- 经历
- 信念
- 价值观
- 能力
- 资源
- 限制
- 状态
- 信息边界
- 关系网络
- 语言表现
- 行动机制
- 剧情功能
- 成长弧
- 场景表现条件
- 连续性状态

### 评估结果

评估结果才是判断这些资料能否支持创作，包括：

- 实体是否明确
- 身份是否完整
- 资料是否互相矛盾
- 角色是否有明确欲望和目标
- 角色是否会主动行动
- 角色是否存在可执行选择
- 角色是否有稳定但不僵化的行为机制
- 角色是否拥有足够的信息边界
- 角色是否能制造信息差
- 角色是否能形成有效冲突
- 角色是否能推动剧情，而不是等待外部事件推动
- 角色是否能产生具体场景行动
- 角色是否能制造关系变化
- 角色是否能承受持续代价
- 角色是否具备长期弧光
- 角色是否具备独立行动能力
- 多角色之间是否形成互相牵制
- 是否能生成差异化对白
- 是否能生成差异化动作
- 是否能产生升级、选择、反转和不可逆结果
- 缺失哪些资料会迫使剧情依赖作者强行推动
- 哪些资料互相冲突
- 哪些资料只能作为作者待定项
- 当前资料是否达到场景创作级
- 当前资料是否达到长线剧情级

因此，下一版方案不能再以现有 `通用小说创作门.py` 为字段基础，也不能把旧的“最小场景槽位”扩大后继续使用。正确方向应是：

1. 新建独立的完整角色资料输入协议。
2. 角色资料与剧情资料分开建模。
3. 建立人物实体、资料完整性、资料一致性、行动驱动、关系冲突、弧光连续性和场景可写性等独立评估层。
4. 允许完整角色资料输入，但不把它写入既有事实库。
5. 不读取或继承现有项目政策、质量门、正文规则和制作流程。
6. 用完整正例、字段缺失、字段矛盾、无行动驱动力、关系冲突有效、弧光不足等样例验证。
7. 最后才决定旧的场景激活和质量门接入是否保留。

前面我把“完整角色创作资料”错误压缩成了“最低可写角色卡”，这确实没有满足原始要求。
