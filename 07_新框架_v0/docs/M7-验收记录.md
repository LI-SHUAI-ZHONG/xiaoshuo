# M7 / T3–T5：故事状态、知情和正文接受

日期为 2026-11-04。施工依据是 08 的实际搭建计划 T3–T5 和架构设计第 4–7 节。

- SQLite v7 保存分支、不可变版本快照、正文变更候选、事实事件和决定。迁移沿用旧库备份，保留 v1–v6 现有记录。接入要求核对现有接受稿映射。尚未结束的旧流程须先完成或显式放弃，旧笔记仍可查，标为 `legacy_unverified`。
- `WORLD` 只接收事实，人物视图只读取自己的认知，读者视图按章、场和披露段落回放。作者可查看全部状态。故事时间与披露顺序独立。证据位置用 Unicode 半开区间，读者披露的零起始段落序号不能早于所引证据。未分类卡片只向作者可见，分支固定采用的卡片版本。
- 提取与独立审查通过 M5 的预算、调用快照和原始响应记录执行。候选变更及审查必须与同一稿件、操作列表和冻结输入匹配。硬问题须修正并重新审查。手工变更走独立的作者入口，仍要提供段落证据和明确的接受决定。
- 批量接受在同一个事务写入事实、已选稿件和分支版本。相同提交编号与内容可以重试。批次先核对预期版本、前场依赖、旧值、证据和明确决定。正文导出在提交后进行，导出失败可重开项目恢复。
- 换早场时，已有的后场须重新核对，即使后场正文没有改变。候选分支保留自身修改，提升主线需要对准分支当前版本和创建分支时的主线版本。M7 采用保守规则，按出版位置要求重审受影响的后场，并要求所有改变的场景在候选分支上重新审核。旧分支的继承稿不能自动覆盖主线。
- 新增 `story`、`cards` 和 `accept --batch`。传统项目继续使用既有命令。托管项目可检查和接受现有草稿，其正常写作上下文接线列在 M8。基线建立之前的故事历史按 `HISTORY_INCOMPLETE` 报告。
