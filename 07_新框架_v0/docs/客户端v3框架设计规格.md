# 小说生产客户端 v3：框架设计规格（交付实现用）

> **用途**：这是给实现模型的完整设计规格，用来从零重建 `07_新框架_v0/src/nw/studio/` 前端，并补齐所需的后端接口。
> **核心定位**：做一个**生产小说的客户端**，不做资料浏览器。资料平时藏在后台，创作时只以「推荐」的形式出现。
> **布局参考**：VS Code（活动栏、侧栏进度树、编辑区、检查面板、底部面板、状态栏）；国内热门 App（番茄/起点书架、剪映分步模板选择、小红书瀑布流图鉴、微信角标提醒）。

---

## 0. 设计原则（每个界面都要遵守）

| # | 原则 | 落地要求 |
|---|---|---|
| P1 | **生产导向** | 每个页面都要能回答「我现在要做什么、下一步按哪个键」。不需要用户操作的纯技术信息（哈希、JSON、Prompt 全文）默认隐藏，放进「高级/开发者」抽屉里 |
| P2 | **按键和面板分开** | **按键**：会改变数据或启动任务（实色、带图标、固定位置）。**面板**：只读的展示（无边框卡片、灰色标题）。不能出现「看起来像按钮的面板」或「藏在文字里的按钮」 |
| P3 | **资料不拆开展示** | 六大资料和拆解资料不在创作流程里逐条列出。创作向导只显示「推荐 Top3 + 全部选项」。原文检索只在「知识库 → 高级检索」里提供 |
| P4 | **实时可见** | 制作过程像 VS Code 跑任务一样：左侧进度树实时刷新状态图标，当前步骤有动画，底部有运行日志 |
| P5 | **全程可回放** | 每本书从选类型到交稿的每一步都留档，在成品仓库可以按时间轴回看 |
| P6 | **推荐只基于真实数据** | 推荐 Top3 只能来自已入库的拆解统计。没有数据就**显示空白占位**，不能编造或用默认值补齐 |
| P7 | **简洁** | 一屏最多一个主操作按钮（Primary）。二级操作放进「⋯」菜单 |

## 1. 信息架构（一级导航）

左侧 **活动栏（Activity Bar）**，48px 宽，只放图标，悬停显示名称，右上角可带角标：

| 顺序 | 图标 | 名称 | 作用 | 角标 |
|---|---|---|---|---|
| 1 | 🏠 | **首页** | 写作入口、继续制作、待办提醒 | — |
| 2 | ✍️ | **制作台** | 制作中的小说，IDE 式工作区（核心） | 待确认节点数（红点） |
| 3 | 📚 | **成品仓库** | 已完成 / 制作中 两个书架，可阅读、回放制作过程 | — |
| 4 | 🗺️ | **类型图鉴** | 33 个主类型、425 个子类型的可视化图鉴，以及各类型的推荐统计 | — |
| 5 | 🧠 | **知识库** | 类型知识库 + 类型资料库（拆解资料、用法计数、升级候选） | 升级候选待批准数 |
| 6 | 📥 | **预存库** | 导入优质小说 → 作者审核分类 → 拆解 → 入库 | 待审核数 |
| — | （底部） | ⚙️ **设置** | 模型/API、目录、外观 | 配置异常时显示黄点 |

> 路由用 hash：`#/home`、`#/studio/<novelId>`、`#/library?tab=done`、`#/atlas/<typeId>`、`#/kb/...`、`#/staging/...`、`#/settings`。

- **主类型列表**：左栏单选。**子类型网格**：卡片式（仿小红书），每张卡片包含名称、一句话定义、推荐角标（TOP1/2/3）、「来自 N 本拆解」。
- **副类型**：最多 2 个，选完后用类型组合表（`type_adaptation_type_combinations_*.py`）做兼容提示；不兼容时给警告，但不强制拦截。

### 4.2 后续步骤：分步选择页（仿剪映模板选择 + 顶部步骤条）

选好类型后，Modal 变成**全屏向导页**，顶部是步骤条：

```
① 类型 ✓ ─ ② 风格 ● ─ ③ 文笔 ─ ④ 写法 ─ ⑤ 世界观 ─ ⑥ 人物 ─ ⑦ 结构篇幅 ─ ⑧ 卖点 ─ ⑨ 确认
```

**每一步都用同一套布局（实现时做成一个复用组件 `WizardStep`）**：

```
┌──────────────────────────────────────────────────────┐
│ ② 风格   基于：玄幻 › 东方玄幻 ＋ 悬疑                    │
├──────────────────────────────────────────────────────┤
│ ⭐ 推荐 Top3（来源：类型资料库「风格」板块用法计数）        │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐               │
│ │冷峻写实    │ │诡谲压抑   │ │  （空白）  │               │
│ │用法 ▲41   │ │用法 ▲17   │ │ 等待拆解   │               │
│ │出自 9 本  │ │出自 4 本  │ │ 数据补充   │               │
│ │[示例片段▾]│ │[示例片段▾]│ │           │               │
│ └──────────┘ └──────────┘ └──────────┘               │
│ 全部选项（分组卡片，可多选/单选按维度定义）                 │
│ [基调] 冷峻 热血 轻松 悲怆 …                             │
│ [色彩] 写实 诗意 黑色幽默 …                              │
├──────────────────────────────────────────────────────┤
│ 已选：冷峻写实 ›（进入细分）                               │
│                [← 上一步]  [跳过此步]  [下一步：文笔 →]     │
```

**「每种选择都要有进一步页面」的实现**：选项分两层。点击一级选项（例如「冷峻」）后，右侧滑出或进入**二级细分页**（例如「冷峻写实 / 冷峻诗意 / 冷峻克制」）。二级页同样有 Top3 推荐 + 全部选项 + 示例片段。层级深度由数据决定（一般 2 层，最多 3 层）。

### 4.3 各步骤的内容与系统映射

| 步骤 | 选择维度（一级 → 二级） | 推荐数据板块（slot） | 映射到现有系统 |
|---|---|---|---|
| ① 类型 | 主类型 → 子类型；副类型 | `genre` | `type_selection.selection` / `_governance.project_config.genre_ids` |
| ② 风格 | 基调、色彩、情绪温度 → 细分 | `tone` | `project_config.tone_ids`，`expression_design_type_tones` |
| ③ 文笔 | 语言质感（白描/华丽/口语）、句式节奏、修辞密度 → 细分 | `style` | `project_config.style_ids`，`expression_design_type_styles` |
| ④ 写法 | 视角（受限第三/第一/多视角）、叙述距离、时序（线性/倒叙/多线）→ 细分 | `narration` | `structure_ids`，`板块53 叙述距离`、`板块59 视角规则` |
| ⑤ 世界观 | 力量体系、社会制度、地理尺度 → 细分 | `world` | `world_design` 前置约束 |
| ⑥ 人物 | 主角原型、对手类型、配角组配置 → 细分 | `character` | `character_design` 前置约束 |
| ⑦ 结构篇幅 | 总字数、卷章数、节奏模板（重/中/轻/空章配比） | `structure` | `structure_ids`、`plot_design_structure` |
| ⑧ 卖点 | 读者承诺、爽点类型、钩子类型 | `hook` | `mechanism_ids`，`plot_design_reader_engagement` |
| ⑨ 确认 | 汇总卡片 + 一句话故事构想（必填）+ 硬约束（选填） | — | 生成 **Brief**，并生成 `type_selection` 的 `_governance` |

**⑨ 确认页**：把所有选择汇总成一张「立项卡」（仿 App 订单确认页）。底部主按钮 **[开始制作]**，点击后：创建项目 → 写入 Brief → 自动进入 **制作台** 并启动全书设计（7+1 步）。

> **关键约束**：向导里的选择只是**作者偏好与约束**，作为 Brief 和 governance 输入。14 步设计依然按 `phase_routes.REQUIRES` 运行，不能跳过前置。

## 5. 推荐引擎规则（Top3）

### 5.1 数据定义

- **拆解条目（decomposition item）**：从一本已入库的优质小说中拆出的一条可复用用法。字段包括：`id`、`book_id`、`slot`（板块，见 §4.3）、`option_key`（对应向导中的哪个选项，例如 `tone.冷峻写实`）、`type_tags`（该书经审核后的类型）、`stage`（适用于 14 步中的哪一步，可多选）、`usage_text`（用法描述）、`evidence`（原文片段与定位）、`status`（draft / approved）。
- **用法计数（usage count）**：
  - **主计数 `corpus_count`**：同一 `option_key` 在已入库拆解中出现的次数（每本书同一用法最多计 1 次，避免一本书刷量）。
  - **辅计数 `adopt_count`**：创作中该选项被采用、并且对应场景**通过审稿**的次数。
  - **排序**：`corpus_count` 降序 → `adopt_count` 降序 → 最近入库时间降序。

### 5.2 推荐计算（每个板块独立计算）

```
输入：已选类型组合 T（主类型 + 子类型 + 副类型），板块 slot
1. 精确层：type_tags 覆盖 T 的已批准拆解条目 → 按 option_key 聚合计数
2. 若精确层不足 3 个 → 回退到「主类型 + 子类型」层补位
3. 若仍不足 → 回退到「主类型」层补位
4. 仍不足 3 个 → 剩余位置返回 null（前端显示空白占位卡「等待拆解数据补充」）
每个推荐项都要返回：option_key, 名称, corpus_count, adopt_count, 来源书目列表, 命中层级(精确/子类/主类), 1–2 条示例片段
```

- **前端要标出命中层级**：精确命中不加标签；回退命中加灰色小标签「同主类型参考」。
- **严禁**用固定默认值、模型生成内容或六大资料原文去补齐空位。

### 5.3 推荐如何反哺创作步骤

作者选中某个推荐项后，该选项关联的拆解条目（只取 approved）会作为**作者选定的参考用法**，随 Brief / governance 进入对应 `stage` 的输入。注意：
- 只传「用法描述 + 简短证据」，不传整章原文。
- 在 14 步中的优先级等同 `design_ready` 方法；低于已接受事实、Brief 和冻结产物（遵守现有 `PRIORITY_HIERARCHY`）。

## 6. 类型图鉴

仿小红书瀑布流 + 百科详情页：

- **列表页**：33 个主类型做成大卡片（每个类型有固定色块和图标），点击展开子类型网格。每张卡片显示：已拆解书数、可用资料条数、推荐覆盖率（9 个板块中有几个板块有数据，例如「6/9」）。
- **类型详情页**（Tab 结构）：
  1. **定义**：定义、包含项、排除项、区别特征（目前原始类型系统里这几项多为空，需显示「待补充」并提供编辑按钮，由类型知识库维护）
  2. **各板块推荐榜**：9 个板块各自的 Top 榜（与向导用同一个接口）
  3. **代表作品**：该类型已入库的拆解书目（点击跳到预存库/知识库的拆解详情）
  4. **常见组合**：常见的副类型搭配与兼容性
- 详情页底部主按钮：**[用这个类型写一本]** → 直接进入向导第②步（类型已预填）。

- **状态图标（全局统一）**：○ 未开始 · ◐ 进行中（旋转动画）· ✓ 完成 · ⚠ 需作者确认 · ✗ 失败 · ⏸ 暂停 · ↻ 已退回修订。

- **数据来源**：`novel_jobs` / `show_job`（现有）+ 新增的进度推送接口（见 §11）。

### 7.2 编辑区（多标签）

| 标签类型 | 内容 | 可编辑 |
|---|---|---|
| **正文** | 场景正文编辑器（衬线字体、行宽 36–42 字、段间距 1.8），顶部工具条：[✓接受本场] [↻重写] [⤴退回修订] [✎手动修改] [⇄对比版本] | 是（手动修改会生成新草稿版本，不覆盖旧稿） |
| **设计** | 某一步设计产物的**可读卡片视图**（例如人物卡、事件节点、场景卡），不显示原始 JSON（JSON 放进「⋯ → 查看原始数据」） | 否（修改通过「退回重做本步」完成） |
| **对比** | 两个草稿版本的词级 diff（复用现有 `simpleDiff` / `highlightDiffWords`） | 否 |
| **阅读** | 整章连读模式（Zen Reader） | 否 |

## 9. 预存库（导入 → 审核分类 → 拆解）

### 9.1 看板视图（仿项目管理 App）

```
[＋ 导入小说]  （txt / md，可批量；后续支持 epub）
┌ 待审核 (3) ┬ 待拆解 (2) ┬ 拆解中 (1) ┬ 待复核 (4) ┬ 已入库 (12) ┬ 已驳回 ┐
│ 书卡        │            │  ◐ 37%     │            │            │       │
│ 系统识别：  │            │            │            │            │       │
│ 玄幻 82%    │            │            │            │            │       │
│ [审核]      │            │            │            │            │       │
└────────────┴────────────┴────────────┴────────────┴────────────┴───────┘
```

### 9.2 流程与按钮

1. **导入**：上传文件 → 系统切章、统计字数 → 进入「待审核」。
2. **自动类型识别**（类型知识库负责）：给出主类型/子类型候选和置信度，以及识别依据（命中的类型区别特征）。**只作建议**。
3. **作者审核**（审核抽屉）：确认或修改类型（可多选副类型）、质量评级（S/A/B）、是否拆解、备注。按钮：[通过并进入拆解队列] [驳回]。
4. **拆解**：按 9 个板块（§4.3 slot）+ 14 个步骤拆出条目，每条都必须带原文证据定位。拆解中显示进度。
5. **作者复核**：逐条或批量 [批准] [修改] [丢弃]。批准后的条目才进入类型资料库并参与计数。
6. **入库完成**：自动重算相关类型的推荐统计，并生成「资料升级候选」（见 §10.3）。

> 状态机：`pending_review → queued → decomposing → pending_verify → archived`；任意状态都可以 `→ rejected`。

## 10. 知识库（类型知识库 + 类型资料库）

侧栏是二级导航：**类型知识库 | 类型资料库 | 升级候选 | 高级检索**

### 10.1 类型知识库（负责：分辨类型）

- 每个类型的**识别特征**：定义、包含、排除、区别特征、典型元素、反例。可以编辑，也可以从已入库拆解中提议补充（需作者批准）。
- 给预存库的自动类型识别提供依据；给类型图鉴「定义」Tab 提供内容。

### 10.2 类型资料库（负责：拆解资料的分类与计数）

- 表格视图：板块 × 选项 × 类型，每格显示 `corpus_count`，点格子展开条目列表（用法描述 + 证据 + 来源书目）。
- 每个板块的「用法最多 Top3」高亮显示，和向导推荐保持一致。

### 10.3 升级候选（负责：不断升级创作步骤里的资料）

- 新拆解条目与现有六大资料条目自动比对，归为三类：**增强**（同义更具体）、**补缺**（对应 F2 台账中的缺义/截断条目）、**新增**（现有资料没有的用法）。
- 作者 [批准] 后，写入**升级层**（新文件或新库），由步骤取材时合并读取。
- **硬约束**：不能修改 `02_原版资料/`；不能改动会触发 `adjudication.db` 重算的 21 个核心裁定文件。升级层要独立存储、独立版本化。

### 10.4 高级检索

六大资料 22,941 条和 F2 台账的原文检索只放在这里（复用现有 `/api/materials/search`、`/api/ledger/search`），供需要时查证，不出现在创作主流程。
