
# M8 / T6–T7 自动选配、故事工作包与候选设计

日期为 2026-11-05。施工依据为 08 的实际搭建计划 T6–T7、架构与复用设计及 M7 接受合同。

## 可使用的入口

- `plan propose` 可在只有 Brief 时产生两至三种书级候选，每种包含读者承诺、主角欲望、阻力、选择、代价和后果。选定方向后可细化卷、章、场景。规划冻结已批准设定、已接受状态、原始资料版本、实际提示及模型参数。返回格式有误时保存原始返回，可用 `plan retry` 按原输入和剩余预算显式重试。
- `plan show` 展示候选根卡、成员、关键开放问题及已有落地映射。`plan apply` 校验与所选根卡匹配的作者批准及全部成员哈希，再在一个事务里保存采用记录、章场编号和分支设定。重复提交同一决定复用章场 ID。关键未定规则随子方案传递，缺少必需设定时场景进入待补状态。
- `story context` 先装配作者约束、确认设定与当前 POV 所知，再按中文关键词、标签和关系召回最多 20 张方法候选，实际选 0–5 张。入选记录原意、当前场景问题、可操作表现和验收点，弃用理由留在审计记录。工作包沿用已登记的不可变原文行号及 SHA-256。
- 托管 `write` 与 `review` 使用预算与冻结工作包。人物事实按故事时间读取，读者既知按披露顺序读取。前文通过相关可见事实和证据坐标承接，工作包保留相邻稿件版本，并单独记录倒叙证据引用。审稿登记目标稿版本。相同故事版本的状态候选继承写作依赖，进入 M7 的接受检查。

## 复用与施工决定

| 依据 | 落点 |
| --- | --- |
| ACCOS `StepInputManifest`、`ReadReceipt` | 复用版本、摘要、提示与来源回读合同。v0 保存卡片与来源段定位、SHA-256、实发消息和输入包，原文由本地来源登记回读。 |

| ACCOS `creative/novel.py`、`character.py` 的版本与确认生命周期 | 适配候选先存档、批准固定版本和成员、事务落地。人物卡承载目标与场景任务。 |
| v0 M5–M7 | 沿用任务调用和恢复、卡片决定、分支快照、正文版本与证据化接受。使用已有 SQLite v7 表。 |

本轮采用确定性排序，并校验可选模型筛选的结果必须是召回子集。自动写作提示使用证据定位与当前可见事实承接前文，整段前文需独立核定可用范围。读者提示限于已披露且本场 POV 同样知道的事实。候选分支可把未接受的受影响设计标记为过期。遇到已接受后场时，重规划事务返回 `REPLAN_ACCEPTED_DESCENDANTS` 并列出场景 ID，已接受正文仍走 M7 的分支与重审流程。
