## 二、needs_author_input（117 条）的处理建议

这些条目需要作者提供原始内容或做出裁定后才能结项。后续模型不应擅自编造原始内容。

### 2.1 原文截断类（38 条）
- **典型特征**：原件定义以冒号结尾（如"包括以下维度："），后面的列表丢失
- **处理方式**：
  1. 检查 `02_原版资料/原始资料/` 对应行号是否确实截断
  2. 若确认截断，标记为 `source_unresolved` 并在步骤文件中注明"原件此处截断，当前按已有定义文字指导使用"
  3. 生成作者确认清单供作者补全

### 2.2 跨表范围冲突（32 条）
- **典型特征**：同一概念在不同板块/文件中有不同定义或边界
- **处理方式**：Opus 5.5 可对照两处原文分析冲突点，给出建议裁定方案，但最终选择留给作者

### 2.3 来源缺失/不完整（19 条）
- **典型特征**：引用了不存在的编号、来源路径有误
- **处理方式**：确认是否为历史迁移遗留问题，若是则按最近版本重定向引用

### 2.4 定义指令冲突（7 条）
- **典型特征**：如 106.1 文风定义与身体信号指令抵触
- **处理方式**：Opus 5.5 可从文学角度分析哪种口径对小说质量更有利，建议作者采纳

```json
  "status": "resolved",
  "resolution_refs": ["07_新框架_v0/docs/前置产物与资料调度纠正.md#问题台账第XX批-批次名称"],
  "resolution": {
    "date": "2026-MM-DD",

    "decision": "具体裁定内容（100字以内说明做了什么、为什么这样做）",
    "batch": "批次号",
    "model": "执行模型名称"
  }
}
```

### 3.3 `source_scope_ambiguity` 的典型处理示例

**F2-INSTEP-LIBRARY-004**: "定义限定已故角色，提示规则另设最终不出场的条件。原件未说明回忆场景是否计为出场。"

**处理方式**：在对应步骤文件（如 `character_design.py`）的相关条目 `【本步用法】` 中追加：
```
回忆、幻象或闪回中的角色呈现不计为实际出场。计入出场的标准为：
该角色在当前时间线的场景中有实际行动、对白或可被POV感知的物理存在。
```
然后在台账中标记为 `resolved`，注明"已在步骤指引中明确回忆场景的出场计算口径"。
