# M6 / T2：真实源段、卡片与决定历史

日期：2026-11-04。依据：08 的《小说部分实际搭建计划 v1》T2 和《小说部分架构与复用设计 v1》第 4、5、8 节。

- 在 SQLite v6 新增来源版本、原文片段、卡片版本、决定历史、卡片关系与后续计划应用映射。v5 旧表和数据保留，升级前沿用 M5 的 SQLite 在线备份与完整性检查。正式项目库没有在验收中被打开。
- 来源版本以仓库相对路径及原文件字节 SHA-256 区分；同编号的原文靠文件版本、行号与片段哈希识别。片段仅将 UTF-8 BOM 与换行标准化，保留正文、空行和原行号。清单中的 `observed_file_sha256` 是制作时观察值；跨系统导入验证规范化文件哈希和片段哈希，数据库保存读取时的实际字节哈希。原文件后来移动、删除或修订，已冻结片段仍能读取；新导入按现有文件重新验证。
- 单文件登记遇 NUL、坏编码或空白时保留待核的文件版本，拒绝产生可用片段。种子文件或片段哈希失配时报告哪项失败，整批不落库；不把这类清单错误登记成原始资料的新版本。
- 卡片新增始终为 proposal，独立记录试用、批准和停用的时间及理由。并行修改只有基于当前版本的一次会成功。默认候选使用最新已裁定版本；仅保存新草案不会撤掉上一版。停用后仍可按旧引用回读。没有来源的模型提案只能保存为候选；要启用，需补来源或另建明确的作者版本。
- 首批只读回查 3 个文件的 13 个片段，导入 13 张候选卡：8 张方法及来源记录（6 条方法候选、2 张文风冲突证据）、沈砚与陆昭 2 张人物卡、首章 3 张场景卡。106.1 的定义、错误指令与纠正候选分别有版本与引用，错误指令不能启用。草案未知条件保持待确认；批准卡片不等同于分支采纳或正文事实。
- 可用 Python 接口登记与回读原文、导入种子、查看卡片/决定/关系。没有新增小说 CLI 命令，资料自动选配、故事状态和正式接受仍按后续里程碑接线。
