# 全局优先的拆解顺序

## 1. 原文目录与通读

导入文本保留版本 SHA-256。目录只按原文卷/章标题建立字面范围；卷首、序言、无标题范围明确标分析推断。没有卷标题就不虚构分卷。根范围及全部章节范围须覆盖已导入文本，同层范围不能重叠。

按章节范围分段通读，每段保留实际完整输入及输出。此时只登记人物、总览事件和原作证据，不产出可复用方法。每个新增事件必须属于当前章节/场景，至少引用一条当前段内的证据；细节只能引用本章已提供的总览节点，不能用其他段观察充作本段分析。证据必须是原文的精确摘录与 Unicode 字符位置；重复摘录必须明确起点。空白、换行和非 BMP 字符不能被悄悄改写。

人物包含身份、目标、初末状态和证据；后续同名、别名的归并通过 `canonical_id` 显式登记，检查未知人物和循环归并，不仅按名字猜测身份。

## 2. 形成全书总览

全部段落完成通读后，才整合核心问题、主线、人物弧光、信息与兑现、结构分段和覆盖限制。全局整合可以分窗口，但窗口必须携带全局总览、未闭合线索、已闭合线索索引、相关人物及端点证据。全局输出不能制造新原文、新事件或新人物。

最后一个全局窗口必须形成六项总览和有来源节点的结构，否则停止，不能跳进章场细拆。总览、线索及结构摘要随检查点冻结成 `global_basis`，保留其 SHA-256。

## 3. 带着全局依据细拆卷章场

再次逐段读取原文，提供冻结的全书总览、相关主线/其他线索、该章总览事件、已登记场景和人物身份。每个细节事件必须指向先前总览节点，不能由写作步骤补猜主线。

事件不只是“剧情发生了什么”：登记所属范围、总览/细节粒度、人物、目标、冲突、选择、代价、结果、信息前后、情绪前后、故事顺序和证据。原作未明确的内容保持待核，不强迫创造结果；故事时间与文本披露顺序分开。

模型识别的场景边界均标分析推断。场景只能在当前章节内建立或延伸，不能跨过所属章的边界，也不能覆盖原目录。

## 4. 逐职责核对跨章结构

对全部已登记细节事件（没有细节的范围保留总览观察），分别检查：

| 职责 | 必须具体记录的内容 |
|---|---|
| 主线 | 核心问题、目标、利害、结局联系、事件推进 |
| 支线 | 作用、与主线交叉、独立推进与结束依据 |
| 人物弧光 | 人物、压力、选择、代价、信念与状态变化 |
| 钩子 | 问题、预期、回应、升级、文本位置与事件链 |
| 伏笔 | 埋设、表面/真实意义、提示、回收、间隔与适用范围 |
| 信息披露 | 谁知道什么、读者何时知道、披露与误导依据 |
| 节奏与情绪 | 事件序列、紧张/松弛、情绪转变、转接与观察范围 |

每类最终必须说明已观察、未观察或存疑及依据；不强制每本作品都有同样数量的线索。关系包括因果、条件、对抗、回应、升级、预示、提示、回收、揭示、人物变化、情绪转变和主支线交叉。关系区分原作可直接观察与分析推断，并记录解释。

关系必须引用真实端点，保留两端各自证据；跨章关系至少两处原文位置。声称钩子已回应、伏笔已回收，须有对应关系。信息与埋收按文本出现顺序校验；因果的故事时间倒置、因果环标待核，特殊非线性/时间环可由作者说明后确认。

自动合并保留原观察，线索节点按原文位置排序，总览在同位置细节之前。该排序用于披露与阅读定位，不能视为已经证明故事发生时间。

## 5. 先审结构，再提炼方法

结构版本、审核决定和方法版本独立。自动结果从不自动批准。缺引用、假引文、缺总览对应或未覆盖范围会阻断结构批准；覆盖限制、未知结果及其他待核项需要作者明确确认。

当前批准结构可建立方法草稿。方法必须填写适用条件、前置、操作、产物、下游、验收、证据和不适用情况；保存来源作品、结构版本及实际线索/事件/关系依据。方法关系和证据不得借用其他无关线索。摘录或完整性未知不能提炼全书/整卷方法。

结构修订只新增版本，旧批准继续有效；批准新结构后，依赖旧结构的方法会提示来源已更新，需要依据新结构重新提炼。编辑方法保留其原始结构来源，不能通过修订抹去来源限制。

## 6. 中断、预算和失败

- 已完成的模型调用按完整请求指纹复用，不能换输入套用旧输出。进程中断后可从检查点续接；已有输出文件但数据库未完成的调用先重新校验文件，不再收费请求。
- 无响应、网络失败及结果未知保留原记录，不自动重试；作者需明确选择重试，并理解可能重复计费。无效或截断结果保留，不能用模板填补。
- 每次发送前核对次数和完整消息字符预算。估算给出已知最低需求 `2 × 原文段数 + 8`，长文本整合批次、提炼及重试会增加次数，不能当费用报价。
- 必需全局上下文超限时保存被拦截输入并暂停，不截断原文或丢弃未闭合线索。可以明确提高预算后续接；字符数不是 token 数，仍须按所用 API 容量设置。
- 续接只可调整调用次数和输入预算。原文、结构基版、模型配置及分析参数改变时，需要取消旧任务并重建，避免混合不同依据。
- 暂停在当前调用返回后执行。取消保留调用记录，迟到输出也不能发布新结构或方法；若任务已经先完成发布，过时的控制请求不能把完成状态改成取消。方法提炼整批完成并校验后原子保存，不把失败前一半候选悄悄入库。

自动结构和旧局部拆解共用同一作品执行锁；新任务登记到现有客户端任务管理中，当前客户端的 Git 同步等待任务结束再保存快照。正式参考文件、数据库全部版本、审核及逐次调用文件仍由同仓库 Git 快照保存。
