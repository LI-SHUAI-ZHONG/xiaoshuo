# 数据结构、接口和来源

本轮仅在独立 Studio 资料库新增六张表，不更改小说核心阶段路由与原资料裁定。

| 表 | 保存内容 |
|---|---|
| `corpus_structures` | 每本参考作品的最新版本与当前批准指针 |
| `corpus_structure_versions` | 不可变结构正文、来源 SHA、正文 SHA、阅读覆盖、任务来源 |
| `corpus_structure_reviews` | 每版一次批准/退回及作者依据 |
| `corpus_jobs` | 结构/方法任务、冻结参数、全局依据、分段/窗口游标和候选 |
| `corpus_calls` | 每次请求指纹、状态、完整输入/输出文件、校验结果、失败记录 |
| `corpus_method_origins` | 方法的每个版本到原作品、结构版本与实际依据的关联 |

`GET` 未建立结构的作品只返回字面目录及空观察，不落一个伪分析版本。手工初始化也只有目录。每次维护一条记录新增整个不可变结构版本，并检查预期版本，避免覆盖另一处修改。

结构 `schema_version=1` 包含：

| 板块 | 关键内容 |
|---|---|
| `source_extent` | `complete/excerpt/unknown`，作者声明及判断依据 |
| `overview` | 核心问题、主线、人物弧光、信息兑现、分段结构、覆盖限制 |
| `units` | 全书/卷/章/场景、上级、原作范围、边界来源与摘要 |
| `characters` | 身份、目标、初末状态、归并人物 ID、证据 |
| `events` | 粒度、上级总览事件、故事顺序、目标/冲突/选择/代价/结果、信息/情绪前后 |
| `threads` | 七类职责的有序事件链、人物、初末状态、各类专门分析、证据 |
| `links` | 前后事件、关系类型、所属线索、解释、观察/推断、两端证据 |
| `evidence` | 精确原文、起止 Unicode 字符位置、解释 |
| `domains` | 每类已观察/未观察/存疑，核对范围与依据 |
| `uncertainties` | 原作未明确、归并存疑、特殊时序等作者待核项 |

字段目录由 `/api/corpus/catalog` 实际返回，客户端使用相同目录生成普通中文表单。完整正文限制为32MiB，不会截断保存。通常通过单条维护接口编辑，不要求作者手填整份 JSON。所有引文仍须通过当前源文件及位置校验。

## API

以下 `root=/api/staging/{book_id}/corpus`，请求和返回均为 JSON：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/corpus/catalog` | 字段、职责、专门分析项、关系枚举 |
| `GET root[?version=N]` | 当前/历史结构、审核、问题、覆盖、分布统计、衍生方法 |
| `POST root/initialize` | `{extent,note,expected_version:0}`，仅目录 |
| `POST root/save` | `{expected_version,body,reviewed_units?}`，完整维护接口 |
| `POST root/record` | `{expected_version,section,row}`，维护单条/总览/完整性/待核项；引用以真实 ID 选择 |
| `POST root/record` | `section=read_confirmation,row=[章节ID]`，显式登记人工阅读确认 |
| `POST root/review` | `{version,decision,note,accept_limitations?}`，当前最新版结构审核 |
| `POST root/estimate` | 分段、输入预算及已知最低调用次数，不调用模型 |
| `POST root/jobs` | `{kind:structure\|methods,options:{…}}`，开始任务 |
| `GET root/jobs` | 本作品任务历史 |
| `GET root/jobs/{id}` | 参数、状态、游标、覆盖和逐次调用索引 |
| `POST root/jobs/{id}` | `{action:pause\|cancel\|resume,retry_failed?,options?}`；续接只可调次数/输入预算 |
| `GET root/jobs/{id}/calls/{seq}` | 完整实际输入、输出、校验和错误 |
| `POST root/methods` | `{version,thread_ids}`，从已批准结构建立待补齐手工方法草稿 |

`options`：`extent`、`note`、`chunk_chars`（1000–20000，默认6000）、`max_calls`（1–3000，默认128）、`max_input_chars`（8000–512000，默认64000）。方法提炼用 `thread_ids`，每批1–20条。结构中可以保留更多线索，通过多批提炼控制开销。

错误不会伪装成成功：缺配置为 `CONFIG_REQUIRED`；引文、引用、版本冲突、参数错误为HTTP400；不存在的作品/结构/任务/调用为404；不受信任网页来源的写请求仍由现有服务拦截。已保存草稿的引用缺项在返回 `issues` 中显示，并在审核时阻断。

## 方法与 Git 数据

新方法继续使用第2步的 `production_method_*` 版本、审批、证据和检索接口。`structure_origin` 附加源结构版本与 `thread_ids/event_ids/link_ids/explanation`，方法修改继承来源关联；不会删除旧局部拆解、自动继承旧审批或自动切换项目选材。

来源文件改变、撤回，或新的结构获批后，旧来源方法不再可用；仍可读取其历史正文、冻结依据和审批记录。新结构仅草拟时不使已批准旧结构及方法突然失效。

现有 `repository_data.snapshot/restore` 对实际 `workspace/library` 的数据库和原作/调用文件整体备份，因此六表、版本、审批、检查点及完整调用文件都进入同一 GitHub 仓库快照。隔离测试已验证恢复到另一工作区后结构和方法来源一致。正式模型配置、库和小说路径仍由现有仓库同步管理；API密钥仍只从设置中指定的环境变量读取。

此次未变更 `runtime_integration=not_connected` 的项目制作状态。方法结构已可维护与提炼，并不意味着已经按本项目语义前置选材或产出设计卡。
