# 实际数据与接口

没有引入第二份资料库或仓库外保存位置。来源仍在当前仓库的 `workspace/library`，本项目设计仍在其实际项目 `nw.db`；原有 `studio_data/runtime` 保存二者的完整Git快照。

## 新增项目配置

新立项提交 `production_methods`：

```json
{"tasks":["character_arc","main_plot","hook","pacing"],"max_methods":6}
```

实际类型由立项类型填入并规范化；旧导入项目可以明确提供 `type_ids`。后端冻结为 `production_method_policy`，含策略 `project-corpus-methods-v1`、任务、类型与每步上限。当前任务不会随着后续配置修改而改变。旧任务没有此字段时继续其冻结流程，不能被补一个“已使用新方法”的记录。

立项可提交 `method_preferences`，每项包含 `id`、`version` 和向导 `slot`。服务端核验该版当前仍获批准、类型及步骤匹配，并从资料库保存版本摘要、结构版本、原文摘要、引用和位置。制作策略中的 `preferred_methods` 由上述选择生成，记录方法 ID 与选定版本。

## 保存位置

| 数据 | 实际位置 |
|---|---|
| 后续配置 | 独立书库 `novels.wizard_json`，修改原因另记 `timeline_events` |
| 立项方法偏好与证据 | 独立书库 `novels.wizard_json` 的 `method_references` |

| 方法选择目标 | 初始目标在 `input_manifests` 的 `project-methods:{request_id}:{stage}`；刷新在 `novel_steps` 追加带新编号的候选记录 |
| 方法与前置确认 | `story_decisions` 的既有 `novel_confirm/novel_reject`，目标含专门的 `kind` |
| 实际输入与输出 | 每次阶段的完整输入清单、`task_calls` 及原始输出 |
| 方法执行 | 阶段产物的 `_method_applications`，实际操作与字段路径/值 |
| 下游回执 | 阶段产物的 `_method_receipts`，承接操作、字段与场景交接 |
| 设计与批准 | `material_work` 阶段会话、具体版本卡、现有 `plan_applications` 和决定 |
| 写作与审稿 | 已冻结写作包、独立审稿 `material_checks`，包含方法版本与真实正文引文 |

方法快照含正文、独立批准版本、原文定位、多层结构版本及具体事件/关系实例；回查使用只读连接，不初始化或迁移正在使用的库。完整状态按原有Git快照保存和恢复，不新增数据库表。

## 客户端接口

| 接口 | 内容 |
|---|---|
| `GET /api/kb/method-recommendations` | 按 `slot` 和 `types` 取当前批准的匹配方法；可按 `selected` 核对已选 ID 的当前版本 |
| `POST /api/novels` | 可提交 `production_methods` 和 `method_preferences`；客户端新建向导默认启用 |
| `GET /api/novels/{id}/methods` | 立项保存的方法与证据、后续配置、当前任务配置、实际执行和下游回执、正文审稿证据 |
| `POST /api/novels/{id}/methods` | `{policy,reason}`，保存后续制作配置；`policy:null`明确关闭，原因必填 |
| 既有 `GET /api/novels/{id}/progress` | 方法/前置确认仍是普通待作者确认节点，目标 `kind=production_method_selection` |
| 既有 `POST /api/novels/{id}/gates/{token}` | `{token,action,reason,method_ids}`，选定方法/前置；不得提交虚构方法或漏覆盖必需任务 |
| `POST /api/novels/{id}/gates/{token}/refresh` | 请求体 `{}`；刷新尚未确认的当前候选，有变化时返回新确认编号。使用已保存的前置产物，不触发模型调用 |
| 既有类型资料库接口 | 方法仍独立编辑和批准，显示是否已有可执行的多层结构来源 |

HTTP不会把错误当成功：配置格式、类型、无效方法、缺决定理由和不受信任来源的写请求均保持明确错误。制作运行时缺方法/前置为 `METHOD_DESIGN_REQUIRED`，来源/批准版本变化为 `STALE_PROJECT_METHOD`，执行/落点/回执不符为 `PROJECT_METHOD`，错误进入任务记录。

## 工程边界

原文和核心裁定仍只读，完整 `phase_routes.py` 不改。新代码在 `src/nw/production_methods/` 和客户端适配中，沿用原有预算、模型适配器、不可变版本、作者门、候选分支、独立审稿及原子接受。

27项本轮新增测试使用明确标记的 `[FAKE]` 来源与模型，全部位于隔离工作区。HTTP小型夹具不装全套原文治理资料，因此仅在夹具里关闭向导治理输入，专项验证方法接口和真实门控；实际治理代码未放宽，完整回归另行运行其原有测试。没有用该夹具宣称真实原义或文学验证完成。
