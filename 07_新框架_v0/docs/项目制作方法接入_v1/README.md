# 第4步：拆解方法实际用于项目制作

日期：2026-11-20。工程状态 DONE，详见[实际验收](03_实际验收记录.md)。本轮范围：按实际类型与需求选方法 → 确认本项目具体前置 → 执行方法生成真实设计产物 → 作者批准 → 下游承接 → 正文与独立审稿取证。真实作品与文学评价仍属于第5步。

方法不再只作为一段参考文字送入提示词。启用后，每条方法都要说明怎样把绑定的本项目前置变成真实卡片字段；下游收到产物后必须提交实际承接落点；正文审稿读取方法、具体设计、场景交接和实际稿件，按位置保留证据。缺资料、缺前置、无执行结果、无承接回执，均不能悄悄跳到写作补猜。

## 客户端入口

新建小说最后一步默认勾选“按已批准的拆解方法制作”，默认要求人物弧光、全书主线、钩子和节奏四类方法。可在制作台“⋯ → 具体制作方法与回执”调整任务，21类生产职责仍对应现有步骤和层级。

方法必须已经从已批准的多层参考结构提炼，并在类型资料库独立批准。手工方法或旧短文即使原来已审核，也不能绕过多层结构来源要求。项目按当前类型、制作任务、层级、产出步骤及真实前置筛选；有类型标签的方法不匹配时不会充作兜底。

到使用方法的步骤时，客户端停在“选择具体方法并确认前置”：

1. 阅读方法的适用和不适用条件，查看原作实际事件与多处证据。
2. 核对绑定的本项目前置及具体版本。上一步新生成的产物仍是候选，需要在此明确确认才作为方法前置；不能把刚生成当成早已批准。
3. 选择覆盖当前职责的方法，填写适用性和前置判断依据。前置缺少时返回补设计。
4. 方法按原有设计阶段执行，生成本项目具体卡片/设计字段。最终方案仍须作者批准，方法确认不代替设计确认。
5. 在“具体制作方法与回执”查看实际操作、具体产物、下游取用和正文审核证据。送达与有效执行分开显示，尚未写正文不会出现正文通过记录。

旧项目可以从同一入口启用后续方法调度；没有类型的旧导入项目需先明确类型。修改配置只影响下一次新建设计，当前任务保持原冻结配置。需要改变当前任务时先取消再重建设计；已有正文后的设计仍遵守候选分支与旧稿复核规则。

## 已落实的关键变化

- 制作调用前检查必需方法是否存在，避免没有相应方法仍先请求制作模型。
- 前置绑定保留立项需求、批准的父纲/实际状态、具体上游步骤产物和版本；作者确认其语义适用性，程序检查存在、引用与内容摘要。程序不声称能仅凭字符串自动理解全部适用条件。
- 输出必须落在现有阶段字段及正确卡种，值须与实际产物一致。所有被声明的操作和产物都要落实，不能只写“已使用”。多方案的剧情方向均须落实。
- 新方法模式下，全书组装保留已生成的世界、人物及剧情等具体设计卡，避免原有书级流程只保留剧情方向。后续仍按已批准父纲细化；书级不直接创建正文场景。
- 下游逐项回执，已批准父纲的方法产物继续进入章场设计。组装不得覆盖或丢弃方法落点；不一致时返回对应步骤补设计。
- 写作按具体场景的可见交接执行；独立审稿读取冻结方法与实际设计，并引用实际正文。只有通过现有审稿、事实与接受门才能接受正文。
- 方法版本、来源文本或批准结构改变后重新核验，停止继续使用旧依据；保存旧记录，不替换成另一个方法。
