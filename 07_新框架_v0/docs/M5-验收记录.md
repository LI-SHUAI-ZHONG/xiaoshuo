# M5 / T1：模型调用和迁移基础

日期：2026-11-03。依据：仓库 08 中的《小说部分架构与复用设计 v1》第 4、5、10 节和《小说部分实际搭建计划 v1》T1。

- 项目级调用支持规划、规则提炼、资料选配、状态提取、事实审查这五类结构化输出。只登记任务、实际消息、模型设置、冻结包、原始响应与独立校验状态；不创建章、场景、草稿、卡片或正式事实。
- 调用前在同一短事务写入请求及预算预留。相同调用只派发一次。根操作文件锁覆盖发起到结算：仍在执行显示 RUNNING；失联中断显示 UNKNOWN 并保留预留。显式重试须用下一尝试编号及新 ID，继续使用原冻结输入。旧场景流的写审改继续沿用 Run/Draft，运行中不能触发并行重试。
- 调用次数及上下文字符数在发出前检查，输出上限映射到提供器参数。费用用冻结单价和 UTF-8 字节数加结构开销估算；未报告可核实用量时保留预留。这个估算不能保证供应商实际账单或精确 token 数。
- 旧库逐级迁移到 v5，升级前在项目旁创建并校验对应版本的 `nw.v<旧版本>.<时间>.<标识>.bak`。每次旧库升级的 DDL 和版本号同事务；恢复应先保留当前数据库，再显式选择备份。新库没有历史数据可备份，从空库一次建成 v5。
- v5 新增 `task_calls`、`input_manifests`、`budgets` 和 `call_reservations`。原 v1–v4 表不重建。模型返回的原始文本与请求 ID 以 JSON 字符串保存，确保不合规的 Unicode 也能原样回读；结构坏时保留传输结果并标为 INVALID。
- 管理模式的显式场景清单要冻结分支、版本及故事/披露时序。旧 v0 自动快照只保留旧入口现有信息；还未有故事分支的项目级 plan/rule_extract 清单允许无时序。结构校验不代替后续里程碑的资料引用查证、故事状态验证与作者决定。
