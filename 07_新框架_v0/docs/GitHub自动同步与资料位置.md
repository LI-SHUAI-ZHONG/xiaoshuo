本次按作者明确要求增加自动 GitHub 同步，替代“只提交一次交付包、运行数据一直留在忽略目录”的旧交付方式。客户端直接使用 `D:\搭建` 这份 Git 工作目录，远程为 `origin` 指向的 `LI-SHUAI-ZHONG/xiaoshuo`，分支为 `master`。

## 实际使用的位置

以下路径均相对仓库根目录：

| 内容 | 客户端实际使用 | Git 保存方式 |

| GitHub 同步开关、远程名、分支、检查间隔、资料版本 | `07_新框架_v0/studio.repository.toml` | 文件直接随 Git 保存 |

| 书库、参考作品全文、拆解证据、知识升级与推荐 | `07_新框架_v0/workspace/library/` | 完整数据冻结到 `studio_data/runtime/` 并自动提交/推送 |

`workspace/` 是 Git 资料的实际运行工作区，位于本仓库内。客户端启动时将 Git 版本与本地状态对应；本地制作更新保存回 Git 快照，远端更新拉取后恢复到实际工作区。原始资料不从 C 盘聊天附件读取。旧 `config.toml` 仅为旧 CLI 的本地兼容配置，已不是客户端默认使用的配置文件。

## 启动与日常使用

双击现有桌面快捷方式，或在 `07_新框架_v0` 中执行：

```powershell
$env:PYTHONPATH='src'
python -m nw studio --host 127.0.0.1 --port 8767 --open-browser
```

桌面启动脚本明确指定 `studio.config.toml`。重新 Git 检出后首次启动会校验、恢复运行资料和作品，不必从 Codex 聊天目录补文件。设置页的“GitHub 仓库与资料”显示实际仓库、分支、配置与数据位置、最后成功同步时间；底栏也显示同步状态。

在通用 API 设置中填写地址、模型名、密钥环境变量名，保存后写入共享配置文件。实际密钥在本机设置对应环境变量后重启客户端读取；保存 API 设置和同步 Git 都不会调用模型。

启动后、保存操作后及每 60 秒会检查同步。设计/写作/拆解任务运行中暂缓数据库快照，结束后自动保存。SQLite 使用在线备份，包含已提交的 WAL 数据；不把锁文件、旧 `_qa_*`/`_pytest_*` 目录或系统临时缓存作为作品上传。

## 同步行为与异常

1. 保存本机非密钥配置、书库和正式作品的完整快照，逐文件 SHA-256 校验。
2. 仅提交客户端配置及 `studio_data/`，按施工规则更新根资料索引；不会夹带未完成的代码修改。
3. 拉取指定 GitHub 分支。远端领先时只进行快进，应用作品快照前保留本机文件备份。
4. 普通推送本机提交，不强制推送，不重置本地历史，不自动合并存在分歧的作品版本。
5. 网络、凭据、其他代码修改或分支分歧会显示具体原因，本机数据及提交保留；可在设置中“立即同步 GitHub”重试。

跨数据库应用因中断未完成时保存恢复标记，重启后继续从同一 Git 快照恢复。本地与远端独立修改而出现资料冲突时明确停下，不将一方静默覆盖另一方。GitHub 拉取了客户端程序更新后，提示重启再继续制作，避免旧代码运行新数据。

作品备份及同步状态在 `workspace/_git_sync/`，不重复上传缓存。`studio_data/runtime/current.json` 是当前 Git 作品清单；分片保存完整内容。原始资料与裁定基线仍保持独立版本和原有资格守卫。
