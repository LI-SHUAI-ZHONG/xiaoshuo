# 剧情与人物的 28 项能力如何进入制作

本表对照 2026-11-21 本次改动前的制作路径与修补后的运行行为。“已有”表示可以在步骤产物、校验或写作输入中找到承接。“部分”表示此前有相关资料或字段，但缺少表中指出的交接。文学效果要由实际章稿验收。

| 项 | 设计问题 | 改动前实际能力 | 当前由哪一步承担、怎样判断 |
|---|---|---|---|
| 1 | 为什么现在要写这件事 | 部分。剧情有目标、阻力和事件，单场进展没有固定的前因引用。 | 剧情设计先定章前问题。场景设计从本场选中的事件或已接受的上章变化取据，交代这次触发。错引其他场的事件要退回。 |
| 2 | 这一章向前走了哪一步 | 部分。章卡有目标和后果，场卡有进入状态和预期结果。 | 场景设计交代什么从何种状态变成什么，章首、章末分别核对起点和结果。一场有用的谈话或一次改判都可以构成进展。 |
| 3 | 公共往事与个人经历 | 已有世界前史、个人背景和分持有人状态。公共前史仍可能直接替人物承担知情依据。 | 世界设计保存已确定的过去。表达设计使用人物自己的经历、已知事实或实际获知的前拍。公共往事可以先透露给读者。 |
| 4 | 往事该概述还是展开 | 已有。表达设计区分概述、重演和回到眼前场景。 | 按当前情境决定讲一个结果还是写出当年的过程。选过去时必须有历史或已接受事实作为依据。 |
| 5 | 何时发生，何时让读者知道 | 已有故事时间、披露顺序和有序表达节拍。 | 原作拆解记录两种顺序。场景可以先呈现结果再讲过去，审稿用实际引文位置核对披露顺序。 |
| 6 | 主角抵达时，世界和别人正在做什么 | 部分。事件有情境，容易只写地点。 | 剧情设计在事件情境中交代仍在进行的活动，场景从中选择真正影响本场的情况。其他人的私人目的留在相应人物视角。 |
| 7 | 事件是否真有因果 | 部分。有事件前置、动作和状态变化，场景整体未区分因果与偶合。 | 场景设计区分因果、偶合、原因未明。写审检查读者能从哪一句看见触发、应对和后果，未决原因可以保留。 |
| 8 | 在场各人分别知道什么 | 已有按人和时间读取事实、误信、怀疑的能力。同场言行缺少具体接收者。 | 表达设计为当下言行标出实际见证人。只有发言者或见证者才能直接据此前拍回应，其他人要有后来转告等途径。新造人物即使恰好与旧资料中的人物同名，也不能继承旧人的知识。 |
| 9 | 读者知道，主角是否知道 | 已有旁白向读者披露和前文保护。 | 正文只收到本场安排的历史披露与人物可见资料。审稿和状态提取核对稿件位置，单靠旁白的往事不能改变主角所知。 |
| 10 | 消息怎样到达这个人 | 部分。可引用先前说过的话，但同场者都可能据此行动。 | 表达设计保留谁说、谁听、谁又转告。配角可以凭自己的消息开口，写作侧只收到他本场实际说出或做出的部分。写作前还要复核所引认知及其稿件证据是否仍是当前分支的有效版本。 |
| 11 | 用什么人称，跟谁亲历 | 部分。有视角人物，也有第一人称等写法资料，场卡没有独立的人称选择。 | 新场卡按已定文风选人称，单独保留视角人物。审稿看叙述句和亲历范围，对话出现“我”本身不足以证明本场采用第一人称。 |
| 12 | 为什么偏偏注意这个细节 | 已有人物目标、记忆、锚点观察者和感知节拍。 | 人物设计给出关注的理由。锚点与表达设计把理由落在他能看见或听见的具体对象，以及这次注意怎样影响下一步。 |
| 13 | 人物怎样解释所见 | 已有思想、推断及个人误信，缺少对部分信息来源的限制。 | 让视角人物根据自己的记忆、可见迹象或听到的话作判断。场尾计划不能提前充当已经发现的证据。 |
| 14 | 情绪为什么变 | 已有情绪前后、触发、人物行为和表达节拍。 | 章场进展也可选择情绪改变。检查可见的改口、迟疑、回避或行动，以及是哪件事改变了这个人。 |
| 15 | 想过以后到底做了什么 | 已有选定动作、代价、失败和可能结果。 | 动作设计落实选择，状态步骤核对变化。正文可以写出人物心里想质问、开口却先试探；实际发生的做法和后果以稿件为准。 |
| 16 | 谈话是否真的改变了局面 | 部分。有台词及回应，听众和章场进展之间缺少对应。 | 场景可选交流为触发。表达节拍明确发言者与听者，后续选择要能说清依据哪句话、为何这样理解。 |
| 17 | 什么时候能直接写另一个人的内心 | 已有按场切换视角和隔离私人想法的规则。 | 直接写他人内心要转到相应视角。留在原场时，可以写此人可见言行和当前视角自己的推测。 |
| 18 | 新剧情从哪里长出来 | 部分。事件系统有候选，缺少“这次转折从哪里来”的场级交接。 | 可选交流、新想法、发现、突发或前事延续，分别交代实际刺激和影响。后续仍有压力时保留，没有则结束这段因果。 |
| 19 | 为什么需要新造这个人 | 旧校验可以同时接受“须有人交接旧册”的原文和只负责“报糕点价”的人物。 | 建卡前固定事件、障碍、行动和预期后果。独立剧情编辑对照前置、现有人物及分支事实判断是否需要这个承担者。已有合适人选时给他分派本次职责。 |
| 20 | 反派、重要角色、普通人、消息提供者怎样分类 | 部分。资料有分类，卡上的单个角色描述难以兼顾。 | 人物卡分别写全书地位和本次职责。一个普通人可以负责关键交接，反派也可以提供真实消息。 |
| 21 | 每个有任务的人能否有一张可写的卡 | 部分。个人经历、行为、声线和独立目标曾可省略。 | 新建的有行动或交接的人物需提供当前欲求、相关经历、行为、独立目标、说话方式与剧情职责。写作按视角投递，初次出场可只呈现其中一部分。 |
| 22 | 配角和反派离开主角后还想做什么 | 部分。已有独立目标字段，可能不填。 | 人物设计交付这个人自己的目标、为何参与及打算。换到其视角时可以沿这条行动线继续；其他视角只收到当前可见的部分。 |
| 23 | 开局如何交代主角 | 部分。原有开篇资料与检查，人物首次出场未必留下可核对的正文节拍。 | 人物设计明确开场呈现方式，首次出现场景接收相应表达任务。处境、眼下所求及行动可以共同完成开场，保留有意隐藏的来历。 |
| 24 | 第一次出场，谁介绍了谁 | 部分。已有身份、声音和披露相关资料，首次介绍没有固定的当事人和听者。 | 新人物可自报、由具备依据的人介绍，普通角色也可由可见行动辨识。表达步骤核对这是否首次登场、介绍者是否在场、谁实际听见。 |
| 25 | 隐藏身份怎样留下伏笔和兑现 | 部分。已有身份状态与伏笔，公开角色卡仍可能提前露出身份。 | 人物设计分别保存明面身份、可见线索、真身份和揭晓依据。表达设计核对揭晓触发，写作包检查提前披露，个人说法按其可信范围承接。 |
| 26 | 上章收获怎样影响下章选择 | 部分。章末有世界变化与身份披露，普通人物的认知、误信等变化容易遗漏。 | 已接受章稿的普通人物变化保留持有人、判断性质和正文证据。续章剧情可以引用仍有效的前置，已由审稿核验的进展与留下的问题也可供续章选用。 |
| 27 | 从原文究竟拆出什么 | 部分。已有叙述、信息、人物弧光等观察，缺少章场进展和角色出场的专门观察。 | 第四版多层拆解补上这两项。声称“后来用上了”或“身份揭晓了”，要有前后事件、按顺序的两处原文及能连接它们的关系，短摘录可留未决。 |
| 28 | 成品能否让读者自己看懂这个人 | 部分。已有独立审稿、原句定位和修订，部分新设计没有进入写审。 | 按本场实际选择核对人物、身份、信息传递与进展，用本稿原句说明效果。通过的状态与证据可留给后续章节。人物是否令人信服仍需阅读成稿作判断。 |

### 角色为何在这一章出现

例如本章要查出谁在夜里过闸，但主角无法独自打开存档柜。若前章已写明值守人保管钥匙，并有理由配合，他可以用原人物卡承担本章交接。若已有的人都接触不到旧册，而归还前必须由当班抄录员签认，剧情才有引入抄录员的理由。无论由谁承担，剧情设计要落实到事件，场景设计要选出此人实施的动作和它造成的变化。独立审稿用本稿原句核对二者。正文用角色当时说出的话、做出的选择来呈现，可以自由措辞。

新方案在世界设计结束、人物设计开始之前完成第一次用人判断。编辑能看到当时的剧情前置、候选演员及分支事实。每批有用人需求时增加一次独立模型调用，沿用项目审稿模型和现有预算。编辑退回时，流程只修订用人提议并复核。细化剧情时才发现缺口，可以把本轮具体转折、依据和现有人选一起送回人物及关系设计。每轮方案允许一次集中回补，仍有缺项时给出原因并停在设计阶段。

章场分派可以改变。一名普通值守人本章交册，下章为保住同僚而拒绝作证，两件事有各自的剧情依据。新分派沿用这个人的身份，前一章已验收的动作、后果和稿件原句可在续章读取。全书按共同的剧情前提提出用人需求，某条分支独有的人选等方向选定后再设计。围观者和环境变化都可以作为背景。复用时需要核实所选人的条件，提议新人时需要逐一说明当前分支已批准的人为何难以承担；长篇中候选人物越多，这一步所需的模型上下文也会增加。

### 一场交流怎样验收

假设林只悄悄告诉主角“旧库里可能还留着一封信”。许某虽在同一场，却没听见。设计应允许主角改道去查，也允许他把听来的消息转告许某。许某在转告发生后才有依据动身。林私下怀疑寄信人用了化名，只有当她说出这一点，或主角取得独立证据，主角才有依据就寄信人的身份作判断。查到信、听说有信、决定去查，在交给下一章时是三种不同的结果。

这个例子用于说明验收口径。生产中的具体人名、事件和写法由本书前置与所选方法决定。

### 何时会用到拆解资料

新建的正式章场会执行人物、进展、叙述和写审要求。导入参考作品后，多层拆解第四版才有该作品的章场证据可读。观察和提炼出的方法分别审核。批准后，立项的「人物」和「结构」能按类型推荐相应方法，制作时再核对本书的前置与实际产物。普通人物与剧情方法沿用项目的选用设置和确认流程。历史任务按冻结版本恢复，旧卡可供后续方案沿用。

多个角色同场时，审稿用本稿引文核对消息归属。只凭某人自称的身份，最多能确认他说过这句话。若要记录主角已经核实身份，应能指出独立凭据以及主角为什么有机会取得它。至于一个人物的反应是否自然、读起来有无说服力，最终要看真实模型的连续章稿。

### 2026-11-21 从正式桌面入口复验

复验时，桌面端口 8767 返回拆解第二版、8 个分析项，同一时刻本地与 GitHub 的提交已经包含第四版。原快捷方式只识别服务名称。现在启动时核对实际后台的仓库、工作区、配置、代码与步内资料指纹，以及它声明的分析项和制作校验版本。新版后台空闲时可以交还端口；有制作或拆解任务时会保留正在进行的工作。GitHub 同时更新程序和作品资料时，由重新启动的程序读取配套资料。

| 交接处 | 此次复现的偏差 | 新方案怎样验收 |
|---|---|---|
| 原作 → 拆解方法 | 编辑请求可把第四版降成第一版，跨章观察也可能用全书或卷的位置作证。 | 保存时拒绝降低已有版本。跨章收获要定位到两个具体章节、按序短引及连接事件；身份揭晓要能追到同一人物。 |
| 拆解方法 → 人物、剧情和场景 | 某些方法只在后续步骤适用，却在前步被判缺；职责回执可能引用同场的另一个角色。 | 按本项目条件冻结可承接的步骤，复用已有角色也能落到本次具体分派。下游核对同一职责、场次和实际产物。 |
| 人物卡 → 表达与正文 | 私有记忆可能泄露，人物自称可能被当成已经查明的身份，临时同名人物还能借用旧人的凭据。 | 分清谁在说、谁听见、当事人掌握什么。角色可据自己的疑心行事。确认身份须有该获知者可接触且指向同一人的独立凭据，揭晓顺序还要对照正文。 |
| 章纲 → 审稿 → 续章 | 本章总体进展通过，就可能把计划中尚未写出的疑问交给下章；仅因角色职责间接引用的旧稿可能漏掉写前复验。 | 审稿对照获批章首目标和章末后果。遗留问题需要本稿单独的证据。续章按当前分支复核前章版本、人物职责和披露依据。 |
| 保存、重试和接受 | 冻结任务与阶段内的规则不一致时，有入口仍可走较旧的校验。 | 新任务冻结现行版本，装配及重新采用时核对原任务和阶段记录。合法历史版本可重放，缺少必须的资料或版本冲突会在继续制作前报出。 |

隔离连续章测试从第一章审稿、接受、关闭重开开始，走到第二章批准与实际写作包。正例承接上章已经写出的行动与结果。对照组通过了一般进展审稿，但未在正文呈现预设疑问，续章不会收到该疑问。正式端口已另行核实为拆解第四版、11 项。以上验证针对流程和输入输出，文学效果仍需真实章稿与读者判断。

Windows 启动脚本也经过实际命令解释器验证。仓库路径带空格及中文时，项目虚拟环境和系统 Python 两个入口都会收到同一配置和端口。Git 检出时保留批处理所需换行，启动失败时的退出码会传回调用方。

### 第五版拆解与制作中的角色阵容参考

进入**知识库 → 拆解条目**或**预存库**可以查看现行的 12 项观察，空库也显示各项要查的字段。第 12 项是**角色数量、种类与章节分布**。打开一部作品的角色阵容或逐章分布，可由人数追到人物、章场事件及原文。

| 问题 | 统计与取材规则 |
|---|---|
| 实际出场多少人 | 按可辨认的个人去重，归并有依据的别名；仅被提及的人另列。群体和归属未明的称呼保留在观察记录中。未核实的章节显示缺少观察。 |
| 这些人起什么作用 | 分别记录全书地位（主角、反派、重要角色、配角、普通角色、未明）和该章职责（推动、阻碍、协助、提供信息、交接、见证等）。同一个人可以随剧情改变职责；每种类别内按人去重。 |
| 哪一章引入、哪一章复用 | 逐章给出实际出场、在覆盖文本中首次出场、再次出场及仅被提及的人数；观察带有章场及证据编号。摘录只支持其覆盖范围内的判断。 |
| 某类型大概用多少人物 | 类型图鉴的「人物阵容」和立项向导的人物步骤读取同一批已批准、类型相符且来源仍有效的作品。只有完整且各章均有可统计观察的作品进入全书范围；完整多章样本另按前、中、后三段比较每章人数、地位和职责。页面列出样本数及具体来源修订。 |
| 怎样用于本书 | 新设计任务从当时的参考库取得聚合数据，交给提出用人需求的世界设计、人物、剧情和场景设计。样本范围不会替本书决定要造几个人。已经发出的任务按冻结输入回读。 |

在隔离样例中，第一章阿霜递出路引，老许接过并提到秦师傅；第二章被称为小霜的阿霜登舟。两章合计两人实际出场，一人仅被提及。第二章是一人再次出场、新出现零人。图鉴和立项得到同一统计，制作调用中收到范围及来源版本。撤回完整样本后，新任务只保留剩余摘录所能支持的章内范围。

修复前，知识库侧栏指向旧局部短文，预存库空库不显示现行目录，部分旧推荐和升级文本还能自动进入新书。现在首页、通知、立项和制作使用现行结构和方法；旧短文、旧升级记录、冻结修订仍可从历史入口核查。浏览器在后台更换版本后会提示重新载入，已打开的旧页面无法用旧表单提交到新版后台。
