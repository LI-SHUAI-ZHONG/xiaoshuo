# 资料原文、转译层与运行层接入

2026-11-06。属于现有 M10 资料接入续作，F5 全量工程验收与最后真实创作仍分别待验。规则单沿用程序中的 `contract` 字段；配对、工程通过与文学效果分别验收。

## 批次14：普通入口与阶段功能

普通 `plan propose` 和 `novel start` 的设计流程现在会读取冻结资料目录，按任务、条目原义及当前类型条件召回具体来源，先形成候选设计。作者可继续显式指定 `materials`；细化继承已选来源、边界和理由。没有目录的旧项目会显式记录 `catalog_missing`；已有目录但规则账本过期则停止，不静默绕开资料。召回结果不是小说事实，仍须具体绑定、作者采用和独立证据核验。

选材与参数转化的必用流程独立装配；可选方法保持有限召回。动态关系连同确切静态前置一起装配，类型条件未满足的边不进入当前方案。原始资料都可查，未命中或缺资格仍留在完整账本；不把全库同时塞进一个场景。

| 来源 | 专门产物 | 实际核验 |
|---|---|---|
| 126.9 时间线调用 | 时间锚点、单位、每场起止与季节、此前时间状态 | 按故事顺序核对计划；用正文提取并独立核验 `timeline_span`，接受后进入后场状态 |
| 126.10 伏笔网络调用 | 伏笔卡、埋设/休眠/唤醒/回收阶段及前后状态 | 禁止先回收后埋设；核对正文 `promise_stage` 变化；按原规则周期及收尾范围核查全量已埋设状态 |
| 126.11 多视角调用 | 实际主角、逐场前后视角、切换理由与源规则参数 | 比较被冻结的真实前场；允许同时引证前场和本场；周期比例按实际稿件字数计算 |
| 126.12 一次性前置调用 | 本次新建人物/世界及开篇、收尾对应的具体设计卡 | 对照真实成员及完整卡片内容，不能填通用“已检查”；候选身份与正式事实继续分开 |
| 126.16 模板版本管理 | 每项实际采用来源的用途、`unit_start`、周期及 `unit_end` | 单元结束即核对整个单元；逐来源审稿结果保存，后续设计读取已接受稿的效果反馈 |

阶段记录使用 `process_bindings` 保存，并随设计冻结其成员、章场坐标、引用及来源字段处置。写作、接受和重开再次验证。全案说明和后场秘密留给设计与审稿；写手只得到本场时间数据、当前可见伏笔表现及原有 POV 工作包。

原文中的周期或比例仅在本项目明确采用对应来源后生效；它们不是所有小说的全局限制。专门产物不能替代被引用子项自身的语义核定，错号、缺义或不完整依赖仍保留问题，不按近似名称猜补。

## 字段隔离与功能重建

`confidence=999` 不会被改成另一个数字。仅当缺陷确实局限于评分元数据、其余原义及依赖均完整时，建立 `field_isolated_functional_reconstruction` 覆盖层：隔离评分，保留原状态、原缺陷、有效字段和确切来源。原定义缺失、错引用、相互矛盾或不完整依赖仍不能提升资格。

组合的正向方法依赖递归核验，并将真实条件、限制和判据带入组合要求。`excludes_rules` 是排斥边界，不作为必须执行的依赖；候选效果或触发条件只有在字段完整、明确归属本组合已采用的确切父规则时随父使用，不单独冒充执行方法。嵌套旧升级从有效内容及原文义务中递归剥离，原字节仍可按哈希回查。

补齐了尾部原文及不配对括号的识别，修复适配项将被引用类型 ID 当作自身 ID 的定位错误。刷新只添加识别位置、校正派生标签；原始来源、片段和旧引用不删除。刷新前的目录另有本地备份。

完整的组合候选另以 `adoption_scope=proposal_only` 进入设计。其 `status=candidate` 和 `selection_status=candidate` 保留；不改成 active，不自动成为作品事实。缺少定义、引用未齐或依赖只是模板的组合仍阻断。自动选配先确认任务明确涉及的类型，再召回至多一个相关的现成组合和一个精确连接，供作者随方案评估。

## 当前阶段的真实模型输入

普通入口接通全目录后，曾发现来源信息和重复原文挤占上下文，使三个真实目录的全书设计请求都触发 `CONTEXT_TOO_LARGE`。现由 `stage_input` 生成当前阶段实际发送的材料：活动义务保留确切 ID 和全文，同一义务在分类列表中的重复只发送一次；全书阶段尚未执行的场景方法保留来源及用途，完整细则仍在不可变的完整资料快照中。细化到对应阶段时重新装配活动要求。

计划保存完整材料、实际消息及 `model_package_sha256`；不能用缩略消息替换存档原文，也不把已拒绝的旧升级重新作为指令发送。三个真实目录、独立测试故事库的普通全书请求已核对实际消息长度为 8,558、29,702、18,529 字符，均可在 45,000 字符预算内准备。这里只准备与冻结请求，未调用真实模型、未写入正式小说正文。

## 批次15：文档治理、验证规范与空库

原来未归属的 23 处附层现按确切冻结来源和 SOURCE 文档识别：字段说明 1 处、枚举 1 处、验证规范 4 处、项目配置 2 处、空集合容器 15 处。原文文档、运行层及具体定位分别保留哈希，字段说明中被误当作 ID 的字典须唯一对应原字段，不能按近似名称猜配。

`materials audit-layers` 会实际执行声明的字段类型、`min/max`、正则 `pattern`、枚举及集合数量检查。字段及枚举检查读取同版本的 3,135 条静态类型连接；逐集合位置包含缺 ID 和非对象记录，不能跳过异常后报通过。缺检查输入、缺声明枚举依赖返回 `not_checked`。15 个原文空库均保持实际条目数 0，旧附层中的角色行动模板不赋予其创作或正文权限。

治理归属另列 `governance_routes`，不增加创作方法配对数或可执行规则单数。验证规范和项目配置目前仅核对结构并保留原规则；字段格式的描述性含义也不猜成确定校验。共 7 份文档规定的功能仍未全部接入相应环节，不能以这 23 处归属已明确而宣布治理功能全量完成。

## 对照与互补

完整拥有者现在包含 `layer_contract`：原文版本和对象哈希、运行层单位哈希、字节范围、行号、JSON Pointer、被采纳或拒绝的字段及理由。原件保持只读，旧 `model_input_eligible`、`completed` 和授权记录仅保留出处作用。

| 来源 | 配对依据与实际用途 |
|---|---|
| 资料库 | 同版本确切条目及实际相邻升级；按原义确定设计、表达、叙述或流程功能 |
| 静态网络 | 起点、终点、该版本边序号及冻结对象；检查关系约束及实际影响，不强求状态变化 |
| 动态网络 | 本边 ID、触发、效果和确切前置静态关系；检查行动因果、前后状态和知情获取证据 |
| 锚点 | 内联拥有者、相邻或唯一原表项；检查对象、POV、原条件及观察时机，不强求选择或代价 |
| 类型与连接 | 对象范围、原生 ID、准确 SOURCE 块；旧序号须与确定的 JSON Pointer 对应，保留两种身份 |
| 类型画像 | 同版本准确 canonical_name；分别保留核心元素、读者期待、风格、篇幅和风险 |

有原文依据的内容、需要具体化的模板及错位/无依据字段分别登记。附层配对不能使缺义、错误依赖或冲突规则自动合格。尚未合格项保留原资格，形成“补原义及依赖→按目标功能重新设计→验证阶段产物”的逐项重建步骤。

## 当前项目的具体转译

有 `review.layer_contract.execution` 的绑定必须填写 `layer_application`：

```json
{
  "trigger": "本项目何时满足该项原条件",
  "operation": "在相应环节执行什么具体操作",
  "result": "应产生什么可观察或比较的效果",
  "verification": "用哪些真实产物和判据验证该效果"
}
```

每项须是不同的具体内容，不能复述资料名称。原条件、例外、限制和判据继续逐项填写 `source_scope`。原文明确的功能优先；运行层中的通用角色行动模板不能把叙述指标或流程规则变成人物动机。

106.1 的完整条目已有一项来源固定的修复：按原定义比较全书叙述语言的句式、用词和叙述距离。身体信号、情绪压抑及一秒识别的错位字段保留在原缺陷中，不进入有效规则单。

## 流程资料的阶段产物

- `material_selection` 在 `process_bindings` 中返回 `task_function`、`selections`、`exclusions`。选中项引用实际来源 ID、`source.fragment_id` 和理由；作者 `material_deferrals` 的范围延后列入本轮排除，保留原理由。
- `material_conversion` 返回 `mappings`，逐项包含 `scene`、`id`、`parameter`、`observable`、`check`。后三项须与实际场景绑定一致，每个已采用的场景规则都有对应映射。

流程记录随作者确认的设计保存。重开、写作和接受前再次检查；旧设计缺这些记录须重新设计。这里验证设计产物的结构、引用和一致性，不宣称已经独立验证了文学效果。

## 写作与效果核验

写作只取已批准的 `observable`、`check` 和相应领域可见字段。完整转译的幕后触发背景、远期结果及验证上下文保留在设计/审稿，不整体送入写作包。

有附层的审稿另返 `layer_check`（`status`、`reason`、`evidence`），核对转译是否保持原义及作用对象，并判断承诺效果是否成立。通过项须引用同版本同哈希的有效句段；范围审稿覆盖指定的每章。漏项、失败、未验证均不能接受。动态状态继续独立核对假设、前后状态与知情证据，接受事务重新验证当前来源、设计和稿件。
