# 第 2 步：按生产任务与产物重组类型资料库

日期：2026-11-19。状态 DONE（第 2 步的方法库组织、维护与需求规格；多层拆解、项目实例化和真实文学验收仍待后续完成）。

本轮接续[实际制作步骤审计](../制作步骤与类型资料库审计_2026-11-19/README.md)。已实现可编辑、可审核、可按版本复查的方法库，入口为客户端“知识库 → 类型资料库”。不把本轮方法库建设等同于多层自动拆解、项目设计卡生成或真实小说验收完成。

## 已实现的变化

- 按 **21 类生产任务 × 全书/卷/章/场景 × 类型范围** 组织方法。任务覆盖既有十四阶段，包含主线、分卷、连续章纲、人物、关系、事件、行动、钩子、伏笔、节奏、信息与表达等职责。
- 每条方法有八类要求：**适用条件、所需前置、具体操作、预期产物、下游用途、验收方法、原作证据、不适用情况**。前置、操作和产物有独立标识，操作必须引用前置与输出，每个输出必须有下游和验收。
- 预期产物只能对应现有设计步骤的真实字段；卡种也须符合该字段。目录和表单显示中文职责，不把虚构的新字段当作已有引擎能力。
- 草稿可以不完整；批准前须补齐八类要求和引用关系，且原作已审核入库、字节/字符位置与冻结来源相符。每次编辑新增版本，审核决定对应具体版本并保留依据。
- 已批准旧版本在新草稿待审时保留。来源撤回或原文改变后，当前方法显示来源不可用，不删除历史记录。旧拆解短文自动迁为待补齐草稿，原行、原证据、原审批、升级与旧冻结引用保留，绝不自动升级为完整方法。
- 统一结构/钩子的旧默认步骤映射与向导偏好；`production_inputs.STAGES` 直接引用 `catalog.SLOT_STAGES`，不再维护两份不同规则。

## 如何使用

1. 在预存库导入参考作品，核对类型并审核入库。只作收藏的作品也可由作者据其真实证据手工维护方法；现行局部自动拆解仍属于旧入口，尚不是下一步的多层拆解。
2. 打开“知识库 → 类型资料库”，按生产任务、层级、主/子类型和审核状态筛选。类型图鉴详情也有对应类型的方法入口。
3. 新建方法，先说明适用条件与前置，再定义产物、操作、下游及验收，并定位原作短摘录。跨章作用应添加多处证据并说明联系；不能靠单处短文声称全书效果成立。
4. 保存草稿，按详情列出的缺项继续补齐。批准须填写审核依据；退回也保留原因。已批准版本修改后保存新版本，不覆盖旧版本。
5. “旧拆解条目”保留原统计和证据。旧短文的方法草稿需另行分类、补齐和审核；原审批不替代新方法审核。

“已批准”只表示方法库这一个版本的结构与证据经作者审核，**不表示它已在当前小说执行，也不表示文学效果已经验证**。当前新增方法还没有作为项目卡生成的调度输入；该接线属于第 4 步。
