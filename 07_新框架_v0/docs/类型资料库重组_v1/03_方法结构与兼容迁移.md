# 方法结构、版本及兼容迁移 v1

## 文档字段

方法文档的 `schema_version=1` 由服务目录提供。类型仍用于过滤，不是唯一分类轴；任务、层级与产物必须单独声明。

| 字段 | 结构与用途 |
| --- | --- |
| title / tasks / scopes / type_tags | 名称；生产任务 ID；全书/卷/章/场景；真实类型 ID，自动保留父类。类型留空明确表示跨类型，适用条件仍必填；不自动从某一作品推导整个类型通用 |
| applicability | 适用条件列表。人工/模型语义分析仍需后续核验，非空不代表条件已成立 |
| prerequisites | 每项 key、input_kind、artifact、requirement；说明需要什么具体资料/批准设计及其条件。是方法级要求，还不是本项目产物引用 |
| operations | 有序列表：key、instruction、input_keys、output_keys。引用本条方法已定义的前置与产物；不能有悬空引用、闲置前置或未由操作产生的输出 |
| outputs | key、stage、field、artifact_kind、description。stage/field 必须是当前真实阶段及其字段，且在声明的每一层级实际执行；世界/人物/剧情/卷章/场景卡限于相应 members 字段及允许卡种，其余是步骤产物。跨层操作不同则拆成独立方法，不能给 book 声称其并不执行的事件/表达步骤输出 |
| downstream | output_key、consumer、usage。每个输出须有下游；设计消费者不能倒向更早的阶段。跨范围同层交接以后须由实例化层明确父子身份，不能用该列表假装已交接 |
| acceptance | output_key、check、evidence_required。每个输出须有检查和具体证据要求；程序不把自由文本的检查自动打分为文学通过 |
| evidence | 可多处：book_id、start、end、quote、explanation。起止为 Python/Unicode 字符位置，end 不含末字符，保留原文空白。服务端查重定位，不用浏览器 UTF-16 下标冒充字符起点 |
| non_applicability | 不适用情况/反例边界。必须填写，不能把来源缺义说成项目不适用 |

行标识以字母开头，使用字母、数字、下划线。每部分最多 64 项，方法正文不超过 96 KiB；限制用于可审阅的独立方法载荷，超出须按用途拆分，不静默截断。原作摘录最多 1,500 字；多处证据各自定位、冻结来源哈希。

所有八类内容都可在客户端表单维护。版本、哈希、旧行快照等由服务生成，用户不能通过方法内容把自己提升为原始资料、项目事实或作者批准的本项目设计。

## 来源与审核

保存时核对原作真实位置；作者可保留结构不完整的草稿。批准必须指定当前版本和审核依据，并重新检查八类完整性、所有引用关系、来源已入库及其冻结版本。原作变化或撤回后，当前可用性失效，历史方法/证据不被重写。

`review_state` 为 draft/approved/rejected；当批准版本的来源失效时，显示 `source_unavailable`。`available` 表示本方法库当前结构/来源/审批可用，**不是本项目可以直接执行的结论**。`runtime_integration=not_connected` 如实标示第 4 步尚未接通；`missing_input_policy=return_design` 是待实例化时必须执行的规则，本轮没有声称已经拦住正文阶段的所有猜测。

保存新草稿时，`expected_version` 必须等于当前最新版本。旧批准版本保留为 `approved_version`，直到新版本批准后切换。每个版本只记录一次批准/退回；退回后修订新增版本。审核不能倒回旧版本或覆盖原内容。源失效仍保留冻结原文和原审核，不能以重新开库自动恢复批准资格。

## 数据表与迁移

新增四表：`method_schema`、`production_methods`、`production_method_versions`、`production_method_reviews`。方法正文/哈希、原文定位/源哈希、旧数据原行快照和审核依据分别保存。

旧 `decomp_items`、`type_kb`、升级版本、采用统计、项目向导及历史冻结引用不删除、不覆盖。启动迁移和新旧拆解导入时，以唯一 `origin_item_id` 创建一次方法草稿，保留旧原行 `legacy_json`；用途短文暂放为待建立前置/输出关系的操作文本。旧类型标签及原证据保留，任务和层级保持未知，绝不根据槽位猜成全书结构或直接继承旧批准状态。

迁移加表可重复执行；草稿转换在 SQLite 事务内完成，唯一来源键防止重复导入。原审批/升级仍属旧入口，新方法须独立补齐与审核。旧推荐入口继续兼容原示例，客户端将它标为“旧拆解条目”；本轮没有把旧示例批量升格为完整方法，也没有切换当前小说的冻结输入。

## API 与查询

| 接口 | 行为 |
| --- | --- |
| GET /api/kb/method-catalog | 任务、层级、输入种类、真实阶段/字段/卡种及八类要求 |
| GET /api/kb/methods | task/scope/types/status/q 组合过滤，limit/offset 分页；不声称已检查本项目实际前置 |
| GET /api/kb/methods/{id}?version=N | 指定不可变版本及历史；省略版本读取最新草稿/修订 |
| POST /api/kb/method-evidence | 按作品、原文短摘录及可选起点定位；相同摘录多次出现必须指定起点 |
| POST /api/kb/methods | `{body, expected_version:0}` 建立草稿 |
| POST /api/kb/methods/{id} | `{body, expected_version:N}` 保存新版本 |
| POST /api/kb/methods/{id}/review | `{version, decision, note}` 批准或退回指定当前版本 |

全部状态默认查看最新版本；筛选“已批准”时读取仍有效的批准版本，即便已有新草稿。筛选类型时保留主/子层级，所选标签须全部匹配方法声明范围；跨类型方法仍由作者查看适用条件。查询没有按热度把缺方法的任务补成假推荐。

## Git 与正式资料位置

实际数据库是本仓库 `07_新框架_v0/workspace/library/library.db`，原作在同目录 imports；现有同步将整个数据库和原作文件冻结到 `07_新框架_v0/studio_data/runtime/` 的普通 Git 分片与清单。因此新方法表、版本、审核、引用证据会随同一份书库同步，没有增加 C 盘独立资料目录或第二个正式来源。

隔离测试通过现有 `repository_data.snapshot/restore` 备份和恢复完整方法库及原作，复查方法哈希、审批和证据仍可用。正式自动同步结果与测试摘要见验收记录；不能仅凭支持新表就宣称一次真实 GitHub 同步已发生。
