# 客户端实际资料的 Git 存储

客户端默认使用本仓库的 `studio.config.toml` 和 `studio.repository.toml`。
API 地址、模型和密钥环境变量名都随 Git 保存；密钥值只读取本机环境变量。

原始资料仍是仓库根目录 `02_原版资料/`。当前可恢复运行资料基线由
`studio.repository.toml` 指向 `fixtures/materials_runtime_baseline/`；启动时
校验原件与裁定指纹，首次检出自动恢复到仓库内 `workspace/materials/`。

`runtime/current.json` 和压缩分片保存实际书库、导入参考作品、知识升级、
正式小说的全部数据库及项目文件。SQLite 采用一致在线备份，逐文件附 SHA-256。
客户端实际读写仓库内 `workspace/`；它是上述 Git 资料的运行工作区。
启动后、保存操作后及每 60 秒自动检查同步，制作/拆解进行时等待其结束。
保存本地版本后正常推送 GitHub；远端只接受快进更新，有分歧时明确暂停。
远端作品资料应用前保留本地备份；不上传旧 QA 目录、锁、环境文件和临时缓存。

重新检出仓库后，直接启动客户端即可恢复当前资料和实际书库。
每台机器分别设置 API Key 环境变量和 GitHub 的 Git 登录凭据。
设置页显示仓库、分支、实际配置/资料位置、最后同步结果，并可立即重试。
GitHub 程序更新需要重启客户端后继续制作，避免旧代码运行新版本的数据。
