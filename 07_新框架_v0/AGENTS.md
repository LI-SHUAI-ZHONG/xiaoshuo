# AGENTS.md —— 07_新框架_v0 施工规则（Codex 必读，优先级最高）

本文件只管 `07_新框架_v0/` 这个新目录。它与仓库里其他任何施工文档冲突时，**以本文件为准**。

## 1. 这是什么

一个**小而能跑**的小说写作骨架 v0：从一句话需求，走到一个场景/一章正文，能存盘、能回看、能重跑、能做 A/B 盲测。
成功标准只有一个：**用命令行从头到尾跑通一个场景，重启后还能读到全文和每次运行的完整记录。**

## 2. 与 ACCOS 的关系（重要）

- `01_搭建框架_ACCOS/` 整体**冻结**：不改、不删、不移动、不继续第 29 步及以后。
- **不要读** `01_搭建框架_ACCOS/后续执行/` 里的施工卡和 `10_Codex总执行指令.md`。其中“24–44 不运行测试”“完整保留扩展功能”等规则**对本项目无效**。
- 01–06 目录对本项目一律**只读**，只在指定里程碑里按指定路径读取少量配置。

## 3. 不许做（范围红线）

不做：Web 前端、Next.js、FastAPI 服务、PostgreSQL、Redis、Docker、向量库、多用户/权限/登录、插件市场、IP 出版、多模态、实时协作、支付分成、自动进化。
不要“顺手”为以后预留这些东西的接口、空模块、Null 实现。需要时以后单独开里程碑。

## 4. 必须做（工作方式）

1. **按里程碑顺序做，一次只做一个**。做完当前里程碑就停下，按第 7 节格式汇报，等用户回复“继续”才进入下一个。不得提前实现后面里程碑的功能。
2. **每个里程碑必须真实运行测试**（`python -m pytest`）并贴出实际输出摘要。没有运行过的东西不得写“通过”。
3. 状态只允许四种：`PLANNED` / `IN_PROGRESS` / `DONE`（附验收命令及其真实输出）/ `BLOCKED`（写明具体原因）。
4. **不删除、不移动任何已有文件。** 新增只发生在 `07_新框架_v0/` 内，以及更新根目录 `00_资料说明.md`。
5. **每次提交前先更新根目录 `00_资料说明.md`**：第 1 节加/改 07 一行，第 2 节目录结构，第 7 节追加变更记录（日期、改了什么、谁做的），顶部“最后更新”日期。
6. 遇到不确定的地方：**停下来写成问题**列在汇报里，不要自己猜着扩范围。
7. 依赖尽量少：标准库 + `pytest`；确需第三方库（如 `httpx`、`tomli-w`）总数不超过 5 个，每个在 `pyproject.toml` 旁注明理由。
8. 单个源文件尽量不超过 400 行；函数有类型标注；所有读写文件显式 `encoding="utf-8"`；路径用 `pathlib`；**必须能在 Windows 上直接运行**（不依赖 bash 脚本）。

## 5. 文本生成的诚实红线（吸取旧管线教训）

旧管线曾出现“模板拼接的正文”“资料标签漏进正文”“句子整段重复”。因此：

- **正文只能来自真实模型调用。** 禁止用模板、拼接、占位句、随机选句来“生成”正文或冒充生成结果。
- `fake` 适配器**仅用于自动测试**，其输出必须明显标记（如以 `[FAKE]` 开头），不得写入任何 `projects/` 的正式正文目录。
- 模型调用失败/截断/拒绝时，如实记录状态；**不得用兜底模板补全**。
- 没有配置真实模型时，相关命令返回 `CONFIG_REQUIRED` 并说明缺什么，不假装成功。

## 6. 数据与文件约定

- 运行数据放 `07_新框架_v0/workspace/`（已加入 `.gitignore`，不上传）；示例/夹具放 `07_新框架_v0/fixtures/`。
- 密钥只读环境变量，**不写进任何文件**。
- 草稿版本**不可变**：只能新增版本，不能覆盖旧版本。“已接受”是指向某一版本的指针。
- 每次模型调用必须存下**完整输入快照**（实际发出的消息、上下文包、参数、模型名）和完整输出，保证可复现、可对照。

```
没做/有意推迟的：
需要用户决定的问题：
00_资料说明.md 已更新：是/否
```
