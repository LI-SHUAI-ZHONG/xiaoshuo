6. 不得使用项目配置或执行产物补足缺失事实。

### 3.2 不允许的推断

以下情况不得当作事实：

- 只因为出现“主角”标签，就认定某个具体人物是主角；
- 只因为出现“重要配角”，就认定存在具体重要配角；
- 只因为“孤光”没有被某一次检索命中，就断言孤光不存在；
- 只因为人物与某个剧情节点相连，就推断人物拥有某种动机；
- 只根据类型规则推断人物性格；
- 只根据网络节点推断人物姓名；
- 只根据项目产物中的人物字段反推原始资料；
- 只根据名称判断两个名字是同一人物。

### 3.3 结论状态

每项审查结果必须归入以下状态之一：

| 状态 | 定义 |
|---|---|
| 已证实 | 原始资料存在直接、可定位的证据 |
| 部分证实 | 有相关事实，但不足以支撑完整创作行为 |
| 资料存在但难以转写 | 有抽象设定，但不能转化为稳定的动作、语言或选择 |
| 资料冲突 | 不同原始资料对同一人物事实给出不一致信息 |
| 未发现 | 在成功完成的目标范围内没有命中 |
| 未确认 | 因路径、编码、命令中断或文件读取失败，不能判断是否存在 |
| 不适用 | 该维度不属于该角色类型，或没有适用场景 |

“未发现”和“未确认”必须严格区分。

1. 目标目录是否只是被移动或改名。
2. OneDrive、坚果云、Dropbox、NAS 等同步服务的回收站和版本历史。
3. Windows 文件历史记录或备份。
4. 右键上级目录，检查“以前的版本”。
5. 其他编辑器、Git 仓库、压缩包、备份目录、临时目录。

**使用 Windows File Recovery 的示例**

```cmd
winfr D: E:\Recovery /extensive /n \小说\*.md /n \小说\*.txt /n \小说\*.json /n \小说\*.jsonl /n \小说\*.csv /n \小说\*.py
```

```cmd

```

- `D:` 是源盘，`E:\Recovery` 是恢复目标。
- 目标盘不能是 `D:`。
- 需要以管理员身份运行终端。
- `/regular` 适用于近期删除、NTFS 状态较好的情况。
- `/extensive` 会进行更深入的扫描，但可能丢失原文件名和目录结构。
- 扫描结果通常会写入 `E:\Recovery\Recovery_<日期时间>`。
