# 08 框架与源文档

## 总判断

ACCOS是面向长期创作平台的模块化单体框架；旧11模块管道是资料组织/调度和历史正文产出路径；07新框架v0是独立的轻量写作实验CLI。三者不是同一条流水线的连续已验收版本。ACCOS的18节点是目标工作流规范，不是已经完成18个真实模型节点的运行日志。v0已把问题收敛到可以保留输入输出、人工接受和规则盲测的最小路径，但真实模型文学质量仍待验证。

证据：ACCOS README L3–5自称v0.1-skeleton、真实模型默认关闭；后续执行/进度.json L7–16给当前断点28与实施未测状态；07_新框架_v0/README L3与L65起给实现范围及fake测试限制；Codex总指令与里程碑.md L115要求记录冻结ACCOS、新建v0，L142将多章记忆/六大资料检索等放在真实模型验收之后。上述是设计与代码静态证据，冻结指令不能单独证明所有外部环境已冻结。

## 18节点的创作质量相关性

来源：后续执行/06_完整小说创作工作流.md L15–32，全量表解析18项。下表说明潜在作用和应观察的证据，不冒充已实现或已证明的效果。

|节点|直接质量作用|实际应验的产物与反例|
|---|---|---|
|N01灵感/澄清|避免模型猜方向|作者确认Brief；不能把聊天摘要变正式设定|
|N02类型/读者|决定承诺与预期|类型影响真正改变冲突和阅读体验；标签齐全不够|
|N03研究|增加事实可靠性与细节|可回读来源及适用边界；未检索不得称检索过|
|N04世界|使代价和规则稳定|规则可解释人物约束；背景百科不能挤满开场|
|N05人物|选择、声音和关系独立|欲望→选择→行动→后果；方法节点不是人物事实|
|N06全书/卷规划|因果与悬念分配|线索披露时间和角色可知信息分离|
|N07本章任务|让章节有目的|变化前后状态与下一场必要性，避免空动作|
|N08依赖预检|防错版/漏输入|冻结引用及缺项阻断；不能用“已加载”冒充“生效”|
|N09上下文|最接近资料进入正文的因果点|保存实际消息与排除理由；硬约束不静默截断|
|N10生成|产生可读正文|完整原始输出/终止原因；不以模板补全掩盖失败|
|N11审稿|发现硬错与叙事弱点|具体文本位置与读者体验证据；自评高分不够|
|N12修订|在局部问题上改善|版本差异及影响，有限轮次；避免为marker破坏语气|
|N13作者审阅|外部偏好校准|实际接受/退回；自动策略需与真人选择区分|
|N14接受/事实提交|维持正式文本身份|同版本完整草稿接受；测试正文不能入正式库|
|N15记忆/索引|保障下一章连续性|事实来源、候选状态和投影完成水位|
|N16下一章/全书复核|检验长期因果|后章真用前章接受状态；首章成功不能替代|
|N17定稿/出版|交付完整与顺序正确|版次/manifest；导出成功不能证明平台受欢迎|
|N18反馈/进化|在真实偏好上改进|记录选择及A/B结果；不足数据不宣称学习成功|

节点之间有明确质量依赖：N05/N07提供有后果的选择，N09决定模型实际看到什么，N10–N13检验文字是否成立，N14–N16阻止下一章遗忘。增加节点数量本身没有质量增益。旧管道的问题恰在“来源已绑定”和“正文自然实现”之间，新规范已写出ReadReceipt/实际消息/作者选择等桥梁，但需要实证执行。

## 原文已经包含的防过度复杂化要求

《创作搭建.txt》L12833–12847直言平台设计庞大，应确定真核心、延后项和第一版范围；L12883起提出架构收缩/核心冻结，担心文件模块越来越多但迟迟无法创作；L53881起又要求从MVP稳定运行逐步扩展。不能只引用庞大蓝图而忽略这些收缩要求。

对本项目的实际含义：保留不可变草稿、完整输入快照、作者接受、失败可恢复和小范围盲测作为核心；六大资料先提供可回读且按场景选择的少量候选；复杂网络、自动进化、出版生态等只有在作者写作的可观察改善出现后才扩展。v0的模块少不是退步，它把文学效果这一尚未回答的问题单独暴露出来。也不能因此删掉ACCOS或旧资料：本轮不修改源，后续可保留为设计/证据资产。

## 仍缺的关键证据

当前能回答“东西在哪里、规范想做什么、部分实现是什么、历史哪里反复出问题”；不能回答“哪套框架已稳定达到高质量商业小说”。缺真实模型在同场景上的可复核输入输出、作者盲评、多场景重复、下一章状态继承，以及修订成本。下一次验证应以这些读者/作者结果为验收，而不是再增加资料条数、节点数或通过字样。
