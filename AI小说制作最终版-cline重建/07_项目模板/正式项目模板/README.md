# 正式项目模板

复制本目录创建新小说项目。模板只提供结构和空状态，不提供任何小说事实。

## 目录职责

- `项目元数据.json`：项目身份、状态和锁定事实入口。
- `创建参数.yaml`：初始化时确认的用户输入快照，记录题材、类型、篇幅、平台和写作目标。
- `项目快照.json`：当前可恢复状态，包括人物、世界、章节和连续性信息。
- `项目状态模型与连续性契约.json`：项目状态字段、状态转换、回滚和检查边界；它是快照的解释契约，不是小说事实。
- `版本记录.json`：重大规划、正文保存和修订的追加记录。
- `设定/`：启动参数、题材定位、故事核心、世界观、人物、关系、时间线和伏笔。
- `规划/`：故事核心、卷纲、章纲和场景规划。
- `正文/`：正式正文，按 `卷NN/第NNN章_标题.md` 建立文件。
- `修订记录/`：正文修订稿和修订说明，不覆盖正式正文。
- `检查报告/`：一致性、质量和阻塞项报告。

初始化后自动读取并保存元数据；Cline 自主完成普通参数、设计和资料组合，不得把自主决策伪装成用户明确事实。

## 状态字段分层

- 已确定：写入设定文件并在元数据中登记来源。
- 待确认：写入 `pending_questions` 或设定文件的“待确认”区，仅作记录，不阻断普通生产。
- 可变：写入候选区，不能作为正文硬约束。
- 禁止擅自修改：写入 `locked_facts`，只有与用户新要求发生不可调和冲突时才阻塞；正常生产中追加版本记录。

## 自动运行

- 状态按 `AUTO_INIT -> AUTO_DESIGN -> AUTO_GENERATE -> AUTO_SAVE -> AUTO_CONTINUE` 推进。
- 每轮保存正文、快照、版本记录、下一步位置和资料来源；保存失败自动重试。
- 正式正文使用不存在的章节路径；已存在章节只用于恢复状态，不覆盖、不重复生成。
- `WAIT_USER`、`WAIT_CONFIRM`、`PAUSED_BY_GATE` 可以保留为记录值，但不能阻断普通任务；真正阻塞统一使用 `BLOCKED`。

## 状态更新边界

每一轮剧情都先记录问题、目标、障碍、行动、后果和新问题，再更新角色认知、世界反应、关系、资源、地点与线索。角色行动必须受当前认知、需求、能力、性格、立场和资源约束；允许犯错、犹豫、误解、隐瞒、反转或产生新目标，但每次变化都要写入版本记录和检查报告。需要撤销时只回滚当前轮，不覆盖历史版本。
