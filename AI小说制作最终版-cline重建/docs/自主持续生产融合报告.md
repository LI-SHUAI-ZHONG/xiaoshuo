# 自主持续生产融合报告

## 改造范围

本轮只调整用户确认、自动决策、自动推进、保存恢复和防重复生产方式，未重新设计小说资料体系、未重新提取资料、未引入外部资料，也未改变资料索引架构。

## 已关闭的普通人工确认

- 项目初始化、正式模板使用和项目参数保存改为自动执行。
- 项目快照读取、资料选择与组合、综合设计、类型适配、篇幅/风格方案、人物安排、卷章规划和下一项任务由 Cline 自主决定并记录。
- 设计完成、章节保存、状态更新、版本记录更新、进入下一章和正常恢复不再等待用户批准。
- `WAIT_USER`、`WAIT_CONFIRM`、`PAUSED_BY_GATE` 保留为历史或运行记录值，不再作为普通生产门禁。

## 保留的真正阻塞条件

仅在项目身份不唯一、目标路径归属不明、覆盖或删除风险、用户硬要求与锁定设定不可调和冲突、关键资料或核心文件损坏/丢失、重大核心设定完全无依据、自动重试仍失败、或存在不可逆写入风险时进入 `BLOCKED`。阻塞时不修改错误内容、不编造结果，并只记录唯一待处理事项。

## 状态机与决策

普通持续链路为：

`AUTO_INIT -> AUTO_DESIGN -> AUTO_GENERATE -> AUTO_SAVE -> AUTO_CONTINUE -> ...`

达到用户目标、规划目标、篇幅/章节目标、完稿标记或真正阻塞时结束。普通缺失按“用户明确内容 -> 锁定设定 -> 项目既有内容 -> 工作区相关资料 -> 类型/风格/篇幅规则 -> Cline 自主设计”补足，并区分 `derived` 与 `cline_decided`，写入 `decision_log` 或运行记录。

## 保存、恢复与防重复

正式正文先检查目标路径并写入临时文件，再原子替换；保存失败最多自动重试三次，仍失败才阻塞。每章保存正文、编号、标题、快照、当前进度、最后完成章节、下一章节编号、版本记录、连续性状态和本轮资料来源。已有章节不覆盖、不重复生成；发现正文已存在但状态未更新时先按实际文件恢复状态，再定位下一个未完成编号。分析和检查结果始终写入正文之外。

初始化脚本 `工具/新建小说项目.ps1` 已补齐实际原子保存实现：项目元数据、创建参数、启动参数、项目快照、版本记录和初始检查报告均通过同目录临时文件写入，并在失败时最多重试三次。目标文件已存在时使用有效的同目录备份路径完成 `File.Replace`，随后清理备份，避免跨卷临时项目初始化时因空备份参数失败。`-Mode continuous` 写入 `autonomous_continuous`，`-Mode one-shot` 写入 `one_shot`，避免一次性短篇/样稿被误标为持续项目。

## 仍存在的限制

当前工作区主要由规则、模板和 PowerShell 检查/初始化脚本组成，没有独立的正文生成引擎、章节保存执行器或后台常驻进程。因此“持续运行”由 Cline 按协议在一次任务中自动推进，并通过快照在后续调用恢复；系统不会脱离 Cline 自行在操作系统后台无限生成。外部资料仍禁止作为运行时来源，核心资料损坏或项目身份不明仍必须阻塞。
