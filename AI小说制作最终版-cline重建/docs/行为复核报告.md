## 4. 模拟任务路径

模拟请求：创建新长篇项目，完成题材定位、故事核心、主角档案和前三章大纲。

预期调用顺序：

1. 读取 README、总规则和项目初始化流程。
2. 收集并确认项目名称、项目 ID、项目路径、题材、类型、读者和硬要求。
3. 复制正式项目模板并生成初始状态文件，不写入正文事实。
4. 按状态机依次推进 `TYPE_SELECTION`、`STORY_BIBLE`、`CHARACTER_DESIGN`、`CHAPTER_OUTLINE`。
5. 每个状态记录来源、产物、未解决项、检查结果和下一状态。
6. 未经用户确认的候选内容保持待确认，不写入锁定设定。

该路径与现有模板和协议一致。本轮使用 `工具/新建小说项目.ps1` 创建了临时模拟项目，传入科幻、星际冒险、长篇、网络文学和成年读者参数；脚本成功生成项目元数据、创建参数、启动参数、正式模板目录和初始检查入口。验证完成后已删除 `06_测试验证/入口模拟项目`，未污染正式项目模板或外部参考目录。

### 4.1 初始化器实测

- 首次运行发现模板目录和新增目录的 Unicode 码点映射错误，脚本停止并未覆盖目标目录。
- 修正 `工具/新建小说项目.ps1` 的模板目录、修订记录和检查报告目录名称后重新运行成功。
- 实测输出目录包含：`设定`、`规划`、`正文`、`修订记录`、`检查报告`。
- 实测生成并校验：`项目元数据.json`、`创建参数.yaml`、`设定/启动参数.md`。
- 目标目录已存在时脚本仍按设计拒绝覆盖。

## 5. 异常与停止规则

- 目标项目已存在：`WAIT_USER`，请求新路径，不覆盖。
- 项目无法唯一定位：`WAIT_USER`，不跨项目读取。
- 锁定设定发生硬冲突：记录冲突并 `WAIT_USER`。
- 外部资料或工具不可用：保留 `partial` 或 `blocked_not_available`，说明受影响模块。
- 用户明确要求停止或一次性任务已完成：停止继续调用。

## 6. 未覆盖范围与风险

1. 本轮包含初始化器的真实文件级模拟，但仍不替代真实长篇多轮续写压力测试。
2. 状态机目前由 Markdown、JSON 和 Cline 协议共同约束，没有独立自动执行器。
3. YAML 索引仍需人工维护；新增或迁移核心文件后，应同步更新索引并重新运行检查器。
4. 原始资料中已标记的编码风险仍需在实际调用时按索引摘要优先读取，原文不可读时不得静默修复。

静态检查通过，初始化、持续生产、恢复和异常停止的规则链条闭合；当前系统满足继续使用的最低验收条件。后续真实项目应以模板复制、项目元数据确认和每轮快照保存作为强制入口。
