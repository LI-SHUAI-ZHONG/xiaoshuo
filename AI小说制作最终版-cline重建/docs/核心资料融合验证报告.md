# 核心资料融合验证报告

## 1. 验证目的

确认原始能力资料、类型资料、静态/动态/锚点网络、一次性流程和持续生产协议已经形成可解释的主流程，而不是重复堆叠或互相争夺事实决定权。

## 2. 融合关系

| 资料层 | 主职责 | 融合后的承载位置 | 处理结论 |
|---|---|---|---|
| 能力资料 | 提供创作能力节点和方法 | `00_资料索引/多维资料索引.yaml`、`docs/原资料功能分析.md` | 保留来源，转为按任务调取 |
| 类型资料 | 提供题材方向、读者期待和边界 | `MOD-TYPE`、类型分析相关流程 | 只约束方向，不直接生成具体事实 |
| 静态网络 | 提供稳定依赖和模块连接 | `MOD-STATIC`、`01_系统核心/资料组合机制.md` | 用于前置关系和结构检查 |
| 动态网络 | 提供条件、冲突、状态和传播 | `MOD-DYNAMIC`、持续生产状态机 | 用于剧情推进和连续性维护 |
| 锚点网络 | 提供场景、动作和表达落点 | `MOD-ANCHOR`、综合设计模板 | 用于把抽象设定转为可写内容 |
| 一次性流程 | 提供单次生产顺序 | `02_生产流程`、一次性调用协议 | 保留为短篇/样稿兼容入口 |
| 运行状态资料 | 提供可恢复思想 | 项目快照、版本记录、状态契约 | 重写后纳入持续生产，不复制旧状态格式 |

## 3. 冲突处理验证

1. 资料索引负责“找什么”和“为什么调用”，不负责替项目决定未确认事实。
2. 类型模块只能提供类型边界和读者期待；与项目锁定设定冲突时，项目设定优先。
3. 静态关系用于稳定约束，动态关系用于状态变化，锚点用于表达落地，三者不得互相替代。
4. 一次性流程与持续流程并存，但入口职责已区分：长篇持续项目进入 `07_项目模板/正式项目模板`，独立短篇或样稿才使用一次性入口。
5. 参考资料没有原样复制到主系统；原始文件继续保留且只读。

## 4. 可执行性检查

- Cline 可先读取 `README.md`、`.clinerules/00-总规则.md` 和 `00_资料索引/多维资料索引.yaml`，再按任务读取对应模块。
- 生产前有需求解析、资料选择、冲突/缺失识别和统一综合步骤。
- 持续项目有项目元数据、项目快照、状态契约、版本记录、修订记录和检查报告入口。
- 新项目入口会拒绝覆盖已有目标目录，并写入启动参数与项目元数据。
- 检查器实测通过：`PARSE_ERRORS=0`、`INDEXED_PATHS=9`、`ERRORS=0`、`WARNINGS=0`。

## 5. 未覆盖范围

- 当前没有自动语义检索器，模块选择仍由 Cline 按索引字段和任务状态判断。
- 当前没有自动状态机执行器，快照更新、版本记录和连续性检查仍需按协议执行。
- 原始 `08_原始资料/类型系统.txt` 的编码风险仍保留并已记录，不能在未确认内容前擅自重写。

## 6. 结论

核心资料已经完成“来源保留、职责拆分、按需调用、统一综合、状态落盘”的融合。当前系统适合进入真实项目试运行；真实长篇生产仍应在每轮保存后执行状态契约和连续性检查。
