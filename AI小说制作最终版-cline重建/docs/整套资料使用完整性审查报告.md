# 整套资料使用完整性审查报告

## 结论

审查范围为 `D:\AI小说制作最终版-cline重建` 当前工作区，原始资料范围为 `08_原始资料` 的 9 份文件。结论是：**资料已经全部登记，但没有全部、完整地进入创作使用链**。

当前系统完成的是“资料登记、职责说明、局部证据抽取、模块路由和项目样例验证”，尚未完成稳定的“条目调用 -> 中间设计 -> 综合决策 -> 章节执行 -> 正文定位证据 -> 验证”闭环。索引契约规定的完整链为：

`index_mapping -> selected_evidence -> synthesis_decision -> design -> text -> verification`

按这个标准，当前真正的主要缺口不是“文件不存在”，而是：

1. 大型原始资料仍主要以 TXT 形式存在，模块级登记多于条目级调用。
2. 规范化资料层只有 7 条模块/网络规则记录，不能覆盖 9 份原始资料的全部真实子项。
3. `selected` 经常只表示“模块被选中”，不表示具体证据已经进入设计；现有 Verify 快照中的 `matched_dimensions` 全部为空就是直接证据。
4. 既有《诡异屋》产物大部分是正文之后的回溯重建，不能证明生成前资料曾经影响正文。
5. 静态、动态、锚点和类型连接虽然已有派生索引，但“可检索”仍没有转化为某个具体项目的采用决策。

## 判定口径

| 状态 | 含义 |
|---|---|
| 完整进入 | 有具体来源证据、综合决策、中间设计、正文/章节定位和验证记录，且不是事后补建 |
| 部分进入 | 已有模块调用或项目结果，但缺条目级证据、生成前交接、正文定位或验证中的一项以上 |
| 未完整进入 | 已登记或可解析，但没有形成可证明的项目设计输入，或被结构/证据门阻断 |
| 正常不进入正文 | 索引、迁移映射、生成指标、审计报告、旧运行状态等只负责路由/验证，本来不应成为故事事实 |

这里的“进入使用”不是把资料全文复制到提示词，也不是在 `source_trace` 中写上模块编号。只有资料对当前设计产生了可定位、可验证的影响，才算完成进入。

## 现有项目与测试的真实证明力

### 《诡异屋》项目

`D:\AI小说制作最终版-cline重建\05_正文\诡异屋` 只能作为回归夹具。其项目快照和调用审计已经明确：

- `source_status=partial`；
- `design_artifacts.status=retrospective_reconstruction_partial`；
- `MOD-CONNECTION`、`MOD-STATIC`、`MOD-EXECUTION` 为 `called_not_transformed`；
- `CAP-GOLDEN-THREE`、`CAP-OPENING-ATTRACTION`、`CAP-CHARACTER-CHAIN` 原生成时缺少条目级调用证据；
- `chapter_execution_manifest.json` 的状态是 `retrospective_regression_manifest`。

因此两章正文中出现了类型效果、动态后果和锚点表达，只能证明“这些内容后来被补建并能解释正文”，不能证明资料在生成前完整进入创作。

### `06_测试验证`

模拟调用记录完整覆盖七个宏模块，且明确本次只验证前三章大纲、不生成正文。这能证明流程的选模块和综合输出格式，但不能证明九份原始资料的条目级覆盖，也不能证明正文影响链。

### 网络三跳验证

当前网络脚本生成 711 条 A→B→C 候选链，节点连接关系全部机械成立；严格词集合验证为 0，宽松子串验证只有 8 条 BC-only，双边通过为 0；锚点增强后 8 条 AB 边均为 `not_found`。这证明候选链生成和状态门在工作，也证明目前没有一条链能作为完整状态连续性事实进入创作。

## 最终缺口清单

### 必须补齐后才能称为“资料完整进入创作”

1. 为 `资料库.txt` 建立条目级索引，至少包含板块/子项、定义、调用条件、指令、检查项、来源行号和证据等级；先处理 5,193 个占位匹配，不把空字段转成规则。
2. 为 `类型系统.txt` 建立按类型、风格、读者、篇幅、适配和冲突的可检索证据层；处理编码/历史路径风险，未确认内容保持 candidate。
3. 为 `类型连接.txt` 建立组合记录、冲突记录、空块和模板记录的状态分类；每次项目运行保存被选组合及未选原因。
4. 将选中的静态连接绑定到具体故事对象、设定字段和章节结构；不只保存“调用了静态网络”。
5. 将动态连接绑定到具体行动、条件、效果、人物状态、事件证据和状态连续性检查；当前三跳候选不能绕过 AB/BC 门。
6. 将锚点绑定到具体场景目标、人物状态、触发条件、正文位置和 source_ref；不能仅凭名称或抽象关键词补配。
7. 把 `MOD-EXECUTION` 的阶段顺序转换为生成前 `chapter_execution_manifest`，并在正文保存前验证来源到正文的定位链；禁止使用回溯清单冒充前置证据。
8. 让每轮运行生成结构化的 `selected_evidence`、`synthesis_decision`、`design`、`text`、`verification` 交接，而不是只写宏模块 `source_trace`。

### 已确认是正常状态，不应强行补入正文

- `运行状态.json`：旧执行器状态参考。
- `dynamic_id_migration.json`：旧编号迁移审计。
- `network_generation_metrics.json`：数量和冲突元数据。
- `node_aliases.json`：未决别名候选。
- `阶段状态/资料网络剧情覆盖.json`及各类审计报告：覆盖门和证据，不是故事事实。
- `template`、`fixture`、`pending`、`needs_review` 和 `unconfirmed` 记录：只能作为候选/阻断说明。
