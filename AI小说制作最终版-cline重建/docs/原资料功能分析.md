# 原资料功能分析

分析范围：当前工作区 9 个文件，以及 `D:\参考\原始资料` 的目录、核心索引、创作能力索引、类型能力映射、检索排序规则、创作流程记录和代表性验证规则。参考目录已确认可读，未修改其中任何文件。

## 结论：原系统是什么

当前资料不是提示词集合，也不是项目管理资料。它是一套“创作能力节点 + 静态依赖 + 动态传播 + 状态锚点 + 类型适配 + 调用映射”的小说生产运行时。其价值不在单个文件，而在多种资料共同把抽象创作需求转换为候选结构、关系、状态变化和表达结果。

## 参考资料提炼出的机制

1. `创作能力索引.json` 提供 85 个能力、同义词、适用阶段和证据引用，适合作为能力检索层，不适合作为正文事实层。
2. `创作资料分块索引.json` 是语义证据级索引，约 303,208 条；它证明资料应按语义片段精准调取，而不是全量复制。
3. `类型能力映射.json` 明确类型只提供能力需求和检索范围，不决定人物性格或剧情事实；该原则进入系统总规则。
4. `检索排序规则.json` 提供关键词、概念、人物、地点、事件、类型、风格、关系距离、状态和时间相关性排序，并对最近使用、fixture、pending 和待恢复规则降权或排除。
5. `全系统检索流程.md` 提供多维检索顺序：项目配置、目标、人物状态、地点、物品、关系、信息、感知、钩子、类型、概念、连接、动态规则、冲突、伏笔和因果；改写为一次性生产中的资料调取阶段。
6. `人物核心调用限制.md` 说明人物资料应返回多个候选和排序理由，而不是擅自选定唯一行动；这适用于设计阶段的方案综合。
7. 核心资料目录和结构定义强调稳定 ID、来源、版本、状态、合并策略和验证信息；仅抽取为主系统索引字段，不复制巨型核心库。

## 联合调用关系

`资料库`提出创作能力；`类型系统/类型连接`筛选和约束方向；`静态网络`建立概念依赖；`动态网络`安排因果与状态传播；`锚点网络`把结果落到场景和表达；`执行正文`规定一次性设计顺序；`索引调用映射`提供旧系统的历史调用线索。它们不能被机械拼接，必须先形成“功能结果”，再综合成单一小说方案。

## 不建立的机制

正文生成后的章节检查、审稿、修订、续写、循环状态管理和普通项目管理不属于本系统运行模式。必要的冲突处理只发生在正文生成前的综合设计阶段。
