# 小说唯一入口协议

本文件是本工作区的入口规则。它与根目录 `README.md` 配套：README 负责说明，本文负责执行顺序。

## 触发条件

1. 先检查用户本轮请求的原始文本是否包含连续的“小说”二字。
2. 包含“小说”时，必须进入本协议；不得直接跳到写正文、修改文件或调用原始资料。
3. 不包含“小说”时，不把请求当作本系统的完整小说制作启动请求；可以正常回答普通问题，但不得擅自读取本工作区资料或写入小说项目。
4. “小说”只是入口触发词，不代表用户已经确认题材、类型、风格、篇幅、项目或章节目标。

## 入口执行顺序

进入本协议后，按以下顺序执行，并在回复中记录当前状态：

1. 读取 `.clinerules/00-总规则.md`、根目录 `README.md`、`00_资料索引/多维资料索引.yaml`。
2. 判断任务是新建项目、已有项目继续/恢复、续写章节、修改设定、规划设计、修订，还是一致性检查。
3. 判断项目身份：扫描 `05_正文/` 下的项目元数据；只有找到唯一匹配项目时才能跨文件读取该项目。项目不唯一或路径归属不明，进入 `BLOCKED` 并只说明这个阻塞原因。
4. 新建项目执行“类型 -> 风格 -> 篇幅/规模”确认链；已有项目先读取项目元数据、启动参数、项目快照、版本记录、最近正式章节、当前规划和检查报告，再处理任务。
5. 按最终确认的类型、风格、篇幅和任务目标选择已登记资料。每个调用必须记录 `source_trace`、调用依据、用途和未调用原因。
6. 需要创作时按 `AUTO_INIT -> AUTO_DESIGN -> AUTO_GENERATE -> AUTO_SAVE -> AUTO_CONTINUE` 推进；已有项目恢复使用 `RESUME`，不要凭记忆续写。
7. 正文生成前必须有章节/场景设计和连续性检查；生成后保存正文、状态更新、版本记录和验证报告。

## 新建项目确认链

- 从索引和已登记资料提取可识别的题材、类型候选，并展示给用户。
- 给出一个类型首推荐及推荐依据，同时允许组合或自定义类型。
- 根据最终类型给出一个风格首推荐及推荐依据，同时允许改选或自定义风格。
- 根据最终类型和风格给出一个篇幅/规模首推荐及推荐依据，同时允许改选或自定义要求。
- 用户确认前的内容只能标记为 `candidate`、`derived` 或 `cline_decided`，不得写成用户事实。
- 用户确认后，把最终值写入项目元数据、启动参数和项目快照，并使其影响资料调用、故事设计、结构、节奏和正文表达。

## 已有项目和保存边界

- 续写必须从项目快照和最近正式章节恢复，定位下一个未完成编号，不覆盖既有正文。
- 修改人物、世界观或时间线时，先检查锁定设定与现有时间线，再生成新版本或修订产物。
- 项目身份冲突、目标路径不明、覆盖风险、核心文件损坏、不可调和硬冲突或工具重试失败时才进入 `BLOCKED`。
- 普通缺失内容继续处理，但必须记录为 `partial`、`derived` 或 `blocked_not_available`，不能静默补成事实。
- 工作区外路径、未登记资料和历史报告中的外部绝对路径不得作为当前运行资料源。

## 最低回复契约

每次入口处理至少明确返回：

- `status`：当前状态或唯一阻塞原因；
- `task_type`：任务分类；
- `project`：新建、唯一已有项目或项目身份阻塞；
- `selected_sources`：实际调用的登记资料及用途；
- `decisions`：用户确认值与候选值的区分；
- `outputs`：本轮生成或修改的产物；
- `unresolved`：未解决问题、资料缺口和后续状态。
