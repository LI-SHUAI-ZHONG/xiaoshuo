# 持续型资料驱动 AI 小说制作系统规则

本工作区是一个可恢复、可持续推进的小说制作系统。一次用户请求只推进当前可完成的状态，不代表作品流程结束。正式项目必须保存项目元数据、快照、版本记录、规划、正文和检查报告。

入口优先级：先执行 `.clinerules/01-小说唯一入口.md`，再执行本文件的通用规则；根目录 `README.md` 是入口说明和目录索引，不替代入口协议。

## Cline 角色与状态边界

- 小说入口硬触发：用户请求文本包含“小说”两个字时，必须进入小说制作入口；不含“小说”的普通自然语言请求不得被当作本系统的完整小说制作启动请求。入口先区分新建项目与已有项目任务，再按当前任务进入 `INIT`、`AUTO_INIT`、`AUTO_DESIGN`、`AUTO_GENERATE`、`AUTO_SAVE`、`AUTO_CONTINUE`、`RESUME` 或 `BLOCKED`。
- 新项目入口固定完成类型候选展示与选择/组合/自定义、风格首推荐与选择/自定义、篇幅或规模首推荐与选择/自定义，并保存最终确认结果；类型、风格和篇幅/规模必须作为后续资料调用、设计、结构、规划和正文表达的输入。
- 已有项目的继续、恢复、续写、章节处理、设定修改、一致性检查和其他小说任务同样从该入口进入；用户无需查找项目目录、章节文件、索引或保存位置。
- Cline 负责项目初始化、状态恢复、资料检索、规划、场景/章节生产、修订和检查。
- 先判断请求属于 `INIT`、`AUTO_INIT`、`AUTO_DESIGN`、`AUTO_GENERATE`、`AUTO_SAVE`、`AUTO_CONTINUE`、`RESUME` 或 `BLOCKED`；旧阶段名可以写入运行记录，但不得作为普通任务的确认门禁。
- 状态机决定下一步，不能把一次阶段任务擅自扩展为全书完稿。
- 认知判断、候选资料和推荐结果必须标注来源层级；对不影响继续生产的普通缺失内容，Cline 可依据优先级自主补充并记录为 `derived` 或 `cline_decided`，不得伪装成用户明确事实。
- 当前项目的锁定设定、时间线、人物状态、资源状态和已发布正文优先于通用资料。

## 资料与网络原则

- 先读取项目配置、当前快照、最近正式章节和本次卷/章/场景目标，再按 `00_资料索引/多维资料索引.yaml` 选择资料。
- 每轮创作必须先运行 `工具/运行资料闭环.ps1 -Mode Plan`（审计或恢复可用 `Audit`/`Verify`），其输出的 `docs/资料闭环-*.json` 是本轮资料选择、依赖边和设计交接的机器可读事实；不得以“已读取文件”代替执行计划。
- 当前运行只允许读取工作区内已登记的资料；外部参考目录和工作区外路径不属于运行时资料源，禁止 Cline 自动读取、调用或写入。历史报告中的外部路径仅作审计依据，不得作为当前 `source_trace`。工作区内已登记资料缺失时必须显式返回 `partial` 或 `blocked_not_available`，禁止静默推断。
- 统一网络调用只允许使用已登记的 L0 核心模块和 L1 受限兼容运行时；L2 仅为候选参考，L3 禁止调用。动态状态变化仅允许已登记的 46 条兼容规则。
- 资料用于方法、约束、候选和可追溯证据，不直接冒充小说事实。
- 根目录启动只读取本规则、README 和索引说明；原始资料按索引的 `call_when` 与 `read_mode` 按需读取。
- 对大于 1 MB 的资料先读取索引、标题或命中片段；只有当前任务需要深入时才读取完整文件，不得因启动而全量读取。
- 同一资料在同一任务中只读取一次；后续使用通过 `source_trace` 引用，避免重复加载。
- 未登记或无法识别的资料先记录为 `unknown_source`，不得直接作为事实或规则使用；确认用途后再更新索引。
- 资料冲突必须在正文生成前记录并选择唯一方案；缺失资料必须标记 `partial` 或 `blocked_not_available`。
- 项目快照的连续性字段遵守 `07_项目模板/正式项目模板/项目状态模型与连续性契约.json`；剧情轮次必须记录问题、目标、障碍、行动、后果、新信息、状态变化和新问题，角色认知与世界反应必须随正文保存同步更新。

## 文件操作与输出原则

- 在 `STORY_BIBLE` 阶段综合题材、核心、世界观、冲突和开篇方向；在后续阶段只读取与当前目标相关的资料。
- 正文前必须完成当前章节或场景所需的设计，不要求一次完成整部小说。
- 任何未确认的用户偏好只能作为候选，不能伪装成事实。
- 正文必须依据当前项目快照、章节/场景设计和状态检查结果生成。
- 正文生成后保存 `chapter_text` 与 `chapter_state`，更新快照和版本记录；后续可通过 `RESUME` 恢复。
- `synthesis_contract.handoff_chain` 必须形成 `task_context -> evidence_bundle -> synthesis -> chapter_design -> execution_manifest -> chapter_text -> state_update -> verification`；缺少任一交接证据时只能标记 `partial`，不能宣称资料已产生正文影响。
- 一次性模式仅在独立短篇或样稿正文输出并完成检查后结束；持续模式按项目目标自动推进，不因轮次结束而等待确认。决策优先级为用户明确要求、锁定设定、项目既有内容、工作区相关资料、类型/风格/篇幅规则、Cline 自主设计；多个合理方案选择依据最充分且最利于持续生产者并写入 `decision_log`。
- 修改文件前先读取；重大改动写入项目版本记录或 `docs/资料改造记录.md`。
- 不覆盖既有正文；修订生成新版本或进入修订目录。
- 输出先说明状态判断、读取的项目资料、资料调用状态，再输出本次产物和未解决问题。
- 正文与分析、检查结果分开保存，不在正文文件中混入过程说明。
- 当前任务建立已读集合；同一文件只读取一次，后续通过 `source_trace` 引用。
- 普通 `WAIT_USER`、`WAIT_CONFIRM`、`PAUSED_BY_GATE` 只能作为历史/记录状态，不能阻断正常生产；仅本文件列明的身份、路径、覆盖、损坏、硬冲突、重大无依据设定、工具失败或不可逆风险进入 `BLOCKED` 并暂停。
- 每次产物必须先写临时文件并原子替换正式文件，保存失败自动重试；正式章节存在时只定位下一个未完成编号，严禁覆盖或重复生产。
- 不同小说项目必须先按项目元数据确认项目根目录；找不到唯一项目时先提问，不跨项目读取正文或设定。
- 仅以下情况进入 `BLOCKED`：项目身份不唯一、目标路径归属不明、覆盖或删除风险、用户硬要求与锁定设定不可调和冲突、关键资料/核心文件损坏或丢失、重大核心设定完全无依据、工具自动重试仍失败或不可逆写入风险。其余 `pending`、推荐、选择、保存、下一章和阶段批准均只记录并继续。
- 持续流程细节见 `01_系统核心/持续生产状态机.md`、`03_调用协议/持续小说生产指令.md` 和 `04_综合设计/项目状态与检查接口.md`。
