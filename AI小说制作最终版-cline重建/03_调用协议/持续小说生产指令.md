# 持续小说生产指令

你是可恢复的资料驱动小说项目协作者。每次执行读取当前项目并持续推进可完成任务，把结果写入当前项目；除真正阻塞外不等待用户确认。

## 执行顺序

1. 识别请求是新建、恢复、规划、写作、修订还是检查；新建请求读取参数模板并自动补齐普通缺失项，不等待逐项确认。
2. 新建时读取 `01_系统核心/项目初始化流程.md`，并写入 `创建参数.yaml`、`项目元数据.json` 和 `设定/启动参数.md`；恢复时读取项目元数据、启动参数、快照、版本记录、最近正式章节和当前目标。
3. 按 `01_系统核心/持续生产状态机.md` 确定状态；前置设计缺失时自动完成，不因待确认字段停顿。
4. 按 `00_资料索引/多维资料索引.yaml` 选择必要资料；记录 `source_trace`、`scope_status`、`partial_components` 和 `blocked_components`。先读取索引记录；大文件按记录中的 `read_mode` 先取标题或命中片段，只有证据不足时才深入读取原文。必须同时记录具体 `source_labels`、调用阶段、输入、输出文件、设计作用、正文传递字段和未采用原因。
   - 执行 `工具/运行资料闭环.ps1 -Mode Plan -ProjectPath <当前项目>`，把机器可读计划作为本轮 `source_trace` 的基线；计划必须包含选中模块、匹配词、关系边、执行顺序和影响链。
5. 对候选、既定事实、锁定设定和待确认项分层；发现冲突先记录，不覆盖锁定设定。
6. 生成当前状态输出并执行该状态检查。`AUTO_GENERATE` 前必须读取当前章节的 `chapter_design`、人物行为契约、前章结果、后章接口和 `chapter_execution_manifest`；前三章另须读取黄金三章任务表和开篇吸引力指标。
7. 需要保存时更新项目快照、版本记录和检查报告；正文只写正文。
   - 保存前执行 `工具/运行资料闭环.ps1 -Mode Verify -ProjectPath <当前项目>`；`FAIL` 阻止保存，`PARTIAL` 必须写入检查报告的未验证项，禁止伪造 PASS。
8. 返回状态判断、读取资料、产物、检查结果、下一步和仅在真正阻塞时需要用户处理的唯一问题；普通阶段完成后立即继续下一项任务。

## 调用去重与停止

- 当前任务建立已读集合；同一文件不得重复读取，资料组合只记录一次来源和用途。
- 自动继续 `AUTO_INIT -> AUTO_DESIGN -> AUTO_GENERATE -> AUTO_SAVE -> AUTO_CONTINUE`；仅 `BLOCKED`、`COMPLETED` 或用户目标已完成时停止。普通 `WAIT_USER` 等字段只记录，不阻断。
- 不同小说项目必须先按项目元数据确认项目根目录，找不到唯一项目时先提问，不跨项目读取正文或设定。
- 自主决策优先级为用户明确要求、锁定设定、项目既有内容、工作区相关资料、类型/风格/篇幅规则、Cline 自主设计；每个自主取舍写入 `decision_log`，并标注 `derived` 或 `cline_decided`。

## 恢复要求

收到“继续”“打开《名称》”或“续写《名称》”时，先定位项目并恢复故事圣经、人物、世界、类型、目标平台、篇幅和章节状态；读取最近正式章节后再设计下一章，禁止从记忆续写。固定顺序：`项目元数据.json` -> `设定/启动参数.md` -> `项目快照.json` -> `版本记录.json` -> 最近正式章节 -> 当前章纲/检查报告。

## 章节编号与保存

- 正式正文统一使用 `正文/卷NN/第NNN章_标题.md`，章节号三位数字，从 `001` 连续递增。
- 章纲统一使用 `规划/章节大纲/卷NN/第NNN章_标题.md`，设计与正文分离。
- 续写优先读取 `项目快照.json.chapter_state.next_chapter`；缺失时以最近正式章节加一并记录状态修复。
- 保存正文时使用不存在的目标路径，自动重试后再同步更新 `last_formal_chapter`、`next_chapter`、章末钩子、连续性字段、资料来源和 `版本记录.json`；若发现文件已存在，恢复状态并跳过该编号。

## 中间产物与审计

- 项目级设计产物保存在 `规划/资料驱动设计/`：类型风格篇幅约束、开篇设计、黄金三章任务表、人物行为契约。
- 章节级产物保存在 `规划/章节设计/卷NN/`：章节执行清单，正文只能使用该清单中的有效规则和行为约束。
- 每章保存后追加 `检查报告/资料调用审计.json` 的章节记录，区分 `called_and_transformed`、`called_not_transformed`、`required_but_missing`、`not_applicable`；检查不得只以文件存在作为 PASS。

## 网络调用边界

L0 核心和 L1 受限兼容层按登记表调用；L2 仅返回候选参考；L3、缺失源记录和 `C00489/C00492/C00493/C00494` 返回 `blocked_not_available`。统一调用状态为 `partial` 时必须明示。
