# 持续生产状态机

## 目的

把用户请求映射到最小可完成阶段，并让项目可以中断、保存和恢复。当前状态定义以本文件、`03_调用协议/持续小说生产指令.md` 和 `04_综合设计/项目状态与检查接口.md` 为准；历史参考目录不属于运行时依赖。

## 状态顺序

`INIT -> AUTO_INIT -> AUTO_DESIGN -> AUTO_GENERATE -> AUTO_SAVE -> AUTO_CONTINUE -> ... -> COMPLETED`

`RESUME -> AUTO_CONTINUE`。恢复后必须读取项目快照、人物/世界资料、类型、章节状态和最近正式章节；同时检查资料调用审计和结构化中间产物。若开篇任务表、人物行为契约或当前章节执行清单缺失，必须先进入 `AUTO_DESIGN`，不能直接写正文。初始化产物保存成功后自动进入 `AUTO_DESIGN`。

## 状态契约

| 状态 | 主要输入 | 输出 | 是否允许写正文 |
|---|---|---|---|
| `AUTO_INIT` | project_id、名称、路径 | 项目元数据、空快照、版本记录、初始化检查 | 否 |
| `TYPE_SELECTION` | 用户题材/类型/读者 | 类型选择与适配记录 | 否 |
| `STORY_BIBLE` | 类型、硬要求、能力候选 | 故事核心、世界方向、主冲突、开篇方向 | 否 |
| `CHARACTER_DESIGN` | 故事核心、世界规则 | 主角、关键人物、关系状态 | 否 |
| `CHAPTER_OUTLINE` | 故事圣经、人物状态 | 当前章节目标与章节纲要 | 否 |
| `SCENE_OUTLINE` 至 `SCENE_BEAT_DESIGN` | 章节目标、场景上下文、材料结果 | 场景设计、节拍、连续性约束、资料调用清单 | 否 |
| `SCENE_DRAFT` | 章节执行清单、节拍、锚点、状态约束 | 场景/章节正文、章节状态、规则体现证据 | 是 |
| `AUTO_SAVE` | 正文、状态检查 | 正式章节、快照、版本记录、资料来源记录 | 保存 |
| `AUTO_CONTINUE` | 快照、正文目录、项目目标 | 下一个未完成任务 | 否 |
| `BLOCKED` | 阻塞原因 | 阻塞记录与唯一待处理事项 | 否 |

## 自动决策与提问门槛

普通缺失字段、类型适配、风格、篇幅、结构、资料选择和章节安排由 Cline 自主决策并记录来源。只有项目身份无法唯一确定、目标路径存在且归属不明、覆盖/删除风险、用户硬要求与锁定设定不可调和冲突、关键资料/核心文件损坏或缺失、重大核心设定完全无依据、工具自动重试仍失败、不可逆数据损失时才进入 `BLOCKED`。`WAIT_USER`、`WAIT_CONFIRM`、`PAUSED_BY_GATE` 仅可作为记录值，不得阻断普通生产。

## 完成标准

每次状态推进都写入运行记录，说明状态、输入来源、产物路径、决策来源、检查结果和下一状态。资料不足时普通项为 `partial` 并自行补足，核心项才为 `blocked_not_available`；`pending` 不得作为普通停止条件。

## 资料驱动门槛

“已读取文件”不等于“已调用资料”。每个可执行资料记录必须产生 `output` 文件，并记录 `source_labels`、输入参数、设计决定、正文要求、判定标准和未采用原因。前三章必须存在项目级 `golden_three_tasks.json`；涉及人物的章节必须存在 `character_behavior_contract.json`；正式正文前必须存在 `chapter_execution_manifest.json`。缺失这些中间产物时，状态只能停留在 `AUTO_DESIGN`。
