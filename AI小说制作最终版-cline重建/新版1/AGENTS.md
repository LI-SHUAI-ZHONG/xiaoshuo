# 项目变更前置阅读门禁

本文件约束在本项目内执行读取、分析、修改、运行或生成证据的自动化代理。项目中的方案、状态、原始资料和既有证据优先于会话摘要、推测和脚本名称。

## 默认拒绝

在完成本文件规定的前置阅读并写入变更阅读记录前，代理不得：

- 编辑 `脚本`、`配置`、`文档`、`正文`、`原始资料`、`网络完整数据` 或 `资料索引` 中的任何文件。
- 运行会写入项目的脚本、升级、修复、回归、发布、采用、场景或正文流程。
- 更新状态、报告、清单、manifest 或任何“已完成/已通过/已授权”声明。

只读检查不产生修改授权。测试通过、脚本存在、历史报告存在或用户转述均不替代前置阅读。

## 必读依据

所有变更必须先读以下通用依据：

1. `文档/修补方案/创作资料全量调取修补主计划.md`
2. `文档/修补方案/全量资料模型受控改进最新版方案.md`
3. `文档/修补方案/修补状态.json`
4. 与目标文件同目录的最新状态、报告、manifest 或采用/消费证据。

按变更类型追加阅读：

- P6、全量资料升级、批次回归或隔离：读取最新 P6 状态、目标 run 的 `manifest.json`、对应异常审计和最新批次回归报告。
- 项目采用、场景、正文或发布：读取项目任务声明、采用决策、正文消费证据、失败样本隔离报告，以及对应授权/发布门证据。
- 修改现有脚本：读取目标脚本全文、其同名测试全文、该脚本写入的所有输出格式和最近一份相关报告；先确认现有参数、默认值、父链和 snapshot 语义。
- 修改配置或原始资料：读取其所属方案、资源注册表、哈希/版本证据和所有直接消费者；原始资料默认不可修改，除非用户明确授权且方案允许。

## 变更阅读记录

每次准备修改前，在 `文档/证据/变更前置阅读记录` 新建一份不可覆盖的 JSON 记录。记录必须包含：

- `change_id`、UTC 时间、计划修改的绝对路径和变更目的。
- 已读文件的绝对路径、SHA-256 和具体结论。
- 已确认事实、未确认事实、冲突证据及处理决定。
- 授权边界：明确列出本次不改变的采用、场景、正文、发布或原始资料状态。

记录缺少任一必读依据、存在未解决冲突，或结论与证据不一致时，代理必须停止并向用户报告，不能通过修改检查、放宽断言、重跑任务或重写历史证据来消除冲突。

目标文件的修改前 SHA-256 必须在编辑前写入记录；未记录前态哈希时不得编辑该文件。修改后哈希只能作为核对值，不能替代前态阅读证据。

## 修改与核对

- 只作解决已确认问题所需的最小修改。不得借机重构、补写状态或改变授权。
- 完整 snapshot 是其自身记录集的权威终态；不得与其父 delta 链重复合并，除非方案和 manifest 明确要求。
- `quarantined`、`model_error`、`draft_only`、`blocked` 不得改写为通过、采用、可消费或可发布。
- 修改后只进行与改动直接相关的静态核对；除非用户明确要求，不得运行测试、回归、升级、采用、正文或发布任务。
- 结束时必须将变更阅读记录与实际修改逐项核对；不得把单项校验通过描述成阶段完成或发布授权。

## 冲突优先级

当状态文件、方案、manifest、报告或消费证据冲突时，停止修改并报告冲突。不得自行选择更有利于“通过”或“完成”的一方。用户明确指定的处理决定才可解除该冲突。
