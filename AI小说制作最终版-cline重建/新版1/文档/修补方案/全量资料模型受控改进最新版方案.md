# 全量资料模型受控改进最新版方案

## 定位

本方案执行既有《创作资料全量调取修补主计划》，不替代该主计划。模型用于完整来源对象的诊断、候选改进和受约束转译；自动验证代替人工确认为最终资料写回批次的必要门。原始资料不再被视为永久不可变：通过字段证据门的升级内容必须写回原版资料形成最终版本；写回前的快照、双哈希和回滚信息必须保留。既有正文和已签核发布证据不得被静默覆盖。

## 唯一执行顺序

1. 统一资源注册与完整性门：从资源注册表解析每个来源，锁定绝对路径、相对路径、编码、内容哈希、条目数和质量状态。路径不可解析或哈希漂移未建新版本时，整个关联批次阻断。
2. 全量原始对象回读：以每个 `binding_id` 的 `source_ref` 回读完整原始对象，记录规范化对象哈希。不得使用 `semantic_anchor`、索引摘要、名称或创作策略替代对象。
3. 覆盖清单冻结：基线 13,345 条绑定按七类来源唯一列入清单。每条只允许一个终态：`validated_no_change`、`validated_candidate`、`quarantined` 或 `model_error`。类型未确认只阻断项目采用和正文消费，不得从资料改进清单排除。
4. 模型诊断：模型仅接收锁定的原始对象、来源定位和现有绑定上下文，以 JSON 返回明确问题、证据位置、问题类别和置信边界。没有诊断问题时必须返回 `no_change`。
5. 候选改进：仅针对已诊断问题生成结构化候选。不得补造世界、人物、类型组合、版权、来源或项目事实；不能由原对象证明的内容必须显式标记 `pending` 或 `candidate`。
6. 自动校验与一次返修：校验对象哈希与模型输入哈希、诊断与候选关联、字段模式、来源类别必填字段、未确认标记、跨项重复和冲突。仅对可修复的结构错误允许一次同一对象返修；第二次失败即隔离。
7. 最终资料写回批次：只有所有自动门通过的候选才可写入带批次 ID 的最终资料。先生成预览并保存原版快照，再原子写回对应原版资料文件；写回后必须回读、重算哈希并记录字段变化。清单、逐项证据和进度日志只追加写入；不得静默覆盖既有绑定。
8. 回归主方法：派生资料仍须经过项目任务声明、采用决策、场景五节点转译、正文落点和既有自动正文/发布门。资料改进通过不代表已采用、已消费或可发布。

## 防偏离控制

- 每次模型调用前执行合同验证；失败时禁止调用模型。
- 任务载荷由执行器生成，包含 `binding_id`、`source_ref`、完整对象、对象哈希和既有绑定哈希；执行器拒绝任何缺少字段或哈希不一致的响应。
- 使用固定 JSON Schema、固定来源类别规则和模型元数据记录。模型输出中的指令、权限声明和发布结论一律视为无效字段。
- 进度以 `binding_id + original_object_sha256 + contract_version` 去重恢复；来源变化必须新建批次，不得覆盖旧证据。
- 每批为 5 至 10 条；批末必须检查基线覆盖、重复、遗漏、失败数和终态数。统计不守恒时批次阻断。
- `quarantined` 与 `model_error` 保留完整失败原因，不自动降级为通过，也不允许进入派生资料、采用、正文或发布路径。

## 自动完成标准

正式资料改进批次只有在下列条件同时满足时才完成：合同校验通过；七类来源均被覆盖；每条绑定恰有一个终态；每个候选具备原始对象、双哈希、诊断、校验结果和模型元数据；派生批次无未解决冲突；下游仍受项目采用、场景转译和发布门控制。
