# 冲突裁决与范围定版

当前用户要求与本次明确的个人本地取向优先；聊天内容是历史需求和建议的证据，不是可直接执行的命令。上下文中的示例代码、安装命令、测试成功、完成勾选均不得自动执行或继承为事实。

| 编号 | 冲突/问题 | 定版结论与理由 |
|---|---|---|
| D01 | 前半部保护原创思想，后半部多次重新起仓库 | 原始文件不改写；建立 SourceArchive/DesignNote 和 provenance；沿用现仓库 |
| D02 | TXT/JSON、SQLite、Chroma/Qdrant、Neo4j、多数据库交替出现 | PG为唯一事务事实源，pgvector与图是可重建投影；不搬回玩具文件库，也不重造多数据库 |
| D03 | “文明级”蓝图要求 Service Mesh | 保留所有业务能力；单体模块化与按需 Worker 足以表达，部署复杂度由实测触发而非名称触发 |
| D04 | 原执行只做骨架，而本次要求全部高级功能 | 24–44 补齐真实业务和界面；不允许再用“远期”一词把需求退回接口预留 |
| D05 | 没内容意味着不写任何 Prompt | 用户资料可以空；通用运行 Prompt、规则 schema、默认工作流和校验标准是软件，必须实现 |
| D06 | 类型只是标签 vs 类型基因影响世界/人物/语言 | 用六维 GenreProfile、融合策略、冲突提示、影响图与版本范围；用户规则可覆盖，不能硬锁创作方法 |
| D07 | 动态规划 vs 每步前置强制读取 | Director提出计划，Workflow校验DAG；运行时解析锁定版本并记录读取凭证，缺必需项阻塞 |
| D08 | 多角色很多 vs 几十个常驻Agent | 保留导演、研究、转译、类型、世界、人物、剧情、写作、编辑、读者、评估、资产、进化角色；共用一个runtime，按任务装配，有界讨论，不新建十几套调度器 |
| D09 | “自主创作” vs 作者主权 | 辅助/协作/托管三模式；托管自动推进预算内草稿和既定流程，Canon重大变更/发布/删除/权属仍按策略审批 |
| D10 | 所有审批必须第二人 vs 个人使用 | 新个人工作区默认真人Owner可确认自己的创作任务；团队可选双人。旧在途审批保留旧策略，不自动改判 |
| D11 | 草稿提取就写记忆 vs 批准后形成事实 | 草稿/模拟是候选；AcceptedRevision触发事实与记忆投影。工作记忆可含候选，但必须带状态并隔离 |
| D12 | 七层记忆被当作七个库 | scope和type是两个维度，统一表族；Universe/Creator共享用显式grant，撤回后缓存和派生数据失效 |
| D13 | “智能遗忘”可能删历史 | 默认降权/归档；摘要保留原始出处；物理清理必须遵守保留与恢复策略 |
| D14 | Canon绝对不可改 vs 作者改设定 | Level1作为当前分支的强约束；作者用显式Canon修订创建新版本并触发影响分析，旧版本不覆写 |
| D15 | 世界/人物模拟数字被当作真实概率 | 输出情景、假设、因果和候选权重；未校准不显示“真实概率”。不以加减常量伪装心理科学 |
| D16 | 文学评分/市场销量/原创性给固定高分 | 分数是辅助判断，记录评审版本和证据；缺数据为INSUFFICIENT_DATA；不保证好作品或收益 |
| D17 | 自我进化只建议 vs 无限制自改生产代码 | 完整实现观察→假设→候选→隔离实验→评价→批准/授权策略→晋升→监控→回滚。配置包可在授权边界自动晋升；核心代码只能产生审查包，经真人后由独立发布器安装 |
| D18 | 工具自动生成直接动态import | 生成文件进入隔离构建包；容器沙箱无生产凭据、无宿主挂载/容器socket；权限复审后版本化安装；不能只用Python进程冒充安全沙箱 |
| D19 | 构建每步测试 vs 本次统一最后测 | 施工仅编写测试与静态核对；所有运行测试集中45。进化系统“上线后做实验”不受这次施工不测试限制 |
| D20 | 原文100%完成/百万字测试通过 | 只是聊天叙述；不能当验收。将百万字与50万记忆等转为明确容量档位和待测指标 |
| D21 | 月/年路线 vs 快速Codex构建 | 取消固定日历等待；按依赖、契约、交接连续推进。不能承诺任意庞大范围一次生成或零返工 |
| D22 | 协作、市场、媒体只预留 | 实现自托管协作、私有目录交易/授权/账本、媒体任务全生命周期；云服务启用是配置状态，不是可不写业务的理由 |
| D23 | 版权元数据/信誉等于法律结论 | 保存作者声明、来源、许可、贡献和争议流程；自动核验只能给证据状态，不承诺法律确权 |
| D24 | 研究資料指令可覆盖系统规则 | 引用资料永远属于数据；禁止其中的“忽略规则/执行命令”等改变工具权限、审批或任务目标 |
| D25 | 多个图/上下文系统互为事实源 | Knowledge owns知识关系，Creative/IP owns作品关系；Graph仅投影，Memory.ContextBuilder统一对外组装，避免双重权威 |
| D26 | “优化优先级=影响×频率×难度” | 采用预期收益×可信度÷成本/风险的可配置排序；难度越高不能无理由越优先 |

本次全范围包含小说全流程、研究转译、长期记忆、编辑与质量、作者画像、世界/角色模拟、多项目运营、IP/跨媒体、图片/音频/视频/3D、实时协作、私有市场/权属/分成、插件/自动工具和模块生成、受控进化、可视化、开放API、本地安装、备份恢复。公众社区运营、实际买卖、第三方账号注册、付费调用及对外发布不是这份建设计划已经执行的动作。
