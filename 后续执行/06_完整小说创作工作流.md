# 完整小说创作工作流

这是系统建成后的运行规则。这里的创作质量检查、实验评价是产品功能；施工阶段不执行这些运行测试。

## 1. 从空工作区开始

首次启动完成本地Owner初始化、存储检查页面、模型配置与预算设置。没有外部模型时，手动写作、资料管理、结构编辑、导出继续可用；生成入口说明缺少哪个配置。没有知识库时不虚构检索来源，可以使用作者输入和明确标注的“无外部资料创作模式”。需事实研究的任务在缺资料时进入waiting_resource。

作者可以手动补齐每个前置产物，也可让系统生成候选后确认。原始想法只追加版本和批注。协作模式默认关键创作关卡由作者确认；托管模式使用作者事先设置的范围、预算、候选数量和停止条件。

## 2. 标准主流程与每步交付

| 运行节点 | 必须输入/强制读取 | 输出 | 推进条件 |
|---|---|---|---|
| N01 灵感捕获/任务澄清 | 作者原话、目标、约束、当前项目 | OriginalIdeaRef + WorkBrief候选 + 缺项清单 | 作者确认目标；缺少会改变作品方向的项不猜成事实 |
| N02 类型与读者定位 | Brief、作者可用偏好、类型组件 | GenreProfile/BlendPlan、六维影响、融合风险 | 作者选方案或使用自定义；无类型库可手工定义六维，不随机填充模板 |
| N03 研究/资料准备 | 资料需求图、来源权限、预算 | ResearchPlan、带证据知识、转译组件 | mandatory来源齐全或经作者将对应可选项调整；不得伪造引用 |
| N04 世界设计 | Brief、类型影响、研究与规则约束 | WorldBible：规则/历史/地理/文明/制度/资源/科技/文化 | 结构检查和作者确认，形成基础Canon版本 |
| N05 人物设计 | 世界、主题、类型、角色任务 | DNA/身份、心理/欲望/创伤、目标、关系、成长、VoiceProfile | 动机和行动有来源；人物知道的秘密与作者知道的真相分开 |
| N06 全书与卷规划 | 已确认主题/人物/世界、结局意向 | Series→Work→Volume→Arc→Chapter→Scene、故事线、因果、情绪曲线、伏笔表 | 不强制单一三幕模板；允许作者提供结构 |
| N07 本章任务 | 卷/章节计划、前章接受版本、未完成伏笔、当前世界/人物状态 | ChapterBrief + ScenePlan +预期状态变化 | 章节计划与输入版本一致 |
| N08 依赖预检 | StageRequirement、所有mandatory refs、授权、配额 | PreflightReport + 冻结StepInputManifest | 缺项→waiting_resource；旧版本→stale；未配模型→waiting_configuration |
| N09 上下文组装 | Canon、角色当前/历史状态、知识组件、作者风格、前置产物 | ContextPackage + ReadReceipt + 排除原因 +token预算 | mandatory全部入包；超预算分步/重新规划，不能截掉硬约束 |
| N10 场景/正文生成 | ContextPackage、场景目的、POV/信息权限、VoiceProfile | PartialDraft→完整DraftCandidate，可选多个变体 | 实际完整返回并存储后才完成；截断/拒绝/取消单独状态 |
| N11 审稿 | 草稿同版本、Canon/时间/因果/人物/主题/风格、引用 | Findings、维度评价、读者模拟、修订候选 | 硬规则阻断；主观评价有证据、可申诉；未检查不能过关 |
| N12 修订 | 指定问题、选中文段、目标Revision、锁定段落 | 有范围的Patch/新版Draft、修改理由/影响 | 作者已写内容不能被旧候选覆盖；有限轮次后转人工 |
| N13 作者审阅 | 版本差异、发现、事实变更、影响 | 接受/拒绝/保留草稿/退回前置节点 | 真人或明确配置的低风险自动策略；主题/Canon重大变更要求真人 |
| N14 接受与事实提交 | 完整正文、批准、未过期检查、expected revisions | AcceptedRevision、事实新版本、Outbox、审计 | 同一提交边界一致；partial draft不可接受 |
| N15 记忆与索引 | AcceptedRevision/新事实事件 | 摘要、事件/因果/角色状态/伏笔投影、应用记录 | 去重与watermark完成；自动推断未证实项保持候选 |
| N16 下一章/全书复核 | 新状态、未回收线索、卷计划、预算 | 下一章任务或卷/全书整合报告 | 依赖版本合格；章节间依赖顺序不可被并行调度绕过 |
| N17 定稿与出版 | 接受版本集合、顺序、作者批准、许可元数据 | TXT/MD/DOCX/EPUB/PDF/项目包，版次与manifest | 本地导出可自动；外部平台发布需具体授权与配置 |
| N18 反馈与进化 | 显式评分/修改/同意信号、成本/失败/质量数据 | 作者模型候选、经验组件、改进实验、成长建议 | 数据不足不伪造学习结果；实验后才能晋升 |

## 3. 灵活性如何保留

默认采用上表，但它是可编辑的依赖模板，不是写死的世界→人物→剧情顺序。悬疑可先真相和信息分配，人物小说可先人物冲突，世界驱动作品可先文明。每个模板说明最终写正文时必须齐全的输入；允许在准备阶段来回迭代，但不允许跳过最终依赖门。

用户新增创作理论先作为versioned组件进入实验空间；规定适用条件、输入、输出、限制、来源、与其他组件组合方式。作者可查看调用路径，主动锁定或禁用组件。旧运行继续引用旧版，不能随模板更新改变正在写的章。

## 4. 多种写作操作

- 从零建书、继续下一章、补写场景、扩写/压缩、对话润色、人物声音统一、视角转换、全章/多章修订、分支试写、旧稿导入接管均进入同一GenerationRequest。
- 手动写作直接保存WorkingCopy，不必先请求模型；接受为正式章节时运行配置的检查与事实提取流程。
- 一次生成多个候选共用明确输入快照，各自计费；评分不能仅靠生成者自评，UI展示差异和依据而非自动宣称最佳。
- 编辑委员会是受预算的独立审查任务：逻辑、人物、结构、风格、读者体验可并行；一次汇总，冲突保留，最多配置轮次，不允许无界互聊。
- 局部修订使用稳定block/character span锚点；原位置变化后进入冲突处理，不把旧offset套到新正文。

## 5. 长篇连续性与修改传播

每个实体有“真实故事时间”“正文披露时间”“被记录时间”；角色可知信息、读者可知信息和世界事实分别查询。倒叙/插叙不视为错误；系统检查对应时间维度。

修订早期设定时，依赖图找出引用的章节/记忆/摘要/分镜/跨作品绑定，标记影响范围，作者选择保留旧分支、重审或重写。先确认规则新版，再对受影响章节分批重检；原正文保持可读，显示stale标签，不整书自动覆盖。

伏笔包含introduced、developed、revealed、resolved、abandoned及理由，deadline可为卷/章节区间；检测“未回收”必须考虑作者明确废弃或开放结局，不能强制所有伏笔闭合。

世界/角色模拟在隔离ScenarioBranch上运行，保存seed/模型版本/假设/步数。假设未被作者接受前，不影响正式Canon和后续章节。

## 6. 失败、恢复与停止

| 情况 | 系统行为 |
|---|---|
| 资料不存在、未授权或版本过期 | 等待资料/权限/重新规划；保留已经完成产物，不伪造空成功 |
| mandatory上下文过长 | 提示预算分配，拆成子任务或经作者确认的受证据约束摘要；硬规则不能静默省略 |
| 模型超时但可能已计费/已完成 | 保存unknown状态和外部request_id；查询/对账后决定续传或新请求 |
| 流式断线/浏览器刷新 | 服务端继续或按取消策略结束；重新查询持久运行与草稿，不由浏览器自己补终态 |
| 作者编辑与AI结果碰撞 | 409 + 三方diff；候选保留，不覆盖作者新版本 |
| 连续修订仍不合格 | max_iterations或预算到达后停止，展示残留问题与已用费用 |
| 模拟/研究/插件反复失败 | 单模块降级，不拖垮手工写作；错误有correlation_id |
| 记忆投影未追上正式章节 | 后续强依赖节点等待指定watermark；不得拿前章旧状态继续 |
| 作者撤销/停止 | 明确取消API；禁止继续发起新外部副作用，保存可恢复的部分结果 |

## 7. 最小与完整验收路径

最小真实写作路径：本地登录→创建空作品→填入短Brief→配置真实/本地模型→生成前置候选并作者确认→产生一章→审稿/修订→接受→刷新/重启仍能读取全文→下一章带正确状态→导出。

完整路径额外覆盖：资料导入转译、类型混合、前置缺失阻断、章节分支与影响分析、人物信息权限、世界模拟、作者画像撤回、真实进化候选A/B/晋升/回滚、IP复用、跨媒介、多人编辑、私有包安装授权与分成账本。测试夹具可以是隔离合成内容，不自动填入用户正式库。
