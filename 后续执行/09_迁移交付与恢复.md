# 迁移、交付与恢复

## 1. 施工和验证分开

24–44写实现、迁移/回填程序、测试代码、安装脚本和文档。允许文件阅读、差异核对、离线代码生成，以及确认无测试副作用的格式/类型/编译检查。**不运行测试、冒烟、真实连接试调用、性能/恢复演练、数据库迁移或服务启动来验证功能。**45才统一在隔离环境测试、修复和回归。延后测试会集中发现缺陷，所以45不能省略，也不能保证零返工。

旧`pnpm check`、`check:quick`、`lint`、`api:check`、`scripts/check.*`不可直接当无测试检查：`scripts/toolchain.mjs`的lint包含`check-openapi.mjs --self-test`等可执行检查。24定义无测试/联网/服务副作用的静态入口；无法证明则留45。Next构建若触发页面取数，先消除构建期运行API的设计，不借构建名义提前联调。

## 2. 保护基线

当前Git没有已提交基线，`git diff`为空不代表没有文件。24按白名单为源码、配置样板、锁文件和文档建立文件hash清单及可恢复副本，记录专用输出目录绝对路径；排除`.env`、凭据、缓存/依赖、真实数据库和对象内容。没有授权commit时不以commit为前置，不调用reset/clean删除未跟踪成果。

原聊天、`执行/`和01–23历史handoff只读保留。方案文件可以更新。续接附件路径变化但hash相同；实际施工发现输入hash变化时比较增量更新矩阵，不重头建仓库。

## 4. 部署档位

| 档位 | 组件 | 可运行范围 |
|---|---|---|
| core | PG/pgvector、Redis、S3、API、Worker、Studio | 手工写作/结构、正文、资产、查询、导出、计划管理 |
| 本地AI | core + Ollama服务/模型/embedding | 能力满足schema/上下文时运行生成与检索，仍记用量 |
| 云AI | core + Provider/secret | 按项目出站策略发送；私密项目禁外发/fallback |
| 团队 | core + apps/collab，远程访问再配TLS/身份 | 多人编辑、评论/任务；默认loopback |
| 沙箱 | core + 受信任controller + 隔离Linux执行环境 | 插件/代码实验；任务无容器socket或宿主挂载 |
| 媒体 | core + 媒体服务或本地ComfyUI/GPU、转换工具 | 配置的图/音/视频/3D；缺项不阻止写字 |
| 目录/结算 | core私有目录 + 独立外部结算配置 | 无支付key可免费包/授权/手工对账，付款不能假报ready |

沿用Compose交付，不强制另购服务器。脚本检测依赖/端口/磁盘/配置后列缺项；安装Docker/驱动/系统服务需具体环境授权，本次规划不执行。开发可本机运行同一API/Studio，不另造简化事实库。

SecretProvider优先引用环境/系统凭据。UI录入需加密，主密钥来自外部配置，不与密文同表；导出仅secret_ref。提供轮换、丢失后重配与加密备份恢复说明，不声称能无密钥解密。

## 5. 顺序和上下文接力

用户授权完整施工后，24–44按序推进；指定某一步时以用户范围为准。第25步已有正式交接及2026-09-26修补记录，下一断点为26。每步内部按契约→数据→应用→适配器→API/客户端→UI→交接。编号不是日历安排，不每步重评全架构/换栈/重建。共享迁移、composition、状态enum、路由注册、锁文件、生成客户端由当前步骤单写入者负责。方案审阅任务不因读取本段而变为施工任务。

默认不自动建新任务或启动子代理。以后用户授权并行时，只拆无共享写入的模块，统一串行集成。每步读共同规范、自身R/T项、直接前置交接和相关源码，借`进度.json`和`docs/handoffs/NN.md`恢复上下文。中断写IN_PROGRESS和下一条动作；外部缺配置可继续代码，公共契约未完成则先修复依赖。

## 6. 交付物

- 本地启动/停止/升级入口、环境样板、配置向导；普通停止保留数据。
- 全业务代码、追加迁移/回填、锁文件、真实适配器、默认运行包；OpenAPI/客户端一致。
- 用户手册：从空白到第一章、旧稿导入、正文恢复、改设定、模型配置、失败恢复。
- 运维手册：迁移/备份/恢复/轮换、GC、索引重建、插件回退、协作故障、结算对账。
- 构建manifest/依赖SBOM/schema兼容表、统一测试证据和外部条件。

交付状态分别是IMPLEMENTED_UNTESTED、VERIFIED_LOCAL、EXTERNAL_PENDING、VERIFIED_FULL_CONFIGURED。最后一种仅表示本次完整配置通过，仍须列出全范围内未启用/未验证项，不豁免未实现功能。缺证据不能说“所有功能已可用”。
