# ACCOS 完整创作系统后续执行包

设计基线：2026-09-24；施工修订：2026-09-26。部署取向：**个人本地优先，完整保留扩展功能**。用户本轮明确指示“继续25步开始施工”，已按实际代码接手第25步并补齐安装与登录恢复路径；24–44不运行项目测试。实际范围遵循最近用户指令，阅读方案本身不构成扩大施工范围的授权。

**总编号到45；后续是22步：24–44共21步搭建，45集中测试。** 第24–26步已有“已实现、未测试”交接；第26步正文、版本、离线草稿、资产和集合基础见[26交接](../docs/handoffs/26.md)。当前施工断点是第27步，28–45待执行。详细断点见[13 接管说明](13_接管说明与施工断点.md)；实际实施状态以[进度.json](进度.json)和真实文件、交接证据共同核对。方案齐全不等于软件已经完成。

## 结论

保留现有「模块化单体 + 独立 Worker + PostgreSQL/pgvector + Redis + S3 + Next.js Studio」，从骨架继续建设。现有 01–23 的成果有价值，但不能直接当作完整小说创作系统：正文尚未落盘、真实模型与 Agent 未接通、创作模型主要保存元数据、多数高级扩展仍是 Null。

本包将后续工作拆成 **24–44 共 21 个构建步骤，45 为统一测试、修复和验收**。编号只表示依赖和交接边界，不代表一天、一周或一个月。可以在同一 Codex 任务中顺序连续执行，不必每步重新开任务或等待确认。

## 使用方法

1. 先读 [13 接管说明](13_接管说明与施工断点.md)，了解范围和已有改动。只审阅方案时不执行施工指令。
2. 完整连续施工使用 [10_Codex总执行指令.md](10_Codex总执行指令.md) 中的施工代码块。第24、25步核对交接后沿用；下一施工断点为26，不从01或24重做。分次执行时以用户指定的当前施工卡为范围。
3. 构建阶段写代码、迁移文件、测试代码和待测登记，但**不运行单测、集成、E2E、烟雾、真实模型试调用、压力或灾备测试**。不得用旧执行包的测试前置条件阻止继续构建。
4. 24–44 开始前为 `PLANNED`，施工中为 `IN_PROGRESS`，代码齐备后只能写 `IMPLEMENTED_UNTESTED`；确有阻塞写 `BLOCKED`。45 按测试表取得证据后才能写 `VERIFIED`。没有密钥、数据或硬件的项目写明具体外部条件，不能写通过。
5. 施工选择下一步时，`IMPLEMENTED_UNTESTED` 表示该步已施工、等待45验证，不因尚未 `VERIFIED` 重做。进度文件同时记录施工暂停状态；暂停不抹去第25步已有改动，也不等于技术阻塞。

## 完成的含义

功能完成需要「领域行为 + 持久化 + 权限 + API + Worker/事件接线 + UI 操作 + 故障恢复 + 测试证据」。端口、菜单、按钮、固定返回值、Fake、TODO 都不能单独算完成。

没有资料时，知识库、作品、人物、作者画像和市场商品可以为空；**默认工作流、通用操作 Prompt、输入输出 schema、路由、提取器、正文存储、校验器和配置页面不能为空**。它们属于软件实现。

外部模型、媒体生成、支付结算的真实运行需要相应服务、账号/密钥或本地模型。必须完成真实适配器代码和完整业务链，缺配置时明确显示 `CONFIG_REQUIRED`；不能把“等用户配置”当作只写 Null 的理由，也不能把未验证的外部能力说成已可用。文学质量、市场收益、人物行为概率都不能由软件架构保证。

原聊天记录和 `执行/` 保持原样作历史证据；本包取代其中“只做骨架、不写运行 Prompt、每步先跑测试、远期能力仅预留”等与本次目标冲突的施工要求。上层系统与工具权限仍有效。
