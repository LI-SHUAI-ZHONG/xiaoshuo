# ADR 0007：个人与团队审批策略

- 状态：Accepted（由 25/28/33/37 落实）
- 日期：2026-09-24
- 扩展 ADR 0004；保留其作者主权、最小权限与审计要求

新建个人工作区默认 `human_owner`：经真人登录的 Owner 可确认自己提出的创作请求。
团队可配置 `dual_control`，禁止申请人自批。Agent、服务身份和 PAT 都不能冒充真人。
核心代码安装、对外发布、不可逆删除、权属转移等仍需与具体资源和版本绑定的真人决定。
低风险自动晋升只可使用用户已授权的独立策略，不把自动行为写成真人批准。

identity 唯一拥有审批策略及版本。请求所属模块保存请求、冻结的策略引用、输入版本及决定，
不建立供多个模块任意写入的共享审批表。旧在途请求固定 `legacy_dual_control`；升级或更改设置
不补发决定、不将既有待审记录自动批准。拒绝、过期、撤权、版本变化必须再次走合法流程。

25 实现一次性本地 Owner 初始化、口令摘要、可撤销会话、成员和权限、PAT、只写凭据配置。
Cookie 会话具有到期、CSRF/Origin 保护；登录限流和服务端撤销。团队 OIDC 使用授权码/PKCE。
凭据密文与主密钥分离；主密钥缺失时报告配置缺项，不能把 API key 存为普通设置文本。

Creator 的身份 anchor 由 identity 在 25 建立；36 的风格学习使用该 anchor。
Universe 的授权 anchor 与现有 Memory 协议兼容，真实 IP 聚合在 39 绑定。
跨项目、Creator 或 Universe 的读取必须有显式授权，`project_id=null` 不代表公开。

最终验证：T004–T010、T025、T073、T097。本决策不代表身份与审批代码已经完成。
