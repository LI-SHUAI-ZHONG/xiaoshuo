## 本阶段变更

### Models 模块

- 新增 `modules/models`，公开 `ModelProvider`、`ModelRequest`、`ModelResponse`、`ModelCapability`、`ModelPolicy`、`UsageRecord`、`ProviderHealth`、`UsageLedger` 与 `SecretProvider`。
- text/embedding 由确定性 `FakeModelProvider` 支持；image/audio/video/3d 有稳定 capability 枚举和 `NullModelProvider`，未配置时返回稳定 `NOT_CONFIGURED`，不会伪造输出。
- `ModelRegistry` 只从显式 allowlist 中按 primary/backups 和能力匹配路由。网关统一执行 RBAC、metadata active 检查、单次/Workspace/Task/尝试预算、timeout、有限重试、退避、熔断与 Provider 并发限制。
- Fake 可按 idempotency key 配置成功、延迟、超时、限流和失败，并产生固定用量/确定性 opaque reference；通过两个 Fake Provider 验证主备切换。
- `SecretProvider` 只按 Provider ID 返回凭据；默认 `NullSecretProvider` 永远不返回值。Provider 凭据不属于任何请求、领域对象、Workflow、日志、账本或错误。
- Prompt/Policy 只登记 ID、kind、语义版本、SHA-256 校验和与状态；同一版本不可变，调用只能引用 active 元数据，不存任何 Prompt 正文。

### Tools 与插件边界

- 新增 `modules/tools`，公开版本化 `ToolDescriptor`、object input/output schema、所需权限、网络 host、相对文件 root、资源类型、timeout、幂等属性、审计策略、`ToolGrant`、`ToolExecutor` 与调用结果/错误契约。
- `ToolGateway` 固定按 RBAC → Registry → Workspace/Project/Task Grant → Descriptor/Grant scope 交集 → 输入 schema → timeout 执行 → 输出 schema → 调用审计的顺序失败关闭。
- 默认工具没有网络 host、文件 root 或资源类型；协议没有 Shell 能力。未知工具、未授予工具、schema 错误、timeout、执行失败、非法输出、网络/绝对路径/`..`/资源越界均返回稳定码并写入调用账本。
- `FakeToolExecutor` 只生成确定性引用，可按 idempotency key 模拟延迟、超时、失败和非法输出，不读取文件、不执行命令、不访问网络。
- `RepositoryPluginLoader` 只读取指定仓库根下名为 `manifest.json` 的 JSON；拒绝目录逃逸和其他文件，不下载、不 import、不执行插件代码。插件声明 ID、版本、核心兼容范围、能力、权限、签名与 enabled；trust 由加载器的本地签名 allowlist 计算，manifest 不能自报可信。唯一测试插件位于 tests fixture。

### 持久化、Workflow 与 composition

- Alembic `0005_model_tool_gateways` 新增 append-only `accos.model_usage_records`、`accos.tool_call_records`，并给 `workflow_runs` 增加服务端提交时的 `permission_snapshot` 和 `policy_version`。
- 两个账本均包含 Workspace、Project、Workflow、Task、actor、correlation、幂等键、稳定状态/错误和时间；模型账本另含 Provider/capability/尝试/用量。两表都不含 credential、模型内容、工具 input/output、网络响应或文件内容字段。
- Workflow Worker 从持久化权限快照重建可信 `SecurityContext`。`GatewayWorkflowExecutor` 在 `framework_smoke` 的 `pass-token` Task 中依次调用 Fake Model 与显式授予的 Fake Tool；其他技术步骤继续委托执行 08 的 `FrameworkSmokeExecutor`。
- composition root 新增 `ModelServices`/`ToolServices`，注册 Fake/Null Provider、Fake Tool、SQL 账本和独立 Secret port。Celery consumer 继续使用独立 `NullPool` 数据库 runtime，模型/工具调用与授权审计也使用该 consumer 边界，避免跨事件循环复用连接池。
- 更新 README、架构导览、数据所有权、数据库/Workflow/Project 运行手册，并新增模型工具架构与运行手册。

## 故障与降级策略

- `NOT_CONFIGURED`：能力无允许 Provider 或调用 Null；不重试为成功、不制造数据。
- `RATE_LIMITED`、`TIMED_OUT`、`PROVIDER_FAILED`：只在当前显式 Provider 路由和总尝试上限内重试/切换；原始异常不外泄。
- `CIRCUIT_OPEN`：达到阈值后在冷却窗口跳过调用并记录非 billable 审计；冷却到期才允许下一次受控尝试。
- `BUDGET_EXHAUSTED`：单次、Workspace、Task、调用次数或路由总尝试任一耗尽即失败；故障切换不会重置。
- Tool 任何失败不修改 Descriptor/Grant，不增加网络、文件、资源或 RBAC 权限；所有拒绝都以 payload-free 记录保留。
