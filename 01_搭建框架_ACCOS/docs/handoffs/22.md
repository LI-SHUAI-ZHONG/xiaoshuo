## 可观测性与诊断链路

- JSON 日志统一包含 timestamp、level、service、environment、event、request/trace/task/workflow/agent/model-call ID、脱敏 Workspace/Project 引用、duration、outcome 与 error code。
- 日志字段递归脱敏凭据、Authorization、Prompt、Memory、正文和原始用户/工作区/项目 ID；HTTP 日志只记录路由模板，不记录带资源 ID 的原始 URL。
- API 响应携带 correlation/trace ID，Workflow、Task、Agent、Model Call、Outbox 与对象存储路径保留可关联标识。
- `TelemetryRuntime` 提供受注册表约束的低基数 Counter、Gauge 与 Histogram；覆盖 API 延迟/错误、Worker 心跳与租约、Workflow 状态、Outbox backlog/age、模型调用/Token、数据库池、知识摄取、SSE 连接、对象存储和 OTLP 导出结果。
- `GET /metrics` 输出 Prometheus 文本；`GET /api/v1/system/observability` 返回指标清单、OTLP 配置状态、Worker 心跳与权威 Outbox 状态，不返回密钥或配置值。
- Worker 定期向 Redis 写有 TTL 的非权威心跳；API 从 PostgreSQL 查询 Outbox 与持久化状态。Redis 不可用只产生诊断降级，不改变 PostgreSQL 权威状态。
- OTLP HTTP 导出为可选、限长队列、批量且 fail-open；未配置时使用 Null exporter。Compose `observability` profile 锁定 OTel Collector、Jaeger 和 Prometheus 镜像并只暴露 loopback 端口。

## 韧性与安全基线

- timeout、有限 retry、指数 backoff、circuit breaker、bulkhead/并发上限和 rate limit 统一从 `RuntimeSettings` 读取并校验，不在调用点散落常量。
- 对象存储包装器记录成功/失败指标并将超时、熔断和存储错误映射为稳定的可诊断错误；失败不删除数据库元数据。
- Worker 在队列、Outbox relay 或心跳存储不可用时记录稳定 error code 并继续有限重试；权威任务、租约和 Outbox 仍在 PostgreSQL。
- `scripts/security_checks.py` 无需凭据或网络即可检查 Python/Node 精确版本与 lockfile 完整性、容器镜像锁定、`no-new-privileges`、无状态工具只读根文件系统、loopback 网络暴露、10 MiB 上传上限、`.env` 忽略和 Compose 不内嵌 Secret。
- `infra/compose.yaml` 为基础设施和观测容器设置资源/日志边界；工具与观测容器使用只读根文件系统和临时 `/tmp`。
- 初始 SLI/SLO 与告警只作为框架基线，未用技术夹具数据宣称生产达标。
