## 本阶段变更

### 领域、策略与公共契约

- 新增 `modules/identity`，包含 `User`、`Workspace`、`Membership`、`ServiceIdentity`、固定 `Role`、动作+资源 `Permission`、控制请求和人工批准模型。
- 固定 `OWNER`、`EDITOR`、`VIEWER`、`SERVICE` 四个角色和 `identity-rbac-v1` 策略。`SERVICE` 的显式授权只能与硬上限取交集，不能管理成员、转移所有权、决定审批、管理功能开关或应用 Evolution。
- 新增 `IdentityProvider`、`IdentityReader`、`AuditRecorder`、`ControlRequestStore`、`RateLimiter` 与 `UploadSecurityPolicy` 端口；公开边界不暴露 ORM Model。
- `SecurityContext` 在请求链中通过 ContextVar 传播 actor、actor kind、workspace、可选 project、权限快照、策略版本和关联 ID，并提供仅供受信任任务信封使用的序列化/恢复契约。

### 身份提供方与配置

- `OidcJwtIdentityProvider` 保持 decoder-neutral，校验签名解码结果的 issuer、audience、expiry、subject、actor kind 和 ServiceIdentity ID；错误统一映射为稳定的 `authentication_required`。
- 默认 `RejectingIdentityProvider` 拒绝所有凭据，不会静默回退为本地身份。
- `DevelopmentIdentityProvider` 只有在 `ACCOS_DEV_IDENTITY_ENABLED=true` 且 token、actor UUIDv4、workspace UUIDv4 全部显式配置时才启用，并通过常量时间比较 token。
- 生产环境启用开发身份会在应用监听端口前以 `configuration_error` 失败；日志安全摘要不会返回开发 token。

### 授权、审计与创作者控制

- `AuthorizationService` 先校验 Workspace/Project scope，再检查显式 permission；未知、缺失和跨 scope 全部失败关闭。
- 允许、权限不足、跨 scope、审批主体非人类、请求人自批、请求不存在及非 pending 决定均写入明确的审计结果和稳定 reason code；审计不可用时操作不会继续。
- Feature Flag、Evolution、Agent 与 Tool 的权限均由同一 `AuthorizationService` 判定，能力状态不能替代授权。
- 所有权转移、导出、归档和删除只创建 `ControlRequest`。高影响决定要求另一名具备 `approval:decide` 的人类 actor；每个请求只能决定一次，本阶段没有物理删除执行器。
- API 中间件为全部 `/api/v1/` 路径强制 Bearer 身份和规范 `X-Workspace-ID`；端点仍需声明资源与 permission。失败返回稳定 401/403，前端可见性不影响后端判定。

### 持久化与迁移

- 新增 Alembic revision `0002_identity_security`，创建 identity users、workspaces、memberships、service identities、control requests、human approvals 和 audit events 七张 identity-owned 表。
- 成员、ServiceIdentity、控制请求、批准与审计查询全部显式带 Workspace scope；双 Workspace 真实 PostgreSQL 测试证明读取和写入隔离。
- `audit_events` 和 `identity_human_approvals` 没有应用层更新/删除端口，并由 PostgreSQL trigger 拒绝 UPDATE/DELETE。
- 审计 payload 只允许 `operation_code`、`state_code` 两类最多 100 字符的稳定码；任意正文、password、token 和未知 metadata 被丢弃。结构化日志继续递归脱敏敏感键和 URL 凭据。
- 当前开发库已完成 `0001 → 0002 → 0001 → 0002` 实际迁移验证，处于 `0002_identity_security (head)`，`alembic check` 无 schema 漂移。06 身份/审计表为空，没有保留冒烟测试夹具。

- 响应统一加入 `Cache-Control: no-store`、CSP、Permissions Policy、Referrer Policy、`nosniff` 和 frame deny 安全头。
- 上传策略和限流端口已经建立，当前适配器失败关闭；真实上传检查留给执行 07，分布式限流预算留给执行 22。

- ESLint 忽略本地 Python/Node 验证缓存，避免扫描受限缓存目录影响前端门禁。

## 反向安全用例

- VIEWER 写 Workspace/Project、EDITOR 转移所有权、SERVICE 权限提升全部拒绝。
- 跨 Workspace 与不匹配 Project scope 的读取/授权拒绝。
- 未授权操作在真实数据库中只产生脱敏拒绝审计，不产生 ControlRequest 或 Outbox 副作用。
- 普通数据库会话更新/删除审计或人工批准触发 append-only 数据库异常。
- 请求人自批、ServiceIdentity 审批、重复决定和不存在的控制请求全部拒绝并有明确审计 reason code。
- 有效、过期、错误 audience、错误 issuer/claims 和错误签名 JWT/OIDC 契约均已覆盖。
- 未认证 API、错误 Workspace header、开发身份默认关闭和生产环境误启用开发身份全部失败关闭。
