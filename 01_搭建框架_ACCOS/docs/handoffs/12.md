## 本阶段变更

### 统一记忆模型与端口

- 新增 `modules/memory`，公开单一 `MemoryRecord` / `MemoryLink`；scope 固定为 working、session、project、universe、creator、experience、wisdom，type 保持可扩展小写标识，两个维度可独立过滤。
- Record 保存 workspace/project/universe/creator anchor、valid/observed time、importance、confidence、公开 provenance 引用、逻辑版本、current/status 与 retention rule。
- 领域与数据库双重约束 canonical anchor：working/session/project 只能有非空 `project_id`；universe 只能有 `universe_id`；creator/experience/wisdom 只能有 `creator_id`。不能用空项目键绕过授权。
- 公开 `MemoryWriter`、`MemoryRetriever`、`MemoryRanker`、`MemoryCompressor`、`RetentionPolicy`、`ConflictResolver`、`MemoryRepository`、`MemoryProjection` 和 `ContextPackageReader` 端口。

### 授权、排序与跨项目边界

- `MemoryAccessPolicy` 在 Repository 查询前计算 allowed anchors。当前项目自动获得 working/session/project；actor 只自动获得自己的 creator/experience/wisdom；其他 Universe/Creator anchor 必须有目标项目活动 grant。
- 项目 scope 永不跨项目召回。无 Universe/Creator grant 时对应记录召回为零；有 grant 时仅开放该 anchor 对应的 scope。未经授权的记录 ID 不出现在 omission 中，只返回通用 `anchor_unavailable`。
- 首期 `FakeSemanticMemoryRanker` 离线运行，语义贡献固定为零；排序由 scope、valid time、importance×confidence、保留降权、来源等级、observed time 和 UUID 决定，结果可重复。真实语义排序未来只能通过同一 Ranker 端口，并继续位于授权过滤之后。

### Scope / Type 与保留矩阵

| Scope | canonical anchor | type | 默认可用策略 | 跨项目规则 |
|---|---|---|---|---|
| working | project_id | 任意合法 type | TTL | 禁止 |
| session | project_id | 任意合法 type | TTL / decay | 禁止 |
| project | project_id | 任意合法 type | keep / decay | 禁止 |
| universe | universe_id | 任意合法 type | keep / decay | 显式 Universe grant |
| creator | creator_id | 任意合法 type | keep | 本人或 Creator grant |
| experience | creator_id | 任意合法 type | decay / keep | 本人或 Creator grant |
| wisdom | creator_id | 任意合法 type | keep | 本人或 Creator grant |

| Retention | 行为 | Context omission | 物理删除 |
|---|---|---|---|
| keep | 分数不变 | 无 | 否 |
| ttl | 到期排除 | `ttl_expired` | 否 |
| decay | 按半衰期确定性降权 | 无 | 否 |
| archive policy | 排除 | `retention_archived` | 否 |
| 手工 forget | 状态归档并记事件 | `archived` | 否 |

valid time 另产生 `not_yet_valid` / `no_longer_valid`。所有“遗忘”都是降权或归档，没有 Memory 物理删除用例。

### 压缩、冲突与 Context Package

- 确定性 compressor 只生成有界技术夹具摘要记录，并创建 `summary_of` links；来源版本与 provenance 完整保留。
- 冲突写入 `candidate` 版本与 `MemoryConflict`，候选决议固定为 keep current / accept candidate。接受时显式先撤销旧 current 再激活候选，避免 PostgreSQL 部分唯一索引受 flush 顺序影响；拒绝时归档候选。
- Context Builder 输入任务引用、项目、scope/type 许可、字符预算和可选 token 预算；token 使用固定 `ceil(chars/4)` 技术估算。任何 package 均满足两个已配置预算，整项超限时返回 `budget_exceeded`。
- Context Package 持久保存 allowed anchors、排序内容、每条 provenance、机器可读 omission、预算使用和 SHA-256；`memory_context_package_id` 写入不可变 AgentContextSnapshot。不存在、格式错误或 scope 不匹配的引用以 `CONTEXT_PACKAGE_INVALID` 拒绝。

### PostgreSQL、Redis 与组合根

- Alembic `0008_memory_context` 新增六张表：`memory_records`、`memory_links`、`memory_grants`、`memory_conflicts`、`memory_context_packages`、`memory_events`，并为 Agent 快照增加 package 外键。
- Link、Context Package 与 MemoryEvent 有数据库 append-only trigger；冲突决议和 soft archive 追加事件。一个 logical memory 由部分唯一索引保证至多一个 current。
- `RedisMemoryProjection` 只保存 Working/Session 的 record UUID 列表并设置 TTL，不保存内容或事实；每次操作关闭客户端。`MemoryProjectionRebuilder` 使用项目 anchors 从 PostgreSQL 重建，缓存清空不影响事实。
- 组合根公开 `MemoryServices(service/context_builder/repository/projection/rebuilder)`；API 使用主连接，Workflow/Agent 通过独立 NullPool 仓储验证同库 Context Package。
