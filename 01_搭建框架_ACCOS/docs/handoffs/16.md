## 本阶段变更

### `/api/v1` 入口与公共契约

- 新增 `entrypoints/api/v1` 的 dependencies、schemas、mappers 和 router；应用工厂挂载 v1 Router，同时保持 `/live`、`/ready` 语义。
- 中间件从 Bearer credential 与服务端 User/Membership/ServiceIdentity 建立不可变身份上下文。统一依赖核对 Workspace header/path、按路由模板限流，并禁止客户端伪造 actor、membership、permission 或 scope。
- 错误固定为 `ErrorEnvelope`，稳定覆盖 400、401、403、404、409、415、422、428、429、500、503；未知异常不返回内部堆栈、对象键或密钥。
- 固化不透明 cursor、1–100 limit、有界过滤/排序、UUID/RFC 3339 时间、关联 ID 回写、安全 Header、强 ETag/`If-Match`、幂等键、429 `Retry-After` 与 202 `AsyncOperationReference` schema。
- `GET /api/v1/identity/context` 保留为受保护的弃用兼容入口，发送 `Deprecation: true` 和指向 `/api/v1/identity/me` 的 successor `Link`。

### 第一批资源

- Identity：当前可信 actor、Workspace、权限与策略版本。
- Workspace/Membership：只读当前选择的 Workspace 与分页 Membership。
- Project：创建、分页列表、读取、更新 settings、归档；创建支持 Workspace-scoped 幂等键，变更支持乐观版本。
- Artifact/Revision：Artifact 创建/列表/读取与 Revision 创建/列表；归属和版本由 Project 应用服务验证。
- Asset：创建/内容哈希去重、分页列表、读取、新版本、下载和保留期内标记删除；继续经过上传策略、扫描端口、对象存储补偿、审计和 Outbox。
- System：受鉴权的聚合 readiness；公开 `/live` 与 `/ready` 保持原契约。

API 没有直接访问仓储；写路由调用既有应用服务，因此 UoW、审计、Outbox 和 correlation ID 继续贯通。公开 DTO 没有导入 SQLAlchemy Model。

### 查询与持久化

- Identity 新增 Workspace/Membership 查询应用服务和只读端口，SQL adapter 固定 Workspace scope。
- Project、Artifact、Revision 与 Asset repository 增加稳定分页、过滤和排序，查询使用确定性的 ID 次排序键。
- Project/Asset 应用服务补充只读列表/读取入口和显式 version conflict current version；跨 Project 子资源统一拒绝。
- 组合根装配 IdentityQueryService 与进程内限流器；原有领域所有权和模块依赖方向不变。

### OpenAPI 与 TypeScript 客户端

- `scripts/export_openapi.py` 从同一应用工厂生成规范化 `packages/api-client/openapi.json`；`openapi.snapshot.json` 是 v1 兼容基线。
- `scripts/check-openapi.mjs` 检查 OpenAPI 3.1、鉴权、Workspace header、错误响应、资源范围和公开 schema 泄漏，并比较操作、响应、必填字段及枚举；`--self-test` 临时删除操作并验证检查必然失败。
- `scripts/api-client.mjs` 用锁定的 `openapi-typescript` 生成 `src/generated/schema.ts`，check 模式连续生成两次并与仓库文件逐字节比较。
- `@accos/api-client` 用 `openapi-fetch` 提供带类型的客户端，只手写 base URL、Bearer、Workspace header 和可注入 fetch；请求/响应 DTO 全部来自生成类型。
- OpenAPI 与 generated 目录明确排除 Prettier/ESLint 自动改写，但继续受快照、生成可重复性和 strict TypeScript 约束。
