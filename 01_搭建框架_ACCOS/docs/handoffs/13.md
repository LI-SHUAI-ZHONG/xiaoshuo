## 本阶段变更

### 四个领域所有者与状态不变量

- `CreativeContainer` 统一空聚合根元数据；公开引用为 `creative://<owner>/<uuid>`。
- `CreativeRecord` 只含 logical/version、scope、typed ID references、opaque source URI、顺序、状态、因果及决议元数据，没有正文或可伪装成业务内容的自由负载。
- `logical_id + record_version` 唯一；只有 `status=current` 的已批准版本可设 `current=true`。
- 所有新结构/状态先创建 `proposal/current=false`。显式批准后才成为 current；拒绝变为 rejected；批准同 logical ID 的新版本时旧 current 先变为 superseded。
- 容器版本作为乐观并发锁。错误 `expected_container_version` 返回既有并发冲突，不覆盖新状态。
- 读写统一经过 Project 公开仓储、AuthorizationService 和 workspace/project scope；归档项目允许历史读取但禁止新增、提案与审批。

### 存储、事件与隔离

- Alembic `0009_creative_domains` 新增 `creative_containers`、`creative_records` 两张表。
- `owner` 数据库约束固定为 novel/world/character/creator。Record 到 Container 的复合外键同时匹配 aggregate ID、owner、workspace 和 project，不能跨所有者或跨项目挂接。
- 部分唯一索引保证一个 logical record 最多一个 current，并保证同 workspace/project/owner/causation ID 最多一个影响 proposal。
- 创建、提案和审批/拒绝与既有事务 Outbox 同事务写入；公开事件 payload 只有版本、类型、decision、causation/source event 等技术元数据。
- ORM 仅位于 `adapters/creative`；公开 `creative.public` 不暴露 SQLAlchemy 类型。

### 双向影响防循环

- WorldEvent 到 Character 只能产生 `BehaviorProposal`；CharacterAction 到 World 只能产生 `ImpactLink` proposal，均不直接改 current 或 Canon。
- `source_event_id` 与 `causation_id` 必须成对保存。同一因果链在同一目标 owner 上重放时返回既有记录和 `created=false`，不追加重复副作用。
- proposal 事件不是 WorldEvent/CharacterAction，正常路径不会反向触发；即使误重放同一 causation，也被唯一约束截断。

### 扩展、Creator 与 Workflow

- 建立 Concept、Theme、Plot、Emotion、Style、Chapter Generator、World Simulation、Character Behavior、Creator Learning 九个扩展 Port，以及政治、经济、科技、文化四类世界组件 Port。
- 组合根默认给全部可选端口装配 Null 实现，固定返回 `NOT_CONFIGURED`；核心项目、工作流和持久状态仍可用。
- Creator Profile 固定绑定当前 actor 的 Creator reference。`PreferenceSignalIngestPort` 与 `creative.creator.preference-signal-ingested.v1` 仅作 schema 占位；Null 端口不保存信号，也没有订阅尚未实现的 Feedback。
- `CreativeCatalog` 和 `CreativeWorkflowExecutor` 通过公开 `creative://<owner>/<uuid>` 引用解析四类容器，不读取 Creative 私有表；新增确定性的 `creative_reference` Workflow 定义。
