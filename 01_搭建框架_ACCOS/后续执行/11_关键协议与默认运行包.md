# 关键协议与默认运行包

这里补齐施工时不能再含糊决定的细节。字段允许兼容增加，不能删去不变量。具体JSON Schema/Pydantic/TypeScript由24定版，后续按同一schema生成，不分别手写三套。

## 1. 核心协议与公共端口

| 契约 | 必填信息 | 调用与校验 |
|---|---|---|
| `WorkBrief` | 原始思想版本、目标/读者/长度区间、主题、禁限、创作模式、预算、缺项 | 用户目标与模型推断分字段；31负责，28仅消费 |
| `CreativePayload` | entity_type、schema_version、revision/branch、typed payload、来源 | 按genre/world/character/scene等discriminator校验；拒绝任意无结构JSON |
| `StageRequirement` | artifact_type、scope/branch、accepted_required、min_schema、mandatory、freshness | 依赖解析器由服务端检查；空库允许生成/手工补齐前置，不能凭空pass |
| `StepInputManifest` | definition/prompt/model/policy版本、resolved refs/hash、grant/consent版本、budget reservation | 运行开始冻结；在途不偷换latest；过期创建linked Run |
| `ContextPackage` | sections、priority、来源span、mandatory、tokens、omitted及原因、input manifest | 唯一Memory.ContextBuilder组装；供应商前最后复核权限与预算 |
| `ReadReceipt` | run/step、source revision/hash、实际装入的section/span/bytes/tokens、input digest | 证明信息进入请求，不证明模型理解。固定mandatory引用不能仅记ID未读正文 |
| `ModelInvocation` | typed messages/content refs、output schema、tools、预算、operation_key | 27新增v2内容协议；旧metadata-only协议保留兼容。模型不能指定actor或授权 |
| `AgentTask/Result` | task_kind、input/context、allowed tools、limits；artifact refs、findings、next-step proposal | Agent不写数据库；tool调用仍过网关；planner返回受限DAG，不执行任意代码 |
| `GenerationRequest` | 操作类型、scene、基线revision、选区稳定锚点、锁段、候选数、文体/视角 | 输出partial/complete分开，正文放资产；不把流式chunk当最终结果 |
| `CheckReport` | 检查revision/hash、checker/rubric版本、维度、证据span、not_checked、发现 | 硬规则与文学建议分开；缺模型不能默认审稿通过 |
| `AcceptanceBatch` | 正文版本、已审事实候选、expected_versions、审批/手工审阅、检查快照 | 先提取候选再确认提交；正文/事实/审批/Outbox一致，后置投影有水位 |
| `ChangePackage` | target类型/旧新版本、样本集/评价、权限diff、迁移、回退、hash | 配置包与代码包分发布器；必须真实切换指针，不只更改proposal状态 |
| `CapabilityStatus` | implementation/configuration/health/verification/data五维、缺项/修复链接 | 旧flag只决定展示/启用，不代表实现或已测试 |

公共端口至少包括：`ContentRepository.get/put_snapshot`、`DependencyResolver.resolve`、`ContextBuilder.build/explain`、`Provider.invoke/stream/embed`、`BudgetLedger.reserve/settle/reconcile`、`WorkflowExecutor.execute/compensate`、`CreativeReadPort.snapshot_at`、`AcceptanceWriter.prepare/apply`、`ProjectionReader.watermark`、`PackagePublisher.promote/rollback`。模块导入其他模块的public/port，不导入其私有ORM。

24仅冻结接口和owner，不提前实现所有后续模块。25创建Creator身份anchor；Universe的授权引用沿用既有Memory anchor协议，39绑定真实IP聚合。30没有Universe时返回无该scope数据，不能造虚构宇宙。36不得重复创建另一个作者身份表。39复用已公开anchor映射，不追改记忆主键。

## 2. 正文、协作与正式版本谁说了算

26的单人模式：浏览器编辑→自动保存WorkingCopy（base_version/client_change_id/If-Match）→生成不可变Revision。正文版本包含编辑器JSON、文本投影、schema、ContentRef。中文输入法composition结束再触发可提交变更；IndexedDB按用户/工作区/项目/文档/分支隔离，退出时提示处理未同步草稿，避免下一身份读取。

41增加`editing_mode=solo|collaborative`和`document_epoch`。同一epoch只有一条写入通道：solo走REST CAS；collaborative走Yjs updates，禁旧REST整份覆盖。切换需要静止检查、服务端快照、提高epoch和令牌刷新；旧epoch客户端转冲突恢复。

协作端保存Yjs二进制update/snapshot、序号和hash；不能只保存JSON后每次重建Y.Doc，否则破坏合并历史。传输服务通过经身份签名的内部持久化端口写collaboration所有的表，不能绕过业务层直写projects正文。每次“已保存”是PG持久ack；广播已到不等于落盘。断线本地update带幂等ID重放，撤权后禁止继续写。

正式Revision生成协议：冻结document epoch和已持久seq→应用全部截至seq的update→转换/校验编辑器JSON→projects生成Revision→绑定collab snapshot和hash→解除冻结继续编辑。作者批准的是这个不可变Revision，之后的协作更改仍是草稿。AI改写始终是patch建议，基线不匹配则三方合并，不能覆盖正在协作的全文。[Hocuspocus持久化说明](https://tiptap.dev/docs/hocuspocus/guides/persistence)。

## 3. 写作理论的结构化落点

- GenreProfile六维固定为world/conflict/character/structure/emotion/language。`strength`表示单类型强度，不必相加100%；BlendPlan的`mixture_weight`在同一混合组归一。作者可设一主多辅、作用卷章、融合规则和明确例外，不以不科学的固定公式裁决好坏。
- StoryPlan包含theme、central_question、main_conflict、transformation、ending_state/open_questions。冲突类别覆盖自身/他人/组织/环境/规则/存在意义；每次事件有cause、actors、goal、choice、result、state_delta，支持多条并行故事线。
- ScenePlan五层为space/action/conflict/emotion/change，目的可为信息/冲突/人物/转折/情绪/铺垫。允许作者解释留白或非传统场景，不把理论建议误设为所有文学的绝对约束。
- WorldBible拆环境、文明、政治、经济、科技/力量、文化；人物六维是identity/personality/psychology/goals/relationships/growth，与类型六维完全不同。
- NarrativeProfile含POV、叙述者知识范围、时态/时间呈现、距离、信息披露策略；VoiceProfile是人物语言特征；StyleProfile是作者/作品表达。三者合成有明确优先级：本次作者指令→作品锁定风格→角色声音/POV约束→受权偏好建议。
- 三个时间轴：story_time（虚构历法含不确定区间）、narrative_order（章节/场景披露位置）、recorded_at（系统UTC）。角色知情来源、读者已知与世界真实状态分别建模。倒叙不等于穿帮。
- 作者样本不足时保留手工StyleProfile；需要文学检查但无模型时选择显式`manual_review`并记录审阅人/范围，不能把未检查改成passed。草稿可导出且明确标草稿；正式出版仍需接受快照。

## 4. 默认运行包必须可执行

`services/core/resources/`由wheel/Docker显式打包，不能仅存在源码目录。24定manifest规范，27建renderer/registry，后续各步填实。每个Prompt含：任务目标、合法输入、资料仅作数据、来源引用要求、不确定/缺项报告、输出schema、工具白名单、停止条件。模板不写用户故事，不用单句“你是专家”冒充完整协议。

| 包ID前缀 | 必须交付的通用任务模板 | 输出/使用步骤 |
|---|---|---|
| `director.*` | intent、plan、clarify、route、meeting_summary、replan | Brief/Plan/Decision；27–28 |
| `knowledge.*` | extract、normalize、abstract、translate、component_review、source_compare | Extraction/Component/Claim；29、35 |
| `memory.*` | summarize_scene/chapter/volume、extract_candidates、resolve_conflict | 摘要/事实候选/冲突提案；30、33 |
| `novel.*` | idea、genre_analysis、genre_blend、theme、outline、conflict、thread、foreshadow、scene | typed创作候选；31 |
| `world.*` | bible、rules、history、geography、civilization、scenario | 世界与模拟候选；32 |
| `character.*` | profile、psychology、motivation、relationship、growth、knowledge、voice、scenario | 人物候选和变化证据；32 |
| `writer.*` | draft_scene、continue、expand、compress、dialogue、pov、style、targeted_patch | 完整正文/patch与来源；33 |
| `review.*` | continuity、causality、character、structure、style、reader、committee、revision_plan | 有证据Finding/Report；33 |
| `research.*` | question_plan、team、claim_extract、verify、synthesize、market_report | 问题/证据/报告；35 |
| `creator.*` | revision_pair、preference_candidate、style_profile、decision_model、growth_plan | 可撤回作者模型候选；36 |
| `evolution.*` | observe、diagnose、hypothesis、candidate、evaluate、retrospective、incubate | 实验/改进包；37 |
| `extension.*` | capability_gap、tool_spec、module_blueprint、code_change、review_package | 受限代码/依赖/迁移/测试包；38 |
| `adaptation.*` | comic、screenplay、audio_script、game_quest/dialogue、synopsis、promotion | 改编schema/素材包；39 |
| `media.*` | visual_profile、shot_plan、audio_plan、scene_3d | 媒体计划，不直接用文字当媒体文件；40 |

通用rubric至少包含结构、因果、世界/时间/人物连续性、信息权限、语言、节奏、主题、人物动机、风格/声音、读者理解与期待。每维定义0–4锚点与`not_checked`，证据不足不计高分；总分权重可配置，硬违规不被平均数冲掉。模型自评与人工评分分来源。

默认工作流包：资料导入转译、从零建书、下一章、局部修订、全书一致性检查、设定变更影响、世界/人物模拟、自主研究、作者学习、创意实验、配置进化、插件代码实验、作品导出/导入、跨媒介、多模态、目录包安装。准备阶段支持人物优先/世界优先/悬疑真相优先，最终正文节点共用依赖门。每个定义有版本、owner、节点IO、执行器、审批/预算、重试/补偿与退出条件。

## 5. 进化、沙箱和结算的提交边界

配置晋升：固定基线与候选→固定评估样本/留出集→硬约束、失败率、质量和成本比较→证据不足则停止→满足用户预授权或真人批准→CAS切换active版本指针→只影响新Run→监控窗口退化即切回。不能通过删难样本、改评分者或换阈值制造提升。首次无历史样本时可在隔离合成集验证机制，不能称作者效果已改善。

代码晋升：Agent仅产出ChangePackage，独立受信任发布器在真人批准后安装。沙箱最小权限、无生产secret/数据库/宿主路径/socket、CPU/内存/时间/输出限额、只允许批准网络、临时空间销毁。依赖下载与执行阶段分离；无合格隔离运行时则CONFIG_REQUIRED，不用普通子进程替代。权限、ownership、预算上限和审批政策不属于自动优化目标。

生成模块的包类型明确分为tool、agent、prompt、workflow、knowledge/content、ui-module、core-change。前五类经各自schema/权限入口安装；ui-module仅安装经审查并构建的声明式注册/静态产物，不在Studio执行任意上传脚本；core-change含迁移/接口/测试/文档，必须走独立维护发布器。它们共用包完整性与审查机制，不把所有插件都降为“只有工具函数”。

结算：订单已支付须由服务端验证的提供商事件或受审的手工对账确认；浏览器跳回success不记账。币种最小单位整数/Decimal、比例和舍入规则固定，先记录应收/平台费用/作者应付，实际transfer成功后才记已付；退款和争议用反向分录与对应transfer reversal，不删账。外部调用operation_key、回调event_id均持久去重，乱序不能回退终态。真实结算由可用商户能力和授权决定。[Stripe webhook](https://docs.stripe.com/webhooks)、[Connect分账](https://docs.stripe.com/connect/separate-charges-and-transfers)。

## 6. 运行与保护约束

下载器区分受权本地模型端点和互联网抓取。研究URL禁止访问loopback、私网、云元数据、file://等；每次DNS解析/重定向复核，限字节/时间/内容类型。作者配置的本地模型是单独管理员白名单，不能通过“允许本地模型”放开网页抓取SSRF。

上传与包导入防路径穿越/压缩炸弹、HTML脚本、外部资源引用；解析器/媒体转换在受限任务执行。私密项目在发请求前强制出站策略；fallback不能把本地限定资料发到云端。

正文、思维记录、API key不进日志；审计存actor/operation/ref/hash/版本/结果/关联ID。用户查看运行解释得到输入依据和决策摘要，不获得模型私有推理。加密/删除/审计保留遵循明确政策；原始创作文本在用户主动删除前受版本和备份保护。
