# 执行 01：仓库初始化与架构契约

## 任务目标

把 `D:\搭建` 从资料目录初始化为可持续开发的 ACCOS 单仓库，并先固化模块边界和关键架构决策。此步不安装完整业务依赖、不写业务模块。

## 前置条件

- 阅读 `00_执行总览与使用规则.md`。
- 解析仓库根：当前目录必须同时直接包含 `改进资料.txt` 与 `执行.txt`；不满足就停止，禁止新建嵌套的第二层项目目录。
- 确认 `改进资料.txt` 与 `执行/` 目录只读保留。
- 检查目录是否已有用户文件；不得覆盖未知内容。
- 本任务没有上一份 handoff 或上一阶段测试；只需记录执行前基线。

## 本阶段实施

1. 如尚未存在，初始化本地 Git 仓库；记录初始状态，不执行远程推送。
2. 创建目标骨架：`apps/studio`、`services/core`、`packages/api-client`、`packages/ui`、`infra`、`tests/contract`、`tests/e2e`、`docs/adr`、`docs/architecture`、`docs/handoffs`、`docs/runbooks`、`scripts`、`.vscode`。
3. 创建根级 `README.md`、`.gitignore`、`.gitattributes`、`.editorconfig`、`.env.example`。忽略密钥、环境文件、缓存、构建物、数据库卷和本地对象；保留 lockfile。
4. 写入以下 ADR，状态标为 `Accepted`：
   - `0001-modular-monolith-and-worker.md`
   - `0002-data-and-storage.md`
   - `0003-rest-openapi-and-sse.md`
   - `0004-creator-ownership-and-human-approval.md`
   - `0005-provider-and-plugin-boundaries.md`
5. 写入架构文档：系统上下文、容器图、模块依赖规则、数据所有权矩阵、功能开关策略和“何时允许拆微服务”的可测条件。
6. 明确依赖方向：`entrypoints -> application -> domain <- ports <- adapters`；领域模块不得直接导入具体数据库、Redis、S3、模型 SDK 或前端代码。
7. 在 `docs/handoffs/01.md` 记录完成内容、目录树、未决问题和回滚方式。

## 必须固化的模块名称

后端 `modules` 预留以下边界，暂不批量创建无意义空文件：

`identity`、`projects`、`assets`、`workflows`、`models`、`tools`、`agents`、`knowledge`、`memory`、`creative`、`consistency`、`quality`、`feedback`、`evolution`。

`creative` 下未来包含 `novel`、`world`、`character`、`creator`。每个模块只通过公开 application/port 契约协作，禁止互相读取私有表。

## 本阶段不做

- 不创建示例小说、角色、世界或演示项目。
- 不选择云厂商、购买服务或配置远程仓库。
- 不提前拆微服务，不引入 Kubernetes、Service Mesh、Neo4j 或独立向量数据库。
- 不生成大量只有 `pass` 的模块文件。

## 验证

- 目录树与 `00` 中目标一致，原资料和执行包仍存在且内容未变。
- Git 状态只包含本阶段预期的新文件。
- ADR 对技术选择、替代方案、后果和未来拆分条件都有说明。
- 依赖图中不存在循环；数据所有权矩阵覆盖所有预留模块。
- 所有文档中的路径均为仓库相对路径，不写死本机盘符。

## 完成标准

- 新成员仅阅读 `README`、ADR 和架构文档即可说清五层蓝图如何映射到此仓库。
- `docs/handoffs/01.md` 标记 `PASS`，并列出供执行 02 使用的固定技术基线。
