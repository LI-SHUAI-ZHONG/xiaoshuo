# 执行 06：身份、权限、安全与审计

## 任务目标

从第一批业务数据开始落实“创作者拥有最终控制权”：建立身份提供方边界、Workspace 成员关系、默认拒绝的 RBAC、资源作用域、不可静默绕过的审计链。

## 前置条件

- 执行 05 数据层与迁移测试通过。
- `0004-creator-ownership-and-human-approval.md` 已接受。

## 本阶段实施

1. 创建 `identity` 模块，领域实体至少包含 `User`、`Workspace`、`Membership`、`Role`、`Permission`、`ServiceIdentity`。
2. 固定首期角色：`OWNER`、`EDITOR`、`VIEWER`、`SERVICE`；权限以动作+资源表示，不在前端硬编码授权逻辑。
3. 定义 `IdentityProvider` 端口：生产面向 OIDC/JWT 验证；本地开发提供显式启用的开发身份适配器。开发身份在生产模式必须拒绝启动。
4. 在请求上下文与后台任务上下文传播 actor、workspace、权限快照和关联 ID。
5. 实现资源级授权服务和 API 中间件；所有受保护路径默认拒绝。仓储查询必须带 workspace/project scope，不能依靠前端过滤。
6. 创建 append-only `audit_events`：actor、动作、资源、结果、策略版本、关联 ID、时间；payload 脱敏，禁止记录正文和密钥。
7. 定义所有权、导出、归档、删除请求和人工批准协议；本阶段只建立状态与授权，不执行不可恢复的数据删除。
8. 加入限流端口、上传安全策略端口、密钥脱敏和安全响应头；具体上传校验在执行 07。
9. 编写安全威胁模型与 `docs/handoffs/06.md`。

## 必须覆盖的反向用例

- VIEWER 写入、EDITOR 改所有权、SERVICE 提升权限、跨 Workspace 查询全部拒绝。
- 未授权请求不能产生部分数据、Outbox 或审计以外的副作用。
- 审计记录不能被普通成员更新或删除。
- Feature Flag、Evolution、Agent 和 Tool 都不能绕过同一授权服务。

## 本阶段不做

- 不接真实企业身份平台，不创建默认管理员密码。
- 不实现计费、组织邀请邮件或用户画像。
- 不把用户行为分析默认视为已同意。

## 验证

- 本地开发身份只能在开发配置中工作；生产配置启用时启动失败。
- JWT/OIDC 端口的有效、过期、错误受众和错误签名契约测试通过。
- 两个 Workspace 的数据查询、写入和审计严格隔离。
- 权限失败返回稳定错误码；前端是否隐藏按钮不影响后端拒绝。
- 关键允许/拒绝动作都有审计事件，且日志与审计均已脱敏。

## 完成标准

- 所有后续模块可复用统一 actor/授权/审计契约。
- `docs/handoffs/06.md` 标记 `PASS`，附权限矩阵和威胁模型链接。
