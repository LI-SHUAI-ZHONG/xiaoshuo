# 执行 11：知识采集、检索与研究骨架

## 任务目标

建立可追溯、可重建的知识管线：资产引用进入提取、规范化、分块、嵌入、索引、验证和检索状态机；每个结果都保留来源。只使用技术测试夹具和 Fake Embedder。

## 前置条件

- 执行 07 资产链路、执行 08 工作流、执行 09 Fake Embedding、执行 10 Agent 契约均通过。

## 本阶段实施

1. 创建 `knowledge` 模块：`KnowledgeSource`、`Document`、`DocumentVersion`、`Chunk`、`EmbeddingRef`、`Citation`、`VerificationStatus`、`IngestionRun`。
2. 固化状态机：uploaded -> extracting -> normalized -> chunked -> embedded -> indexed -> verifying -> ready；任一步失败进入带阶段信息的 failed，并可受控重试。`VerificationStatus` 另行区分 verified、unverified、not_configured、rejected：只有策略要求验证且结果未通过时才阻止 ready；策略允许无验证器时可 ready，但必须显式标为 not_configured，绝不能伪装 verified。
3. 定义 `Extractor`、`Normalizer`、`Chunker`、`Embedder`、`VectorIndex`、`Retriever`、`VerificationProvider`、`GraphProjection` 端口。
4. 首期只实现确定性的纯文本/Markdown 测试提取器与 Fake Embedder；PDF、DOCX 和外部数据库使用 `NOT_CONFIGURED` 适配器和契约测试。
5. 使用 pgvector 建立按 workspace/project/source/version 隔离的索引；删除/更新使用可重建投影，不破坏原始资产和来源元数据。
6. 建立检索请求和结果契约：查询、过滤、top-k、分数、chunk、文档版本、来源、可信状态；空结果必须是正常结构化结果。
7. 建立最小关系边投影到 PostgreSQL，表达来源/引用/派生关系；不引入独立图数据库。
8. 定义研究工作流接口：问题 -> 计划 -> 资料请求 -> 验证 -> 报告引用；当前只返回技术状态，不访问外网。
9. 加入重复上传、内容哈希、重建索引、过期版本和来源隔离测试；写入 `docs/handoffs/11.md`。

## 本阶段不做

- 不上传或内置真实书籍、论文、世界观资料或知识包。
- 不联网抓取，不把模型常识标为验证来源。
- 不实现专业学科 Agent、知识转译内容或生产级分块/排序算法。

## 验证

- 同一资产版本重复提交只形成一个有效索引；失败重试不重复 chunk。
- 技术测试文档能经过完整状态机并返回带来源的固定检索结果。
- 跨 Workspace/Project 检索为零结果且无信息泄露。
- 更新文档版本后，新旧引用可区分；索引可从原始资产和元数据重建。
- 空检索、解析器未配置、验证器未配置、验证拒绝、嵌入失败和索引不可用均返回稳定且互不混淆的状态。
- Fake 与 pgvector 适配器通过共享契约测试。

## 完成标准

- “测试资产—知识管线—带来源检索”可由 Workflow 驱动并在中断后恢复。
- `docs/handoffs/11.md` 标记 `PASS`，记录状态机、索引隔离和重建流程。
