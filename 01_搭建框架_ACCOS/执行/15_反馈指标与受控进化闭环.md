# 执行 15：反馈、指标与受控进化闭环

## 任务目标

建立可观测反馈、实验、问题诊断和改进提案框架，并把“自我进化”限制为只读观察、离线分析、模拟验证和人工审批，禁止系统自行改代码、权限、数据结构或部署。

## 前置条件

- 执行 14 的检查、提案和人工审批模型通过。
- 模型、Agent、Memory、Workflow 都已产生结构化用量和状态事件。

## 本阶段实施

1. 创建 `feedback` 模块，支持四类显式来源：user、system、creative-result、behavior-consented。行为类默认关闭，必须记录同意版本与撤回状态。撤回后立即停止采集；按保留策略删除或不可逆匿名化原始行为事件，给派生指标/实验样本写 tombstone 并触发重算或排除。审计仅保留同意/撤回动作、策略版本和时间，不保留被撤回的行为正文。
2. 定义 `FeedbackEvent`、`MetricDefinition`、`MetricPoint`、`DiagnosticFinding`、`Experiment`、`Variant`、`ImprovementProposal`。
3. 把经授权、满足同意策略的 Creator Preference/Decision 信号通过执行 13 的 `PreferenceSignalIngestPort` 送入 Creator；未同意、已撤回或不符合 schema 的事件不得接线，Creator 不反向依赖 Feedback 仓储。
4. 首期指标覆盖 Agent 成功/延迟/预算、Memory 召回状态、Workflow 完成/失败/恢复、API/Worker 健康；不采集正文原文作为默认标签。
5. 指标名称、单位、维度、保留期和敏感级别必须有注册表；拒绝无限高基数标签。
6. 创建只读 System Doctor：基于确定性阈值生成诊断 Finding，不直接修改模型路由、Prompt、Workflow 或配置。
7. 建立版本化实验协议：假设、指标、样本范围、起止、变体、结果和停止条件；本阶段只使用技术烟雾数据。
8. 创建 `evolution` 模块边界：Observer、Analyzer、Planner、SimulationEnvironment、VersionManager、SafetyController、EvolutionMemory。
9. 固定状态链：observed -> proposed -> simulated -> evaluated -> awaiting_approval -> approved/rejected -> externally_deployed -> verified/rolled_back。系统内部最多到 awaiting_approval。
10. SafetyController 使用不可变策略拒绝：改变所有权、关闭安全、提升权限、绕过批准、自动提交代码、自动部署、未经迁移改 schema。
11. 记录所有提案输入、算法/规则版本、模拟证据、批准 actor 和回滚引用；写入 `docs/handoffs/15.md`。

## 本阶段不做

- 不自动优化 Prompt、Agent、Memory 权重或 Workflow。
- 不采集未授权正文、隐私行为或真实作者画像。
- 不创建代码生成、自动 Git 提交、自动迁移或部署能力。

## 验证

- 同一技术故障能形成指标、诊断 Finding 和 Improvement Proposal，但配置保持不变。
- 未同意/已撤回的行为反馈不被采集或继续纳入实验；撤回前的原始事件和派生样本按策略完成删除/匿名化、tombstone 与重算，并留下不含行为内容的审计证据。
- 任何尝试修改所有权、权限、安全策略或绕过审批的 Proposal 被拒绝并审计。
- 状态机不允许从 proposed 直接到 deployed；只有授权 actor 可批准。
- 指标中不含密钥、正文、原始 Prompt 或高基数对象 ID。
- Evolution 模块只有公开提案接口，无文件写入、Shell、Git 或部署权限。

## 完成标准

- 反馈与进化形成“可观察、可建议、可验证、必须人工决定”的安全闭环。
- `docs/handoffs/15.md` 标记 `PASS`，附隐私默认值、状态图和不可变安全规则。
