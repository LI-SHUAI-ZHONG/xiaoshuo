# 执行 09：AI 模型网关、工具与插件边界

## 任务目标

让领域模块和 Agent 只依赖统一的模型/工具协议，建立能力注册、路由、预算、超时、重试、降级、权限与调用审计；默认使用确定性 Fake/Null Provider，绝不要求真实密钥。

## 前置条件

- 执行 08 的工作流恢复与幂等测试通过。
- 身份、审计、配置和关联 ID 契约稳定。

## 本阶段实施

1. 创建 `models` 模块，定义 `ModelProvider`、`ModelRequest`、`ModelResponse`、`ModelCapability`、`ModelPolicy`、`UsageRecord`、`ProviderHealth`。
2. 首期协议覆盖 text、embedding；为 image/audio/video/3d 建立 capability 枚举和 Null 适配器，不安装真实多模态 SDK。
3. 建立模型注册表与路由策略：能力匹配、允许名单、主/备 Provider、超时、有限重试、退避、熔断、并发限制、工作区预算、任务预算、最大 token/调用次数。
4. 实现确定性 Fake Provider，可按请求配置成功、延迟、超时、限流、失败、主备切换和固定用量；CI 默认只用 Fake。
5. 凭据由 Secret Provider 端口按 Provider 读取，禁止进入领域对象、数据库 payload、日志、错误或前端。
6. 创建 `tools` 模块：`ToolDescriptor`、输入/输出 schema、版本、所需权限、网络/文件/资源范围、超时、幂等属性和审计策略。
7. 实现 Tool Registry、Tool Executor 端口、Fake Tool 和权限拦截器；Agent 只能调用工作区和任务上下文明确授予的工具。
8. 建立插件 manifest 与加载协议：插件 ID、版本、能力、兼容范围、权限声明、签名/信任状态、启用开关；本阶段只加载仓库内测试插件。
9. 建立 Prompt/Policy 元数据版本协议，只存 ID、版本、校验和和状态；不填入正式 Prompt 内容。
10. 把模型和工具调用接入 Workflow Task、关联 ID、用量记录与审计；写入 `docs/handoffs/09.md`。

## 安全不变量

- Provider/Tool 失败不可自动扩大权限或取消预算。
- 重试和故障切换共享同一总预算；不能每次切换重置上限。
- 工具默认无网络、无 Shell、无任意文件系统权限。
- 未配置能力返回稳定 `NOT_CONFIGURED`，不得返回伪造成功数据。

## 本阶段不做

- 不接入真实 OpenAI/其他付费模型，不配置用户密钥。
- 不写系统 Prompt、写作模板、Agent 人设或生成内容。
- 不实现插件市场、远程插件下载或任意代码执行。

## 验证

- Fake Provider 的成功、超时、失败、限流、熔断、主备切换、预算耗尽均有测试。
- 所有 Provider 适配器遵守同一契约；领域与 Agent 包不导入厂商 SDK。
- 未授权工具、未知工具、schema 错误、超时和越权资源访问全部拒绝并审计。
- 日志、数据库、OpenAPI 和前端构建物中搜索不到测试密钥原文。
- 同一 Workflow 可追踪到 Model Call、Tool Call、用量和最终状态。

## 完成标准

- `framework_smoke` 可调用 Fake Model/Fake Tool 并受预算与权限约束。
- `docs/handoffs/09.md` 标记 `PASS`，列出协议版本、默认限额和故障策略。
