# 执行 23：集成测试、CI、发布与最终验收

## 任务目标

用一条不访问外网、不使用真实模型、不填充创作内容的纵向 E2E 证明五层骨架可运行；把安装、迁移、检查、构建、容器和恢复验证纳入 CI，形成 `v0.1-skeleton` 可交付基线。

## 前置条件

- 执行 01–22 的 handoff 全部为 `PASS`。
- 临时测试环境可从空卷启动；所有真实 Provider 与远期 Feature Flag 默认关闭。

## 本阶段实施

1. 建立分层测试：unit、architecture、integration、contract、migration、frontend component、Playwright E2E、backup/restore smoke；测试失败不得被重试掩盖。
2. 创建唯一最小 E2E 技术夹具，不含小说/世界/人物语义，跑通：
   - 本地开发身份进入 Workspace；
   - 创建空 Project；
   - 上传一个固定技术文本文件并完成 Fake embedding/带来源检索；
   - 写入最小技术 Memory 并构建受预算 Context Package；
   - 提交 `framework_smoke`；
   - Director -> Workflow -> Fake Agent -> Fake Model/Fake Tool；
   - 生成技术 Draft/Proposal 元数据；
   - Consistency/Quality 结构门禁；
   - 人工批准测试步骤；
   - 保存 Revision、Memory、审计、指标；
   - Studio 经 SSE 显示终态，刷新后仍一致。
3. 覆盖失败 E2E：主 Provider 失败并降级、知识为空、Memory 冲突待人工、非法 Canon 变更、Worker 中断恢复、重复请求幂等、跨 Workspace 拒绝、对象存储暂时不可用。
4. 建立 CI 阶段：依赖锁校验 -> secrets/dependency scan -> lint/format -> type -> unit/architecture -> migration -> integration/contract -> frontend build -> E2E -> container build -> 产物清单。
5. CI 使用 Fake Provider 与临时服务，不持有真实 AI key。缓存不能成为成功前提。
6. 构建 API/Worker/Studio OCI 镜像：固定 base、非 root、健康检查、SBOM/依赖清单、版本与源码 revision 标签；不推送、不部署，除非用户另行授权。
7. 创建 `docs/runbooks/first-run.md`：从全新检出、配置、启动基础设施、迁移、启动 API/Worker/Studio、运行 E2E、停止且保留数据。
8. 建立追踪矩阵：原资料目标 -> 当前模块/契约 -> 自动测试 -> 状态（implemented skeleton / port only / intentionally deferred）。
9. 复跑执行 22 的隔离恢复烟雾；核对源资料、执行包和用户已有文件未被改坏。
10. 生成 `docs/handoffs/23.md`、`docs/acceptance-v0.1-skeleton.md` 和后续“内容层实施入口”清单。

## 验证：最终二元验收

- [ ] 清洁环境按 first-run 文档一次成功安装并启动。
- [ ] 空库迁移、API/Worker/Studio readiness 全部通过。
- [ ] OpenAPI 与 TS client 无漂移。
- [ ] 完整 Fake E2E 和全部失败路径通过。
- [ ] Worker 重启可恢复，重复请求无重复副作用。
- [ ] Workspace/Project 隔离、RBAC、Tool 权限、预算和人工批准反向测试通过。
- [ ] 日志、Trace、指标、审计贯通且无敏感内容。
- [ ] 备份恢复与对象清单校验通过。
- [ ] 所有镜像可构建、非 root、无真实密钥。
- [ ] 所有远期能力明确为 port/disabled/deferred，没有伪装为完成。

任何一项未勾选，版本状态必须是 `BLOCKED` 或 `PARTIAL`，不能标记 `v0.1-skeleton`。

## 本阶段不做

- 不创建正式内容、Prompt、知识包、示例作品或真实模型结果。
- 不推送 Git、镜像、云环境或生产部署，除非用户明确授权。
- 不删除失败测试、降低安全策略或硬编码成功状态来通过验收。

## 完成标准

- CI 与本地全量验证均通过，追踪矩阵有可重复证据。
- `docs/handoffs/23.md` 标记 `PASS`，版本可标记为 `v0.1-skeleton`；下一阶段才进入具体创作能力和内容实现。
