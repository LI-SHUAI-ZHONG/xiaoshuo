# ADR 0002：数据与存储基线

- 状态：Accepted
- 日期：2026-09-02

## 背景

ACCOS 需要事务数据、关系查询、向量索引、任务队列、短期协调和对象文件。第一版的目标是验证边界和纵向链路，而不是同时运营多套专用数据库。

## 决策

- PostgreSQL 是事务记录的唯一事实源，并通过 pgvector 承载第一版向量索引。
- 每个模块拥有自己的表、迁移和仓储；同库部署不代表共享所有权。
- Redis 仅用于队列、短期缓存、锁和临时会话状态，不作为持久业务事实源。
- 对象文件存入 S3 兼容存储，本地使用 MinIO；PostgreSQL 只保存对象键、校验值、所有权和状态元数据。
- 事务 Outbox 与业务写入使用同一 PostgreSQL 事务，Relay 负责投递，消费者负责幂等。
- 工作区标识进入所有工作区级持久记录和仓储过滤条件；跨工作区访问默认拒绝。
- 备份和恢复必须覆盖 PostgreSQL 与对象存储的一致恢复点。Redis 数据可以重建，不纳入业务事实恢复承诺。

## 替代方案

### 独立向量数据库

暂不采用。当前没有规模或延迟证据证明需要额外系统；pgvector 足以验证契约。

### 图数据库

暂不采用。关系结构先用 PostgreSQL 表达；只有查询形态和性能数据达到拆分门槛后再评估。

### 将对象直接存入数据库

拒绝。大对象会放大事务存储、备份与迁移成本，并模糊元数据和文件内容的职责。

### Redis 作为工作流状态源

拒绝。临时存储无法满足重启恢复、审计和一致性要求。

## 后果

### 正向

- 本地栈和备份面较小，事务边界清晰。
- 关系与向量检索共享授权和数据生命周期约束。
- 未来可在保持端口契约的情况下替换具体存储。

### 代价与风险

- 需要防止模块绕过仓储直接访问其他模块表。
- pgvector 或单库达到容量边界时需要有数据支持的迁移计划。
- 对象元数据与文件内容需要补偿和清理流程处理部分失败。
