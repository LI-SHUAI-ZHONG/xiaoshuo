# ADR 0005：Provider、工具与插件边界

- 状态：Accepted
- 日期：2026-09-02

## 背景

模型、工具、多模态、对象存储和外部身份服务会随供应商、成本与部署环境变化。直接在领域代码中调用第三方 SDK 会泄漏供应商类型、阻碍确定性测试，并扩大密钥和网络权限范围。

## 决策

- 外部模型、工具、多模态、对象存储和身份能力先定义内部端口，再由 adapters 实现。
- 领域与应用契约不得暴露供应商 SDK 类型、响应对象或异常。
- 默认启用确定性 Fake/Null Provider；没有显式配置、权限和预算时，真实网络调用失败关闭。
- 真实 Provider 的凭据只由运行环境的秘密管理注入，不进入仓库、日志、事件或业务数据。
- 每次模型或工具调用都经过能力白名单、主体与工作区授权、输入约束、配额/预算、超时和审计检查。
- 工具与插件以最小权限声明可用动作和数据范围；安装或启用不等于获得全部工作区访问权。
- Provider 故障转换必须由策略决定并可审计，不得静默改变模型、成本等级或数据区域。
- 外部适配器必须通过公共端口的契约测试；Fake 与真实实现遵守相同错误和可取消语义。

## 替代方案

### 在各模块中直接调用 SDK

拒绝。它会形成供应商耦合、重复鉴权和不可控网络访问。

### 只在测试中 Mock SDK

拒绝。Mock 供应商细节无法验证稳定的内部契约；Fake 应实现内部端口并提供确定性行为。

### 自动选择最低价或最快 Provider

暂不采用。选择会影响隐私、质量和预算，必须由显式、可审计策略控制。

## 后果

### 正向

- 无真实密钥也能运行测试和完整 Fake 链路。
- 替换供应商不会穿透到领域模型。
- 权限、预算和审计在单一网关边界执行。

### 代价与风险

- 需要维护内部能力模型和适配器契约测试。
- 供应商特有功能只能通过显式扩展契约暴露，不能临时下沉到业务模块。
- Fake 必须保持确定性并明确与真实能力的差异，避免把空实现误报为功能完成。
