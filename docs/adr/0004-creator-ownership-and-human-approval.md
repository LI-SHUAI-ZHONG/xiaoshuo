# ADR 0004：创作者所有权与人工批准

- 状态：Accepted
- 日期：2026-09-02

## 背景

ACCOS 会处理创作者资产、偏好、知识、记忆、反馈和改进提案。愿景中的“自我进化”如果缺少权限、审计和人工关卡，可能越权修改内容、配置、代码或部署。

## 决策

- 创作者对其工作区内的内容和资产拥有最终控制权；系统只能在明确授权范围内处理。
- 所有业务访问同时受身份、工作区成员关系和角色权限约束。项目权限不能扩大工作区权限。
- 工作区级数据默认隔离；跨工作区访问必须由显式系统能力授权并留下审计证据。
- 读取、生成、导出、删除、工具调用、Provider 调用和管理操作使用最小权限。
- 高影响操作必须展示作用域、预期变更和风险，由有权限的人明确批准；批准不可由功能开关、Agent 或模型输出替代。
- `evolution` 只能生成版本化、可审查、可拒绝的改进提案。系统不得自行改代码、提升权限、修改安全策略或部署。
- 审计记录包含主体、工作区、动作、目标、结果、时间、关联 ID 和批准链；敏感正文与密钥不得写入日志。
- 数据删除、导出、保留和恢复能力必须遵循所有权边界并可审计。

## 替代方案

### Agent 可自动应用低风险改进

暂不采用。风险分类本身可能错误，第一版全部应用操作都经过人工批准。

### 仅依赖应用页面隐藏权限

拒绝。权限必须在服务端和数据访问边界执行，前端可见性不能形成安全边界。

### 共享全局知识与记忆表

拒绝。共享读取会破坏创作者与工作区隔离；共享能力只能消费经授权发布的公共契约。

## 后果

### 正向

- 创作者始终保留控制权，敏感操作可追溯。
- Agent、工具和 Provider 采用相同授权与批准模型。
- “受控进化”可以被验证，而不会演变为自治变更系统。

### 代价与风险

- 人工关卡会增加高影响流程耗时。
- 需要维护权限、审计、批准与数据生命周期的反向安全测试。
- 后续改变审批粒度必须有风险证据和新 ADR。
