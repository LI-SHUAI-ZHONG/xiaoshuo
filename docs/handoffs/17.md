## SSE 契约与恢复

```text
GET /api/v1/events?run_id={run_id}
Last-Event-ID: {run_id}:{sequence}
Content-Type: text/event-stream
```

- 连接建立前先通过 Workflow 应用服务核对 Workspace、Project 和 `AGENT_RUN`；无权或跨空间 Run 不会泄漏事件。
- SSE 只读 PostgreSQL 中已持久化的版本化 `WorkflowRunEvent`，不消费 Celery 任务，不作为事实源；浏览器断开不取消 Workflow。
- 每个数据帧使用 `id: {run_id}:{sequence}` 和业务 `event` 类型；`SseEventData` 包含 `event_id`、`sequence`、`type`、`schema_version`、`correlation_id`、`run_id`、`project_id`、`occurred_at` 与有界 `payload`。
- OpenAPI 的 `text/event-stream` 响应通过 `x-accos-event-data-schema` 显式引用 `#/components/schemas/SseEventData`；生成客户端包含同名载荷类型。
- 首帧建议 3 秒重连，10 秒无数据时发心跳。合法游标从下一序列继续；格式错误、Run 不匹配、负数或超前游标返回稳定 400。
- 首次读取发现保留窗口缺口时返回 `EVENT_CURSOR_EXPIRED`/409，并指示重拉状态 URL；已建立的流后续发现缺口则发 `stream.reset` 并关闭。

## 应用与持久化边界

- Workflow repository/service 增加有序 Step、Task、Approval 和 `after_sequence` Event 查询，所有查询固定 Workspace scope。
- Agent、Knowledge、Memory、Feedback 和 Evolution 应用服务补齐 API 需要的只读用例；Knowledge/Feedback SQL adapter 补齐对应 scoped lookup。
- Model/Tool status 由现有 gateway/registry 报告配置与协议版本，不暴露密钥、原始错误或内部 adapter 对象。
- `EventCursorExpiredError` 进入统一错误描述器，返回可机器处理的恢复策略；未知错误仍由 HTTP 外层隔离内部堆栈。
