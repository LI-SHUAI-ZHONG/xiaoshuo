## 本阶段变更

### Kernel 端口与稳定错误

- `kernel/persistence.py`：ORM 无关的 `UnitOfWork`、模块 `Repository`、`Page`、`IdempotencyRecord` 与 `IdempotencyStore` 协议；事务只允许应用层显式提交。
- `kernel/events.py`：带事件 UUID、workspace/project/aggregate、类型、schema 版本、payload 与 UTC 时间的 `EventEnvelope`，以及 Publisher/Outbox Writer 协议。
- `kernel/graph.py`：`GraphNodeRef`、`GraphEdge` 与 `GraphStore` 端口；本阶段没有具体适配器或独立图数据库。
- 新增 `concurrency_conflict` 与 `idempotency_conflict` 稳定错误，未知数据库异常仍由外层安全映射。
- `kernel/asyncio.py`：统一 Selector 事件循环工厂，解决 Windows 上 psycopg 异步连接不支持 Proactor 的约束；API、Worker 与迁移入口使用同一兼容策略。

### 异步数据库运行时

- `adapters/persistence/database.py` 创建共享 `AsyncEngine`、`async_sessionmaker` 和 `DatabaseRuntime`。
- 连接池参数来自显式环境配置：pool size、max overflow、等待超时和连接回收时间；启用 `pool_pre_ping`。
- API 与 Worker 的 composition root 只创建一个数据库运行时，生命周期顺序为 Kernel → Persistence → Health，关闭时逆序 dispose 连接池。
- PostgreSQL readiness 改为通过共享异步 Engine 执行 `SELECT 1`；应用启动不执行 `create_all`，也不隐式迁移。

### 幂等与 Outbox

- 幂等预留在嵌套保存点内处理并发唯一约束：同 key、同请求摘要返回既有结果；同 key、不同摘要返回稳定冲突，不破坏外层事务。
- `SqlAlchemyOutboxWriter` 使用调用方 Session flush，但绝不自行 commit，保证事件和未来业务写入同事务提交或回滚。
- `SqlAlchemyOutboxRepository` 使用 `FOR UPDATE SKIP LOCKED` 按单调 `sequence` 认领可用事件，并写入租约 token、过期时间和尝试次数。
- 发布在数据库事务外执行；成功只能用仍有效的 token 确认，失败写稳定错误码和下次可用时间。过期租约可被后续进程重领。
- `OutboxRelay` 提供批次高水 cursor；`InMemoryPublisher` 按事件 UUID 去重，用于验证 at-least-once 投递下只产生一次可见副作用。
- 普通 Worker 没有扫描业务表或 Redis/Celery 消费逻辑。

## 数据不变量与扩展规则

- PostgreSQL 继续是事务记录唯一事实源；Redis、图/向量投影、缓存与未来搜索索引必须可重建。
- 每个新业务表必须在所有权矩阵声明一个模块拥有者，并同时提交显式迁移、私有 ORM 映射、仓储 workspace 过滤和测试。
- 模块公开契约不得返回 SQLAlchemy Model；其他模块不得导入拥有者的 ORM 或直接写表。
- 跨模块修改通过公开应用服务；异步协作只消费版本化 Outbox 事件。
- 所有重试副作用使用幂等记录或等价唯一约束；at-least-once 消费以事件 ID 去重。
