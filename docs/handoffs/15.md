## 本阶段变更

### Feedback、同意与 Creator 单向接线

- 新增 `modules/feedback`，定义 `FeedbackEvent` 及 user、system、creative-result、behavior-consented 四类来源；所有事件只含 schema、signal code、数值和不透明引用，没有正文/Prompt 字段。
- 行为同意以 Workspace/Project/actor/policy version 为范围，默认无 ACTIVE 记录即关闭。授予与撤回保留策略版本及时间证据。
- 撤回在一个仓储事务内清除原行为事件的 actor、signal、数值、来源、consent 与 Creator link，把状态改为 `ANONYMIZED`；关联指标和实验样本立即排除并写时间。
- MetricPoint 写 `RECOMPUTE` tombstone；ExperimentSample 与 Creator 派生信号写 `EXCLUDE` tombstone。撤回 Outbox 不包含行为正文。
- 新增 Creator-owned `RepositoryPreferenceSignalIngestPort` 适配器。满足授权、同意和 `creator-preference.v1` / `creator-decision.v1` schema 的信号以 inert `PreferenceSignal` Proposal 保存到 Creative；Creative 代码没有导入 Feedback 仓储。

### 指标、诊断与实验

- `MetricDefinition` 注册 name/version/unit、最多四个有限维度、1–400 天保留期和 sensitivity；每维最多 32 个预注册值。
- 固定拒绝 actor/user/workspace/project/object/request/correlation ID、正文、Prompt 和 secret labels；MetricPoint 拒绝未注册指标、额外/缺失维度、未注册值、NaN/Infinity 和非法来源引用。
- 首期内置 Agent 成功/失败、延迟、预算，Memory 召回，Workflow 完成/失败/恢复以及 API/Worker 健康六组指标定义。
- `SystemDoctor@1` 使用确定性阈值生成 `DiagnosticFinding`；相同 point 与 rule/version 得到相同 ID，Doctor 不持有任何配置写入端口。
- 版本化 Experiment 保存 hypothesis、primary metric、technical-smoke scope、起止、variant、停止条件、状态与 result code；支持 `PLANNED -> RUNNING -> COMPLETED/STOPPED`，拒绝非技术烟雾样本。

### 受控 Evolution

- 新增 `modules/evolution` 的 Observer、Analyzer、Planner、SimulationEnvironment、VersionManager、SafetyController、EvolutionMemory 和 Proposal Service 边界；默认实现均为离线确定性实现。
- 状态协议固定为 `observed -> proposed -> simulated -> evaluated -> awaiting_approval -> approved/rejected -> externally_deployed -> verified/rolled_back`。
- 公开应用服务只推进到 awaiting approval；人工 decide 要求 `approval:decide`、USER actor 和职责分离。状态机包含外部状态，但本阶段没有进入 deployed/verified/rolled_back 的公开用例。
- Proposal 与追加式 Audit 保存 Finding/Metric 输入引用、算法/规则版本、模拟证据、Safety 结果、批准 actor 和 rollback reference，并使用整数乐观版本防止旧状态覆盖。
- `ImmutableSafetyController@evolution-safety-v1` 固定拒绝改变所有权、关闭安全、提升权限、绕过批准、自动提交代码、自动部署和未经迁移改 schema；拒绝 Proposal 仍持久化并审计。
