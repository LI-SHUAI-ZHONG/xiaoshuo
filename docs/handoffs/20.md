## Workflow Monitor 与 SSE 恢复

- Workflow 定义、Run、Step Run、Task Run、尝试次数、失败引用、输出引用、审批等待和终态都来自服务端响应。
- `framework_smoke` 只提交 URI 形式技术引用。202 响应的 Run ID、status URL、task URL 与 events URL 用于后续恢复，不生成业务内容。
- SSE 投影按 `run_id:sequence` 去重并保存内存游标；断线重连发送 `Last-Event-ID`。游标过期或旧服务端 reset 帧不符合类型时，客户端清空游标、重新读取 Run / Step / Task / Approval，再从无游标连接。
- SSE 只在 URL Project 与 Run Project 一致且 Run 非终态时建立；终态由状态 API 校准。刷新后可按服务端 Run ID 恢复，不使用 localStorage 或 sessionStorage。
- pause、resume、cancel、审批批准/拒绝和终态重试均使用确认 Dialog；403、409、429、过期审批和终态竞争保留服务端错误与关联 ID。

## Agent、质量与反馈

- Agent Descriptor 展示能力、允许工具、模型策略与完整预算上限；依赖未配置时显示 `NOT_CONFIGURED`，配置齐备时只显示 `REGISTERED`，绝不显示“在线”。
- Agent Run 展示服务端记录的模型调用、工具调用、Token、尝试、结果引用和稳定错误码。
- 一致性页面可提交无业务内容的结构断言，展示 Finding 类型、严重度、状态、验证器及证据引用；Resolution Proposal 必须逐项选择和人工决定。
- Quality 使用服务端 Rubric / Evaluation / Execute 链路并展示维度状态；不存在结果时保持真实空状态。
- Feedback 页面以 Project 为隔离边界。没有集合端点的 Feedback、Metric、Diagnostic、Experiment 与 Improvement Proposal 采用已知 ID 恢复，不在前端合成列表。
- 行为同意查询、明确授权与撤回连接真实应用用例；撤回响应展示匿名化事件数和 tombstone 数。Improvement Proposal 批准只改变受控状态，不会自动改代码或部署。

## System 与 Settings

- `/system/health` 的 503 readiness 正文仍作为有效健康投影处理，可同时展示 database、redis、object storage 与 AI provider 的 critical、status 和安全 detail。
- `live` 表示受保护 System API 能响应；`ready` 来自 readiness；关键依赖健康但可选依赖异常时派生 `degraded`。
- `/system/settings` 新增最小脱敏读取契约：environment、log level、对象存储 region/TLS、AI provider 名称、开发身份开关、Feature Flag，以及 Worker / Outbox runtime boundary。
- Worker `configured` 明确标注 `liveness_unreported`，Outbox `configured` 明确标注 `backlog_unreported`；页面不会把配置存在误报为在线或零积压。
