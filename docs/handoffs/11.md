## 本阶段变更

### 领域、端口与状态机

- 新增 `modules/knowledge`，公开 `KnowledgeSource`、`Document`、`DocumentVersion`、`Chunk`、`EmbeddingRef`、`Citation`、`IngestionRun`、检索/研究结果和最小 `KnowledgeEdge`。
- 固化 `uploaded -> extracting -> normalized -> chunked -> embedded -> indexed -> verifying -> ready` 检查点；失败保存 `failed_stage + error_code + retryable`。受控 retry 从失败阶段继续，full rebuild 回到 uploaded 并替换派生投影。
- 独立维护 `verified / unverified / not_configured / rejected`。非强制策略可以 `not_configured + ready`；强制策略只有 `verified` 可 ready，其他结果保持互不混淆的稳定失败码。
- 同一 AssetVersion 首次预留后，验证策略成为该 Run 的不可变输入；无论复用原幂等键还是更换别名键，从 `not_required` 切换为 `required` 都返回明确的幂等冲突。SQL 仓储还会在最终结算层拒绝把任何非 `verified` 的强制验证 Run 标记为 `ready`。
- 公开 `SourceReader`、`Extractor`、`Normalizer`、`Chunker`、`Embedder`、`VectorIndex`、`Retriever`、`VerificationProvider`、`GraphProjection` 和 scoped repository 端口。

### 离线处理、检索与研究

- 实现严格 UTF-8 的纯文本/Markdown Extractor、确定性空白规范化与 paragraph-first 定长分块、8 维 SHA-256 Fake Embedder；相同内容生成相同向量和 UUIDv5 投影身份。
- 新增 PDF/DOCX `NotConfiguredExtractor` 和外部数据库/远程来源 `NotConfiguredExternalSourceReader`，默认失败关闭；未配置验证器永不宣称 verified。
- `DefaultRetriever` 先从仓储取得当前 Workspace/Project 下 active+ready 版本许可集合，再执行向量搜索并通过 scoped repository 回填 Chunk/Citation。空结果是稳定结构；跨 Workspace、Project、Source、Version 与 Verification filter 不泄漏。
- Citation 固定 source/document/document version/asset/asset version/chunk/locator 与真实验证状态。`ResearchService` 只返回 deterministic plan/material-request/report 引用和已有 Citation，不访问外网。

### PostgreSQL、pgvector 与重建投影

- Alembic `0007_knowledge_pipeline` 新增九张 Knowledge 表：四张来源/文档/Run 事实与状态表，五张 Chunk/Embedding/Citation/Vector/Edge 可重建投影表。
- 原生 pgvector 路径把列升级为 `vector(8)` 并建立 HNSW cosine index；本机 Windows `vector 0.8.6` 是 text domain shim，迁移建立同名普通索引，适配器用确定性余弦回退。两条路径共享 replace/search 与隔离契约。
- Document 由 Workspace+Project+Asset 稳定复用，Source/DocumentVersion 对应不可变 AssetVersion。新版本 ready 后旧版本 `active=false`，旧来源和引用保留审计但不参与默认检索。
- 重建只删除当前 DocumentVersion 的 chunk/embedding/citation/vector/edge 投影和规范化文本，不删除 Asset、对象或来源身份。
- 修复了中断版本中的首次预留写入顺序：在没有跨聚合 ORM relationship 的前提下，事务显式按 Source -> DocumentVersion -> IngestionRun 分层 flush，避免外键对象因 mapper 插入顺序而提前写入；仍保持单事务原子提交。

### Workflow 与组合根

- 新增元数据型 `knowledge_ingestion@1` / `knowledge-ingest` reference step，输入仅接受 `knowledge-run://<uuid>`。失败按 Knowledge 的 retryable 语义映射为 Workflow retry/dead-letter。
- API 与 Worker 使用各自数据库连接边界但共享公开契约；Worker 侧继续使用独立 NullPool，Knowledge executor 包裹既有 Agent/Framework executor，不截获其他工作流步骤。
- 默认 composition 注册 SQL repository、AssetSourceReader、确定性处理器、Fake Embedder、PgVectorIndex、SQL GraphProjection、NotConfigured verifier、Retriever 与 ResearchService。
