## 2. 分析结论与定版原则

原资料适合充当产品愿景和模块词典，但不能直接按“第 7、15、21、41、43 阶段”执行，原因如下：

1. 项目当前没有代码，但原文从中段开始，并把数据库、后端、Agent、RAG 等未出现的工程内容标成“已完成”。
2. 同一规划被重复三次，若照抄会生成三套重叠模块。
3. “最终技术架构”直接跳到 Service Mesh、多数据库、生态平台，缺少依赖选择、迁移、测试、安全和发布步骤。
4. 多模态、第 114 步工程总计划只有预告，没有可执行细节。
5. “功能完成”与“概念描述完成”混用，不能当作验收证据。

因此采用以下落地方案：

- 第一版采用**模块化单体 + 独立后台 Worker**，而不是一开始拆微服务。
- 所有业务模块使用端口/适配器边界；未来有真实负载证据时再拆服务。
- PostgreSQL 统一承载事务数据、关系数据和向量索引；先不引入独立图数据库或向量数据库。
- Redis 只承担队列、短期缓存、锁和临时会话状态；对象文件放入 S3 兼容存储。
- 所有 AI、工具、多模态和外部身份提供方都先实现接口、空适配器和确定性 Fake，真实调用不属于框架搭建。
- “自我进化”只能生成可审计的改进提案，必须人工批准；禁止系统自行改代码、改权限或部署。
- 先完成一个可验证的纵向空链路，再扩展远期模块边界。

## 3. 固定技术基线

执行阶段不得临时改成另一套技术栈；确需更改时，先新增 ADR 并说明迁移成本。

| 区域 | 定版选择 |
|---|---|
| 架构 | 模块化单体、独立 Worker、端口/适配器、事务 Outbox |
| 前端 | Next.js App Router、React、TypeScript、Tailwind CSS、TanStack Query；Zustand 仅管理本地 UI 状态 |
| 后端 | Python、FastAPI、Pydantic、SQLAlchemy、Alembic |
| 异步任务 | Celery 适配器 + Redis；工作流状态持久化在 PostgreSQL |
| 数据 | PostgreSQL + pgvector；Redis；S3 兼容对象存储（本地 MinIO） |
| 接口 | `/api/v1` REST/OpenAPI；SSE 推送任务进度；协同编辑 WebSocket 延后 |
| 身份 | OIDC/JWT 端口 + 本地开发身份适配器；工作区级 RBAC |
| AI | 模型网关、工具网关、配额和审计；默认使用 Fake/Null Provider |
| 质量 | Ruff、类型检查、pytest、ESLint、TypeScript、前端单测、Playwright |
| 可观测性 | 结构化日志、OpenTelemetry 接口、指标、健康/就绪检查 |
| 本地运行 | Docker Compose；生产先交付 OCI 镜像与单节点部署说明，暂不引入 Service Mesh |

版本策略：执行 `02` 时检测本机能力，选择彼此兼容的稳定版本并立即锁入 Python、pnpm 和容器锁定文件；不要长期使用 `latest`，也不要在代码中写死 `D:` 盘路径。

## 5. 全局范围边界

每个执行文件都必须遵守以下边界。

### 必须做

- 创建真实可导入、可启动、可迁移、可测试的骨架，而不是只建空文件夹。
- 每个模块至少具有公开契约、空/Fake 实现、错误模型、最小测试和文档。
- 保持工作区、项目和创作者数据边界；记录审计与关联 ID。
- 每一步先运行上一阶段测试，再实施，再运行本阶段完整验证。
- 把阶段结果写入 `docs/handoffs/NN.md`，包括变更、命令结果、遗留项和回滚方法。

### 明确不做

- 不写小说章节、世界设定、角色档案、作者偏好、知识资料或演示数据。
- 不制作正式 Prompt、Agent 人设、评分内容、故事模板或研究语料。
- 不接入真实模型密钥，不发起付费模型调用，不抓取外部知识。
- 不实现支付、市场、版权交易、收益分成或完整多人实时协作。
- 不实现自治自改代码、自治部署或绕过人工批准的“进化”。
- 不因为原文画了 Service Mesh 就提前拆微服务。

最小测试夹具只能使用无业务含义的固定字符串，如 `fixture-project`、`fixture-document`，并集中放在测试目录。

## 6. 执行方式

将 `00` 与当次编号文件一起交给 Codex；一次只执行一个编号。Codex 应按以下固定流程工作：

执行仓库根目录必须由机器判定：它是**同时直接包含** `改进资料.txt` 与 `执行.txt` 的目录。当前项目中应解析为 `D:\搭建`。任务开始时先断言这两个文件存在；若当前目录不符，先切换到该目录，禁止在其下再创建第二层 `搭建/`。绝不根据聊天工作目录猜测仓库根。

1. 阅读 `00`、当前任务和上一编号的 handoff。例如执行 08 时读取 `docs/handoffs/07.md`；执行 01 没有上一份 handoff，也没有上一阶段测试，只做仓库根、用户文件和基线检查。
2. 检查当前工作树与本机依赖，保护用户已有文件和未提交修改；若仓库根目录存在 `.codegraph/`，理解或定位代码时先使用 CodeGraph，再使用普通搜索。
3. 先运行前置验证；不通过时只修复当前阶段所需的阻塞项。
4. 严格执行“本阶段实施”，不得顺手提前做后续模块。
5. 运行任务文件列出的全部验证；失败不得写“完成”。
6. 更新 handoff，列出实际文件、验证证据、已知限制和下一阶段输入。

除非用户明确要求，不执行 `git commit`、远程推送、镜像推送或任何生产部署。

任何步骤若需要真实账号、密钥、外部付费调用、删除用户文件或改变定版架构，必须停下并请求用户确认。

## 8. 全局完成定义

只有同时满足以下条件，才能把框架版本标记为 `v0.1-skeleton`：

- 新电脑按文档可在不使用真实 AI 密钥的情况下启动完整本地栈。
- 数据库可从零迁移，备份可以恢复，Worker 重启后任务状态不丢失。
- Fake 模型驱动的项目、知识、记忆、Agent、工作流和 UI 纵向链路通过。
- OpenAPI 快照与生成客户端一致；错误、分页、幂等和关联 ID 有契约测试。
- 工作区隔离、RBAC、审计、工具权限、预算和人工批准有反向安全测试。
- 后端、前端、契约、集成和 E2E 检查全部进入 CI。
- 所有远期能力只存在于清晰的端口/功能开关中，没有伪装成“已完成”的空业务功能。
