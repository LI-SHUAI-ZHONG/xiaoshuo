# 执行 04：后端内核与应用启动

## 任务目标

创建 FastAPI API 与后台 Worker 的真实可启动入口，并建立全系统共用的配置、ID、时间、错误、日志、依赖组装和健康状态契约。内核只负责运行机制，不包含创作业务。

## 前置条件

- G1 的执行 01–03 均为 `PASS`。
- 本地基础设施可以启动；Python 工具链全量校验通过。

## 本阶段实施

1. 在 `services/core/src/accos` 建立：
   - `entrypoints/api`：FastAPI 应用工厂与生命周期管理；
   - `entrypoints/worker`：Worker 启动入口，当前只加载空任务注册表；
   - `kernel`：配置、日志、ID、UTC 时钟、错误信封、结果类型、关联 ID、功能开关、健康状态；
   - `composition` 或等价组装层：唯一允许实例化具体适配器的位置。
2. 配置模型按必需、可选和功能开关分组；生产模式禁止弱默认值，测试模式使用显式测试配置。
3. 定义通用契约：UUID/ULID 选择及序列化、UTC 时间格式、分页、版本号、幂等键、请求/任务/Trace 关联 ID、结构化错误码。
4. 实现 `/live` 与 `/ready`：`live` 只表示进程存活；`ready` 汇总关键依赖。可选 AI Provider 缺失只能显示 `DEGRADED/NOT_CONFIGURED`，不能让 Fake 模式无法启动。
5. 实现统一异常映射、请求日志中间件、关联 ID 传播、敏感字段脱敏和安全默认响应头。
6. 建立模块注册协议和启动/关闭钩子；现在只注册 Kernel 与健康模块。
7. Worker 与 API 必须复用同一配置和组装逻辑，不能复制一套环境解析。
8. 添加单元测试与启动烟雾测试；写入 `docs/handoffs/04.md`。

## 预期关键路径

```text
services/core/src/accos/
├─ entrypoints/api/
├─ entrypoints/worker/
├─ kernel/
│  ├─ config.py
│  ├─ errors.py
│  ├─ ids.py
│  ├─ clock.py
│  ├─ logging.py
│  ├─ health.py
│  └─ features.py
└─ composition/
```

文件可按职责进一步拆分，但禁止形成万能 `utils.py`。

## 本阶段不做

- 不创建项目、知识、记忆、Agent 或创作 API。
- 不在内核中导入 SQLAlchemy、Redis、S3 或任何模型厂商 SDK；具体依赖进入适配器。
- 不用单一 `/api/master/run` 充当万能入口。

## 验证

- API 与 Worker 分别可启动并正常接收终止信号。
- `/live` 返回稳定契约；基础设施在线时 `/ready` 为 ready，关键依赖离线时为 not ready。
- 同一请求的响应、日志和错误含同一个关联 ID；密钥被脱敏。
- 配置缺失、非法状态、未知错误分别映射到可测试的错误码，不暴露堆栈。
- 架构测试证明 `kernel` 不依赖任何领域模块或具体基础设施 SDK。

## 完成标准

- 不使用真实 AI 密钥即可启动 API 和 Worker。
- `docs/handoffs/04.md` 标记 `PASS`，记录启动命令、端口和健康契约。
