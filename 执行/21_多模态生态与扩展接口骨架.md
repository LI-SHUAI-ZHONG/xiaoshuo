# 执行 21：多模态、生态与扩展接口骨架

## 任务目标

为原资料远期的多模态、知识图、协作、权属、市场和生态能力建立隔离的扩展端口与功能开关，证明未来可接入而不污染核心；本阶段不实现这些业务。

## 前置条件

- G4 的执行 16–20 通过。
- 核心纵向空链路在所有远期功能关闭时稳定运行。

## 本阶段实施

1. 建立 `extensions` 或等价隔离包，核心模块只能依赖抽象 capability，不得反向依赖扩展实现。
2. 多模态端口：Image、Audio、Video、3D 的 input/output asset reference、capability、job、provenance、usage 与安全元数据；提供 Null Adapter。
3. Graph Port：node/edge/projection/traversal 契约；提供 PostgreSQL 可重建关系投影适配器的最小契约，不部署独立 Graph DB。
4. Collaboration Port：team、role、task、comment、presence/collaborative-editor capability；默认 disabled，不实现实时编辑。
5. Rights Port：owner、contributor、license metadata、permission、provenance、audit 不变量；不得声称完成法律版权验证。
6. Marketplace/Reputation/Growth 只定义 capability manifest、权限、事件和 API 状态；无支付、商品、评分和推荐实现。
7. Knowledge Network 扩展只定义外部 Acquisition、Research Team、Verification Provider；无外网抓取或专业知识内容。
8. 每个扩展有 Feature Flag、权限、配置 schema、Null Adapter、契约测试和停用行为；禁用时不要求依赖或密钥。
9. 建立“晋升为真实模块”的门槛：用户需求、数据所有者、威胁模型、SLO、成本、迁移和退出方案全部批准后才能实施。
10. 写入 `docs/architecture/extension-parking-lot.md` 与 `docs/handoffs/21.md`。

## 本阶段不做

- 不生成或处理真实图片、音频、视频、3D 资产。
- 不实现多人实时协作、支付、分成、市场商品、信誉算法或法律合同。
- 不访问外部知识网络，不部署图数据库、Kubernetes 或 Service Mesh。

## 验证

- 关闭全部扩展时，安装、启动、迁移、API、Worker、前端和 E2E 不加载可选 SDK。
- 调用关闭/未配置能力返回稳定状态，不产生假结果、半成品数据或用量。
- Rights 不变量测试证明任何资产引用都不能在扩展中改变核心 owner/workspace。
- 扩展包无法导入核心私有仓储；核心包无法导入具体扩展实现。
- PostgreSQL Graph 投影可删除并由权威事件重建。

## 完成标准

- 远期能力有清晰、安全、可测试的接入口，但没有被误标为业务完成。
- `docs/handoffs/21.md` 标记 `PASS`，附每项扩展的默认状态和启用前置门槛。
