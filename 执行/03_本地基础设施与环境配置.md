# 执行 03：本地基础设施与环境配置

## 任务目标

用 Docker Compose 建立可重复启动的 PostgreSQL/pgvector、Redis 和 S3 兼容对象存储，为 API 与 Worker 提供统一配置和健康检查。

## 前置条件

- 执行 02 全量校验通过。
- Docker Engine 与 Compose 可用；若不可用，报告阻塞，不用本机临时数据库替换目标拓扑。

## 本阶段实施

1. 创建 `infra/compose.yaml`，包含：
   - PostgreSQL，启用 pgvector 扩展；
   - Redis，启用持久化并配置健康检查；
   - MinIO 或等价 S3 兼容服务，以及幂等创建开发 bucket 的初始化任务；
   - 显式网络、命名卷、资源限制和健康检查。
2. 容器镜像使用明确版本或 digest，不提交 `latest`。开发默认仅绑定本机回环地址；数据库、Redis、对象存储不得裸露到局域网。
3. 建立配置分层：代码默认值、`.env`、进程环境变量；提交 `.env.example`，不提交 `.env`。
4. 环境变量至少覆盖数据库 URL、Redis URL、S3 endpoint/bucket、开发凭据占位、日志级别和功能开关。启动时缺少必要值应快速失败，并隐藏敏感值。
5. 创建 PowerShell/POSIX 的 `infra up`、`infra down`、`infra status` 包装脚本；`down` 默认不得删除卷，清空数据必须是另一个显式且有警告的命令。
6. 创建基础设施自检脚本：检查 PostgreSQL 连接和 pgvector、Redis ping、bucket 存在与最小读写；测试对象执行后清理。
7. 编写 `docs/runbooks/local-infrastructure.md`，说明启动、停止、端口冲突、卷位置、无损升级和故障排查。
8. 写入 `docs/handoffs/03.md`。

## 本阶段不做

- 不加入独立 Vector DB、Graph DB、消息中间件或 Service Mesh。
- 不启动真实 AI 服务，不写入业务种子数据。
- 不在默认关闭命令中删除卷。

## 验证

- `docker compose config` 无错误，且所有镜像均已锁定。
- 从空卷启动后，所有服务在规定时间内变为 healthy。
- pgvector 扩展可查询；Redis 和对象存储最小读写测试通过。
- 重启 Compose 后，测试数据库记录与测试对象仍在。
- 无 `.env` 时得到清晰错误；日志不显示密码或密钥。
- 执行根级全量校验仍通过。

## 完成标准

- VS Code 任务可一键启动/查看/停止基础设施。
- `docs/handoffs/03.md` 标记 `PASS`，记录端口、镜像、卷和执行 04 所需连接配置。
