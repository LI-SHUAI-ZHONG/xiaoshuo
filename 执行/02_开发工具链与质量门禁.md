# 执行 02：开发工具链与质量门禁

## 任务目标

建立 Python、TypeScript、VS Code 和统一质量检查底座，使后续每一步都有可重复运行的安装、检查和测试命令。

## 前置条件

- `docs/handoffs/01.md` 为 `PASS`。
- 本机已安装或允许安装 Git、Python/uv、Node.js/pnpm；缺失时先报告，不用另一套工具静默替换。

## 本阶段实施

1. 按固定算法选择版本：Python 使用 3.12 系列中满足依赖兼容的最高可用补丁；Node 使用 22 LTS 系列中满足前端工具链的最高可用补丁；pnpm 通过 Corepack 锁定项目版本。若本机没有该系列就报告并安装/请求安装，不能改用另一主版本。把最终精确版本写入 `.python-version`/等价版本文件、`packageManager`、锁文件、文档和 CI 变量；后续机器必须复用，不再重新选择。
2. 初始化 `services/core` Python 包与 `src` 布局；配置 uv 锁文件、Ruff、类型检查、pytest、覆盖率和导入边界检查。
3. 初始化根级 pnpm workspace，登记 `apps/studio`、`packages/ui`、`packages/api-client`；创建根级脚本入口，但前端应用本体留到执行 17。
4. 配置 ESLint、Prettier、TypeScript 严格模式和前端测试公共配置；不得关闭严格检查来换取通过。
5. 创建跨平台脚本入口：至少包含安装、格式检查、lint、类型检查、单测、全量校验。PowerShell 与 POSIX 包装脚本调用同一底层命令，避免逻辑分叉。
6. 配置 `.vscode/settings.json`、`extensions.json`、`tasks.json`、`launch.json`：提供后端、Worker、前端、测试、Compose 的任务占位；调试配置不得包含密钥。
7. 增加 pre-commit 或等价本地门禁，仅运行快速检查；完整测试留给 CI。
8. 所有依赖和容器版本必须锁定；记录升级策略，不提交全局缓存或虚拟环境。
9. 写入 `docs/handoffs/02.md`。

## 预期关键产物

```text
pyproject.toml 或 uv workspace 配置
uv.lock
package.json
pnpm-workspace.yaml
pnpm-lock.yaml
services/core/pyproject.toml
.vscode/settings.json
.vscode/tasks.json
.vscode/launch.json
scripts/check.ps1
scripts/check.sh
```

允许根据 uv workspace 的实际能力调整根级 Python 清单位置，但必须只有一个明确的锁定来源。

## 本阶段不做

- 不创建真实 API、数据库模型或 UI 页面。
- 不添加 AI 厂商 SDK、富文本编辑器、图数据库客户端或云 SDK。
- 不以 `latest` 或未锁定范围提交核心依赖。

## 验证

- 从清洁缓存状态执行 Python 与 pnpm 安装成功。
- 根级快速检查命令可运行，即使当前只有最小占位测试。
- Ruff、类型检查、pytest、ESLint、TypeScript 和前端单测的失败能正确返回非零退出码。
- VS Code 能识别 Python 环境和 pnpm workspace；所有调试配置使用环境变量。
- `rg` 检查仓库，不存在真实密钥、绝对 `D:` 路径或被误提交的环境文件。

## 完成标准

- 一条根级全量校验命令能覆盖当前 Python 与 TypeScript 工作区。
- `docs/handoffs/02.md` 标记 `PASS`，记录实际锁定版本和复现命令。
