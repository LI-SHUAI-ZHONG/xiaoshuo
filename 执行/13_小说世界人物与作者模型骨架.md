# 执行 13：小说、世界、人物与作者模型骨架

## 任务目标

把原资料中三次重复且互相嵌套的创作引擎收敛为四个唯一归属模块：Novel、World、Character、Creator。只建立模型、状态、命令、事件和扩展端口，不实现创作算法或内容。

## 前置条件

- 执行 12 通过。
- 项目、资产、Workflow、Knowledge、Memory、Agent 的公开契约稳定。

## 本阶段实施

1. 在 `creative` 模块下建立统一包边界，禁止同时出现 `backend/world_engine`、`services/world` 等第二套实现。
2. `novel` 负责作品结构与编排引用：`Work`、`ConceptRef`、`ThemeRef`、`PlotPlan`、`Chapter`、`DraftRevision`、`EvaluationRequest`。它引用 World/Character ID，不复制其实体。
3. `world` 负责：`World`、`WorldState`、`WorldRule`、`Civilization`、`Location`、`WorldEvent`、`ImpactLink`、`ScenarioRequest`。政治、经济、科技、文化仅建可扩展组件协议。
4. `character` 负责：`Character`、`CharacterState`、`PsychologyState`、`Relationship`、`GrowthArc`、`GrowthEvent`、`Motivation`、`BehaviorProposal`。
5. `creator` 负责：`CreatorProfile`、`PreferenceSignal`、`StyleProfile`、`DecisionRecord`、`EvaluationPreference`。本阶段只定义 `PreferenceSignalIngestPort` 和事件 schema 占位，不订阅尚未创建的 Feedback 模块；执行 15 再完成事件接线。Creator 不另建一套 feedback/evolution 引擎。
6. 每个模块建立 application commands/queries、仓储端口、事件和迁移；公开契约使用 ID/DTO，不暴露 ORM。
7. 定义扩展端口：Concept、Theme、Plot、Emotion、Style、Chapter Generator、World Simulation、Character Behavior、Creator Learning；默认 Null 实现返回 `NOT_CONFIGURED`。
8. 与 Knowledge/Memory/Agent 的交互只能通过公开 Port/Workflow；不得直接读取对方私有表。
9. 建立双向事件防循环规则：WorldEvent 可以触发 CharacterImpact proposal，CharacterAction 可以触发 WorldImpact proposal，必须带 causation ID 并去重。
10. 添加领域不变量、版本、并发和依赖边界测试；写入 `docs/handoffs/13.md`。

## 核心边界

- World/Character 是独立事实模块；Novel 负责组织作品，不拥有它们的状态。
- Creator Profile 只保存经授权的信号和版本，不默认采集正文或用户行为。
- 模拟和预测只产生 Proposal，不直接改变 Canon 或当前有效状态。
- 所有 Draft/Proposal 与已接受事实分开存储。

## 本阶段不做

- 不生成主题、剧情、章节、世界、文明、人物、关系或作者偏好。
- 不实现文明模拟、心理模拟、风格模仿、行为概率或质量算法。
- 不写 Prompt，不用大量 `pass` 文件宣称功能完成。

## 验证

- 每个实体有唯一数据所有者；架构测试阻止 Novel 复制 World/Character 仓储。
- Null 扩展被调用时返回 `NOT_CONFIGURED`，核心项目与工作流仍正常。
- Draft/Proposal 未获批准时不能更新当前有效状态。
- World/Character 双向事件使用 causation ID，不形成无限循环或重复副作用。
- 跨项目读写、并发版本冲突和归档项目写入均按既有策略处理。

## 完成标准

- 四个模块可创建空容器、保存状态元数据、发布事件并被 Workflow 引用。
- `docs/handoffs/13.md` 标记 `PASS`，附原资料重复目录到唯一模块的映射表。
