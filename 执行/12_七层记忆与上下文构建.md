# 执行 12：七层记忆与上下文构建

## 任务目标

把原资料的七层记忆变成一个统一、可查询、可审计的数据模型，并明确“记忆层级”和“人物/世界/事件等记忆类型”是两个维度；建立有预算的 Context Builder。

## 前置条件

- 执行 11 的来源与检索契约通过。
- Workflow、Agent、项目作用域和审计可用。

## 本阶段实施

1. 创建 `memory` 模块，使用单一 `MemoryRecord`/`MemoryLink` 模型，包含：
   - scope：working、session、project、universe、creator、experience、wisdom；
   - type：project、character、world、event、decision、preference、system 等可扩展类型；
   - workspace/project/universe/creator 作用域键；
   - valid time、observed time、importance、confidence、provenance、version、retention policy。
2. 固定 scope anchor 与授权规则：working/session/project 必须有 `project_id`；universe 必须有 `universe_id`；creator/experience/wisdom 必须有 `creator_id`，且只能由本人或显式授权的 Workspace 使用。查询先由授权服务计算 allowed anchors，再按 scope/type 过滤；不能用可空 `project_id` 绕过权限。跨项目 Context 只有显式 Universe/Creator grant 才允许。
3. Working/Session 可在 Redis 建缓存投影，但需持久追踪的信息必须落 PostgreSQL；缓存丢失不能破坏事实。
4. 定义 `MemoryWriter`、`MemoryRetriever`、`MemoryRanker`、`MemoryCompressor`、`RetentionPolicy`、`ConflictResolver` 端口。
5. 首期实现确定性排序：授权 scope anchor、时间有效性、重要度、来源；语义排序使用 Fake/pgvector 适配器。
6. “压缩”生成新版本/摘要引用并保留来源链；“遗忘”默认降权或归档，禁止无审计物理删除。
7. 冲突处理生成 `MemoryConflict` 与候选决议，作者/授权用例选择后再产生新版本；不得静默覆盖。
8. 创建 `ContextBuilder`：接收任务、项目、token/字符预算、允许的 scope/type 和权限，输出排序后的 Context Package、来源与被排除原因。
9. Agent 只读取 Context Package，不自行扫全部记忆表；上下文快照与 AgentRun 关联。
10. 添加 TTL、降权、跨项目隔离、显式跨项目授权、冲突、预算截断和可重建测试；写入 `docs/handoffs/12.md`。

## 本阶段不做

- 不写人物记忆、世界记忆、作者偏好或创作智慧内容。
- 不实现 LLM 摘要 Prompt、长期学习算法或自动改变作者偏好。
- 不建立七套数据库或七套重复表。

## 验证

- scope 与 type 可独立过滤；任何查询先应用 allowed anchors。无 Universe/Creator grant 时跨项目召回为零，有显式授权时也只能读取获准 scope。
- 过期 Working Memory、降权记忆和当前有效记忆的排序行为可重复测试。
- Context Builder 永不超过预算，并为省略项返回机器可读原因。
- 冲突保留全部历史，未获批准不能改变当前有效版本。
- Redis 清空后，持久记忆事实与可重建投影保持一致。
- 一次 AgentRun 能追踪到 Context Package 和每条来源。

## 完成标准

- 使用最小技术夹具即可写入、检索、冲突、降权并组装上下文。
- `docs/handoffs/12.md` 标记 `PASS`，附记忆作用域/类型矩阵和保留策略。
